# Pure Plan5 P2 judgement

This implements the early, effect-free subset admitted by the [governing amendment](https://github.com/Epiphytic/heterodyne-metaharness/blob/cb180b72c21a157f721be1e4fa57ccfd03d4a11b/docs/adr/2026-10-16-plan5-governing-amendment-admission.md) and the [D4 contract](https://github.com/Epiphytic/heterodyne-metaharness/blob/45e239a53bdb3bee82d6d44125c021abe296f60d/docs/designs/2026-10-16-plan5-actions-and-executor-d4.md), especially §§3, 5, 8 and 12. It reuses the merged gatekeeper DTOs, bounded privacy validation, evidence quotes, enrichment projection and result validation. It does not register the full Plan7 intake or a model service.

`heterodyne.actions.judgement` exposes an asynchronous fake-provider protocol. Its invocation contains a detached, privacy-validated purpose projection, a private input digest and the requested model/schema/release. The provider returns bounded result bytes, the per-attempt nonce and reported metadata. Requested/reported metadata are explicit attestations; they do not prove a hidden served model. Unknown, unavailable, malformed, mismatched or late results cannot produce a sufficient proposal. Permission failures escalate. Permission inputs additionally require explicit host `PolicyFacts` bound to the current policy fingerprint, including supplied host overrides and workstream restrictions. Current deterministic hard denial takes precedence over even a malformed or stale receipt. All other outward permission projections retain the P0 escalation floor. The existing arbitrary tool-invocation DTO cannot demonstrate that its effect equals the P0 action envelope: permission assessment therefore does not invoke a provider and cannot return `AllowProposal`. This is a deliberately unavailable bridge, not a semantic-equivalence attestation.

The deadline is at most 60 seconds (or the smaller remaining permission budget). The default elapsed clock is Linux BOOTTIME so suspend counts. An injected clock is a test seam, not an authenticated clock. Backward/invalid samples and the exact deadline refuse; cooperative async cancellation is bounded by `asyncio.timeout`. A timed-out provider that suppresses cancellation still cannot produce a successful receipt. No real provider process, thread cancellation or service timeout enforcement is claimed.

A receipt binds the P1 logical origin and request identity, revision, canonical action envelope/configuration, whole opaque ask bytes, native context digest, source revision, allocation/recovery provenance, enrichment provenance, exact gatekeeper snapshot/context/source pins, privacy policy, host policy controls and model specification. `current_projection` recomputes the binding on every modeled use and revalidates the result. Unchanged semantic input survives P1 lifecycle-only transitions from ask-pinned to sufficient/filed; any altered ask, digest, revision, source, policy, context, model or origin invalidates it. Terminal/denied requests refuse. P1's opaque native-ask and digest fields remain host observations: this module does not implement or authenticate the native canonical digest algorithm, origin, live policy reader or equivalence of the purpose projection with that ask. Those remain future trusted adapter responsibilities.

Receipts additionally carry a fresh invocation nonce echoed by the reply, observed boot identifier, BOOTTIME start/end samples and the attempted budget. Reuse checks their consistency and current supplied boot identifier; old receipts lacking these fields refuse. These are trusted host observations, not unforgeable proof that a model ran. A future owner must durably reserve the nonce/input/boot/start before calling its provider, correlate the reply and end sample, retain the record and recheck the current request at use. This pure port has no such durable owner, and a caller can forge its values.

Receipts and grooming state are immutable, serializable values for a future owning journal. This task does not install persistence or modify the existing P1 journal/decision reducer, and does not convert model output into authenticated consent. A caller must retain evidence and recheck current native facts through a separately admitted adapter before any real posting, recovery, decision or effect. No production pipeline calls these functions.

Enrichment returns a bounded whole-candidate proposal using the existing exact source-quote checks. It is never sufficient. `repin_enrichment` requires current validated enrichment advice and uses a pure P1 transition that increments the request revision, rebuilds the envelope, stores the candidate/previous ask provenance, clears sufficiency and requires different whole ask bytes and context digest. It charges no groom revision. A fresh judgement must bind the complete `Used` candidate and the new ask; the original request refuses. Opaque bytes and digests remain host observations: proving the regenerated native ask actually contains that candidate is future adapter work.

`P1.groom` clears old ask/sufficiency/enrichment state and enforces at most two revisions in the same logical originating session, allowing a later generation without granting authority to resume or replace a session. P2 callers use `groom_request`, which additionally requires current recorded negative advice for this exact creation key, approval and binding. `GroomState` records revision zero without charging a revision, and reconciles later negative assessments against the actual P1 counter. Repeated receipts and outages do not advance this P2 wrapper. An older caller may already have consumed a P1 revision during an outage; P2 cannot refund it and instead preserves that counter, allowing the revision-two negative assessment to reach the fixed concern exit. It never grants a third revision. Reassessment under a new model at the same revision cannot spend another revision.

After revision two receives negative advice, `concern` offers only the four D4 fixed reason codes, a 12-character private-input digest prefix, choices `groom`/`deny`, and recommendation `deny`. This is inert data, not a posted Marmot card, denial, status write or consent. No model prose, full private pins or arbitrary payload is copied into that public projection. Silence and unavailable judgements remain held. A later native adapter must authenticate an actual deny and preserve the real history.

All five outward adapters remain unavailable. There are no credentials, model calls, native queue operations, session input, transport, timers, installation, services, deployment or live migration in this task. Tests use synthetic P1 observations, fake providers and detached fixtures only. Full Plan5/Plan7 integration, native snapshot equivalence, receipt durability and an actual model provider remain separately admitted work.

The permission bridge requires a later design decision before production support: define a closed action-specific public projection derived from the same validated P0 envelope and exact privacy policy, plus an independently checked binding from the admitted permission DTO to that projection. Private `action_data` must not be copied into model input, and a caller-supplied digest of two unrelated objects is insufficient. That schema and its native/provider adapter are not approved or implemented here. Until then permission assessment remains unavailable and escalation never becomes effect authority.
