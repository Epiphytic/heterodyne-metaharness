# Pure Plan5 P2 judgement

This implements the early, effect-free subset admitted by the [governing amendment](https://github.com/Epiphytic/heterodyne-metaharness/blob/cb180b72c21a157f721be1e4fa57ccfd03d4a11b/docs/adr/2026-10-16-plan5-governing-amendment-admission.md) and the [D4 contract](https://github.com/Epiphytic/heterodyne-metaharness/blob/45e239a53bdb3bee82d6d44125c021abe296f60d/docs/designs/2026-10-16-plan5-actions-and-executor-d4.md), especially §§3, 5, 8 and 12. It reuses the merged gatekeeper DTOs, bounded privacy validation, evidence quotes, enrichment projection and result validation. It does not register the full Plan7 intake or a model service.

`heterodyne.actions.judgement` exposes an asynchronous fake-provider protocol. Its invocation contains a detached, privacy-validated purpose projection, a private input digest and the requested model/schema/release. The provider returns bounded result bytes and reported metadata. Requested/reported metadata are explicit attestations; they do not prove a hidden served model. Unknown, unavailable, malformed, mismatched or late results cannot produce a sufficient proposal. Permission failures escalate. Permission inputs additionally require explicit host `PolicyFacts` bound to the current policy fingerprint; permissions widening hard-denies before provider invocation. An advisory `AllowProposal` cannot defeat the P0 outward floor or enable an effect adapter.

The deadline is at most 60 seconds (or the smaller remaining permission budget). The default elapsed clock is Linux BOOTTIME so suspend counts. An injected clock is a test seam, not an authenticated clock. Backward/invalid samples and the exact deadline refuse; cooperative async cancellation is bounded by `asyncio.timeout`. A timed-out provider that suppresses cancellation still cannot produce a successful receipt. No real provider process, thread cancellation or service timeout enforcement is claimed.

A receipt binds the P1 logical origin and request identity, revision, canonical action envelope/configuration, whole opaque ask bytes, native context digest, source revision, exact gatekeeper snapshot/context/source pins, privacy policy, host policy and model specification. `current_projection` recomputes the binding on every modeled use and revalidates the result. Unchanged semantic input survives P1 lifecycle-only transitions from ask-pinned to sufficient/filed; any altered ask, digest, revision, source, policy, context, model or origin invalidates it. Terminal/denied requests refuse. P1's opaque native-ask and digest fields remain host observations: this module does not implement or authenticate the native canonical digest algorithm, origin, live policy reader or equivalence of the purpose projection with that ask. Those remain future trusted adapter responsibilities.

Receipts and grooming state are immutable, serializable values for a future owning journal. This task does not install persistence or modify the existing P1 journal/decision reducer, and does not convert model output into authenticated consent. A caller must retain evidence and recheck current native facts through a separately admitted adapter before any real posting, recovery, decision or effect. No production pipeline calls these functions.

Enrichment returns a bounded whole-candidate proposal using the existing exact source-quote checks. It is never sufficient. The host must regenerate the whole native ask and digest and submit a fresh judgement; the old receipt fails against changed input. `P1.groom` clears old ask/sufficiency state and enforces at most two revisions in the same logical originating session, allowing a later generation without granting authority to resume or replace a session. `GroomState` records initial advice without charging a revision, then counts only the two actual failed groom revisions; repeated receipts and outages do not spend that budget. Reassessment under a new model at the same revision cannot spend another revision.

After both failed revisions, `concern` offers only the four D4 fixed reason codes, a 12-character private-input digest prefix, choices `groom`/`deny`, and recommendation `deny`. This is inert data, not a posted Marmot card, denial, status write or consent. No model prose, full private pins or arbitrary payload is copied into that public projection. Silence and unavailable judgements remain held. A later native adapter must authenticate an actual deny and preserve the real history.

All five outward adapters remain unavailable. There are no credentials, model calls, native queue operations, session input, transport, timers, installation, services, deployment or live migration in this task. Tests use synthetic P1 observations, fake providers and detached fixtures only. Full Plan5/Plan7 integration, native snapshot equivalence, receipt durability and an actual model provider remain separately admitted work.
