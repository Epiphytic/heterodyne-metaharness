# Memory, context and task integration verification

The shared supervisor applies provider capabilities before each launch/resume.
Tmux passes validated environment values literally and protects ownership keys.
Native identity registration precedes optional enrichment; enrichment runs from
the installed module directory with a ten-second deadline so an unavailable
queue or recall index cannot prevent identity recovery.

Reviewed auto-memory is isolated and pinned. Claude uses its upstream index;
Codex uses the documented bounded JSONL fallback because the upstream schema gate
rejects this host's newer native database. No schema bypass or transcript deletion
is part of installation. Standalone agents receive scoped recall instructions;
managed agents receive bounded SessionStart context automatically.

The existing BTQ implementation remains the task authority. Managed hooks use
the durable harness UUID and the facade's additional approval-dependency checks.
Native-session changes do not create a new queue worker. Direct work starts with
pickup paused; reboot records recovery guards before restoring terminals.
Explicit reconciliation records evidence and never restarts interrupted work.

Validation covers real tmux environment/ownership, simulated reboot, native
compaction identity, hook import from unrelated worker directories, trusted hook
migration, repeated installation, scoped recall and both providers' task lifecycle
through the installed BTQ implementation with an isolated fake bd transport.
Real queue checks are read-only; Semble MCP initialization and a fixture search
succeeded. No production task was claimed and no paid model workload or physical
host reboot was used as a test.

The structural quality scan is not clean: it reports the supervisor's additional
enrollment branches and class length, hook discovery's event/matcher/timeout
parameters, and growth of test classes. Its dead-code reports include dynamically
dispatched test doubles and unittest methods exercised by the passing suite.
These are reviewed tradeoffs, not a claim that the quality gate passed. Hook
migration was split into preflight and trust operations, with a shared installer
lock; both providers are validated before mutation.

There is no configured GitHub or Radicle remote in this local repository, so the
implementation is committed locally rather than claiming it was published.
