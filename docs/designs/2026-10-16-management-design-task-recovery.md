Design task `btq-zcd1l`; proposed amendment, design only, 2026-10-16. Actual R1 reviewed `e73eab04ac9eeb91ea7a5794cd04bbe2236fde4d` and returned REVISE; its 24 findings and this revision's dispositions are retained in [the review record](../reviews/zcd1l-r1-dispositions.md). This draft grants no implementation, recovery or deployment authority.

## 1. Existing authority and bounded amendment

The [approved original management d2](../reviews/approved-inputs/2026-10-15-operator-task-management.md) supports authenticated stopped-holder reclaim, status correction and typed dependency repair for implementation tasks. Preserve its archive bytes and genuine approvals. Queue `6fe57598468ff53bf74dfd9e1cf181ad3177c3f1` currently requires `kind:task` in `Management._route` and valid implementation pins in `_approval`; a planning task cannot use it to resume producing its design. This amendment adds the finite planning classification below and repairs the management journal/packaging seams needed to operate it safely. It does not change normal queue claim/close, approval validity or implementation design gates.

Implementation scope is expressly extended beyond the original queue-only scope: queue `bin/btq-manage.py`, its named safe offline tests and documentation; harness `scripts/workstream_manage.py`, `scripts/install_workstream_controller.py` and their named offline tests/documentation. Keep queue `bin/btq`, `bin/btq-supervise` and harness `harness/**/*.py` byte-identical to the pinned deployment baseline. This avoids drifting the active controller's separately pinned queue binary or harness digest. Any implementation that cannot fit these boundaries returns for an amended design; it must not quietly re-pin the controller.

The source closure, approved archive provenance and installed baseline digests are in [the input manifest](../reviews/zcd1l-management-inputs.json). That manifest describes observed input, not a future executable release. The implementation and deployment must bind their own exact candidate commits and file hashes.

## 2. Native schema and classification

Normalize one native snapshot once, then use the same representation in validation, digest, expected state and final comparison. Native objects must be dictionaries; labels must be a present list of unique strings; metadata must be absent or a dictionary with string keys. Do not coerce booleans, numbers, lists or null pin values into strings. If `dependencies` is omitted and `dependency_count` is the integer zero (not bool), normalize to `[]`. An explicit list must contain well-shaped unique `(id, dependency_type)` records and agree with an available integer count; omitted dependencies with nonzero, missing or malformed count refuse. Missing labels never mean empty. Preserve raw snapshot/hash alongside normalized facts so normalization cannot erase an unexpected field.

There must be exactly one native workstream label matching the enrolled workstream and exactly one `kind:` label. Conflicting or malformed routing refuses. For reclaim, also prove all native agent/session selectors admit the actual receiving run using the queue's existing routing rules; another agent's task cannot be relabeled or stranded in this controller's lane. For status/dependency repair, preserve routing and show the intended eligible worker route without assigning a worker.

| Native kind | Management class |
| --- | --- |
| `kind:task` | Implementation; original implementation pin/approval/blocker checks retained |
| `kind:brainstorm`, `kind:review`, `kind:research` | Planning; additional rules below |
| `kind:approval` | Always forbidden, including inspection-to-mutation transitions |
| Missing, mixed, malformed, legacy `kind:implementation`, or any other kind | Refuse without conversion |

The class is derived, never supplied by the caller. Validate kind, schema, routing and protection when preparing, authorizing, before every effect and during final readback. Malformed inputs produce a stable safe refusal reason, not a raw traceback or echoed secret-shaped payload. Validation errors use the module's handled `ValueError` boundary; the shim returns typed safe reasons for held states as well as ordinary refusals.

For implementation, retain the exact existing nonempty `design_approval`/`adr_revision`, native `approval_valid` and corresponding final `blocks` edge checks. For planning, both metadata keys may be absent: this confers no implementation authority. If either key is present, both must be nonempty strings and pass those same checks. Also bind the actual approval's authenticated scope to this planning task using its retained exact ask/artifact and native edge; a valid approval for another task is not transferable. Ambiguous scope refuses. No fake pins or local approval JSON are accepted.

Invalid planning pins remain a safe refusal. `approve-bead` is not a planning-pin repair API and is not proposed as one. This amendment does not authorize metadata edits. A needed exceptional pin correction requires a separately scoped, reviewed and authenticated Marmot OPS repair specifying exact old/new metadata and original authority; refusal alone is not its authority. Ordinary unpinned planning recovery has no such prerequisite.

For both planning pin states, protect every existing edge to an approval endpoint, of any edge type. Native labels in the pinned source establish `kind:` and routing; they do not establish a general harness-gate role detector. Define the following **proposed closed classifier rules**, `management-endpoint-roles-v1`. These versioned rules require design review/approval and reviewed deployment when changed; per-endpoint fact attestations are ordinary runtime inputs, not software/design changes.

- Native `kind:approval`, `kind:confirm` or `kind:question` always means `gate`. Missing, mixed or malformed kinds mean `unknown`. Existing authenticated scope/policy evidence identifying the endpoint itself as a permission/approval gate also means `gate`, even when its kind is `task`. The module must retain and bind already known protected-gate facts from the target's protection snapshot and endpoint's native content/history and exact referenced authority artifacts; a caller cannot omit them by supplying a shorter attestation. An ordinary endpoint's own `design_approval`/`adr_revision` merely govern its implementation and do not classify that endpoint itself as a gate.
- Proposed plan input `--endpoint-facts-file FILE` is a bounded data-only JSON object `{schema: "management-endpoint-roles-v1", workstream: string, entries: [{id: string, native_kind: "task"|"brainstorm"|"review"|"research", native_snapshot_sha256: lower_hex_64, purpose: "ordinary_work"|"permission_gate"|"unknown", evidence: [Evidence]}]}`. Limit the file to 64KiB, 16 entries and 4 evidence items per entry, with each excerpt at most 512 characters. IDs must be unique and belong to this request's endpoints; unknown fields, mismatched workstream/kind/hash or malformed values refuse. `Evidence` is exactly either `{source: "native", field: "description"|"design"|"acceptance"|"notes", sha256: lower_hex_64, excerpt: nonempty_string}`, or `{source: "artifact", sha256: lower_hex_64, excerpt: nonempty_string}`. Native hashes must match the complete fresh field bytes; artifact hashes must resolve to retained exact bytes with recorded provenance through a proposed read-only management-module hash lookup over retained evidence objects (not an assumed installed API); unavailable objects are unknown, with no network fetch or caller-selected code/path traversal. Excerpts must be literal substrings, not executable instructions. No title-only inference, guessed purpose, code loading, native metadata writes or runtime rule changes are permitted.
- An `ordinary_work` attestation needs nonempty exact evidence actually describing this endpoint's work-product purpose. It is an untrusted proposed fact until the existing authenticated management card visibly presents the role, decisive purpose excerpt/source, known protected-gate facts and exact snapshot/evidence digests, and the ordinary per-operation A decision covers those facts. That is the existing management decision, not an extra approval, model invocation or deployment. The card cannot override native gate kinds, established protected-gate evidence, missing evidence or a contradiction; those produce `gate`/`unknown` and removal refuses before posting. Ambiguous source meaning remains `unknown`, never an author-only assertion of ordinary purpose. A known protected gate cannot become ordinary through a fresh attestation or per-operation card.
- The shim/module must read the file as data, validate its closed schema and bounds, retain its exact bytes/hash in the saved request, and revalidate fresh endpoint snapshots and complete protected facts at all usual boundaries. Apply consumes only the retained card-bound attestation, not a replacement file. Native/source drift requires fresh facts/card; it does not silently update the attestation. The rule parser and its predicates are installed code; adding a legitimate new endpoint's supported evidence under unchanged rules does **not** require a changed design, redeployment or any approval beyond the original per-operation card.

Only verified `ordinary_work` endpoints may be removed/replaced; `permission_gate` and `unknown` refuse. Without attestations, status/reclaim/add remain available while unclassified removal/replacement refuses. Fixtures must include a newly created ordinary endpoint with exact work-purpose evidence succeeding under one ordinary management card and unchanged installed rule hash; native gate kinds, custom gate evidence, omitted known protection, unknown/contradictory purpose, false excerpts, stale snapshots and attempted rule/code input must refuse. Adding a gate records no approval. Retain all protected edges, including deployment prerequisites distinct from the primary design pin. This strengthens Management without relaxing native `bd_dep` approval protection.

## 3. Operations, effects and evidence

Only the genuinely enrolled Codex controller and its exact receiving lane may use the pinned `workstream-manage` facade. Raw mutable-checkout `btq` is not the installed route. Existing supported entry points are:

```text
workstream task RUN --controller --workstream WS pause
workstream-manage RUN --workstream WS --lane ID manage ID --plan --change FILE --evidence-file FILE [--post]
workstream-manage RUN --workstream WS --lane ID manage ID --apply --ask ASK --expect DIGEST
```

`RUN`, `WS` and `ID` must match the enrolled identity, configured workstream and lane. No impersonation or routing conversion is introduced. The new read-only `manage ID --inspect`, journal-only `manage ID --settle --expect RECORD_DIGEST` and plan argument `--endpoint-facts-file FILE` are **proposed shim/module support**, not existing CLI support; implementation must add their closed grammar without changing `bin/btq`. After ordinary pinned-runtime verification the shim dispatches these extensions into the existing `btq-manage.py` `management(queue, namespace)` factory; it must not pass unsupported arguments to the unchanged raw parser. Other established verbs retain their existing dispatch. They cannot accept arbitrary native commands or metadata changes.

| Operation | Admitted delta and restrictions |
| --- | --- |
| Planning status | Only blocked/unassigned → open/unassigned. Closed planning is excluded: current native detail cannot enumerate the affected dependent set or prove lifecycle reclose support. No close, in_progress, assignee or arbitrary status override. |
| Existing implementation status | Original d2 grammar retained, including its closed-source case, subject to complete existing authority and truthful effect evidence. This amendment neither certifies dependent visibility nor overrides lane-close replay prohibitions. If affected dependents or later lifecycle safety cannot be established, refuse that request rather than promise completion. |
| Reclaim | Existing stopped-holder transfer into the actual compatible receiving lane, status unchanged. Native claim/handoff note append, reservation/fence settlement and local current pointer are explicit expected effects, not an assignee-only operation. Alive refuses; unknown needs the existing explicit cessation coverage and real holder locks. No timeout inference. |
| Typed dependencies | Existing parked/blocked ownership rules and typed add/remove/replace; closed planning excluded. Native cycle checking retained. Replace adds before removing. Exact endpoint identities/types and expected inverse/count effects are bound. Parent-child edits additionally bind the exact before/after parent derived from the requested native edges; unrelated parent changes refuse. No ambiguous multiple-parent result. |

All other labels, routing, metadata, content and history remain unchanged except the explicitly appended management audit/claim records. Parent remains unchanged except the explicit parent-child delta above. Whole-task comparison must include `parent` in addition to the current `evidence_snapshot` fields; reclaimed planning and implementation requests receive the same strengthened final classification/content checks before the existing Handoff finish effects. This deliberately tightens Management readback for both classes without changing normal implementation eligibility or the original pin checks.

Pause parent pickup before plan/post/apply. Quiesce affected workers and acquire the actual holder/lane locks required by the operation; no missing-lock bypass. Dependency endpoints must be stopped/parked as required by the original contract. Do not automatically unpause, unpark, claim or launch reviews after recovery. Preserve all worktrees and histories.

Worktree evidence must examine every native claim/worktree note relevant to the target, including historical holders when the current assignee is empty. Bind each note's holder/run, repository, path, source and inspection result. Distinguish no recorded worktree from recorded-but-missing, remote, inaccessible, malformed or uninspected. The latter states refuse an effectful plan until supported read-only evidence resolves them; never present them as clean/none or delete them. Bound the candidate inventory; overflow refuses. Existing source/branch/unmerged-work checks remain. Unassigned status must not substitute the receiving controller for the historical holder.

Reopen requires an explicit human-visible blocked reason/source: quote the bounded current native blocking note and any retained human hold/scope restriction. If no unambiguous reason is recorded, state that explicitly in the card; if a material reason cannot fit or be safely disclosed, refuse posting. The facts bind the complete original content, not merely that excerpt.

For planning tasks with an existing review lineage, require a typed retained evidence descriptor: lineage/task ID, original design/revision, cap, unique invocation/start identities, issuance records, available result/report artifact hashes and remaining rounds recomputed as cap minus distinct actual **issued** model invocations. Issued calls consume a round even when failed, aborted, still running or unresolved; completion is not required. A reservation proven never spawned is recorded separately and consumes no round; absence of a result is not proof of nonissuance. Unknown issuance, missing start history, duplicate/conflicting identities or contradictory records HOLD and cannot increase remaining budget or permit status-to-open/work-resuming reclaim. At zero remaining, no reopen or work-resuming reclaim is authorized by this amendment; retain blocked/parked state and request a separately scoped operator resolution via Marmot. Do not reset the lineage or count a new task as fresh budget. Tasks with no review yet require the explicit factual `not_started` state, not an unverified boolean. Recovery does not authorize another review invocation; the controller must check this same retained history before invoking one. This is an operational recovery guard, not a claim that every external model launcher now enforces review caps.

## 4. Authenticated decision and finite card

Each effectful recovery retains original d2's per-operation authenticated Marmot question. Only a fresh actual current-policy principal's authenticated intent covering the exact operation counts. The policy may legitimately include Bel following the operator's explicit restoration instruction; this design neither removes Bel nor infers authority from a key's presumed human/agent nature. A controller/model cannot fabricate, send itself, or synthesize the required consent. Mere policy membership, local text, a review, a cessation statement or this design is not an authenticated decision. Original task/design/deployment approvals remain distinct.

The current user authorizes merging after actual Claude review passes and necessary real approvals are obtained; a separate historical `master go` question is superseded by that explicit instruction. New/changed designs and deployments still require blocking Marmot approval. D2 currently also requires each management card; this amendment retains that approved contract without adding a new routine gate. The separately proposed bounded delegation design is not current authority.

Cards must be self-contained: task/title/kind/class, exact before/after delta, reason/hold, routing and source/worktree facts, liveness/cessation, protected gates/pins, review history/remaining budget, known dependent/parent effects, limitations, nonce, full facts digest and finite choices. Show unsupported effects as refusal, never as a harmless count. Use literal hostile-text quoting, secret checks and supported admind transport bounds. Keep the existing conservative 36-line/3200-character management limit within admind's 40/3500 limits; compact optional labels without dropping material facts. Plan validates with the full 12-character posted nonce width and exact encoded layout. A maximum-size nonce/card is tested. Overflow posts nothing; it does not truncate decisive facts or fall back to terminal consent.

## 5. Versioned journal, liveness and failure recovery

Add a distinct `management_format: 2` record inside the existing Handoff storage envelope; do not reinterpret the base Handoff format as new authority. Required fields include immutable request/nonce/task/run/lane, class/routing/protection, normalized/raw fact hashes, exact change and expected effect sequence, review descriptor, card/ask identity and digest, authenticated decision snapshot, native steps with issued/verified state, audit payload/hash/marker, phase, safe reason and append-only transition history. The original serialized request is retained by hash before every terminal archive; no single-file overwrite may erase it. Archives are immutable content-addressed files below the same lane state root, with an index binding predecessor/next record. Concurrent apply/settle remains serialized by the existing locks.

Decision reads occur outside the queue exclusive lock. Take a current-policy/authenticated ask snapshot, then acquire locks and revalidate the native facts and snapshot age before any write intent. The decision must remain exactly A, with the same authenticated principals/scope; cancelled, B, expired, missing, policy-revoked or unknown never authorize a new native write, even after a prior step. Before each later step release only the queue lock (retain required holder/lane ownership), refresh outside it, then reacquire and repeat all fact/endpoint checks against the expected intermediate state. A snapshot older than five seconds cannot initiate a step. This is a bounded initiation check, not a claim of native-atomic revocation; revocation after a write was issued cannot undo it. If native/transport calls exceed the bound, refresh and revalidate before issuance.

| Observed state | Required supported outcome |
| --- | --- |
| Prepared/posted/authorized, no issued native/audit intent | Drift, B, cancellation, expiry or stale/unknown authority produces `held_unissued`; inspect exposes the reason. Settle archives as `aborted_no_effect` only after fresh readback proves exact before-state and no issued intent. A new card may then be prepared. |
| Validated step ready | Persist exact native effect intent immediately before calling the adapter; only now enter `moving`. Do not mark moving merely to begin preflight. |
| Issued step, response absent/error | Hold `outcome_unknown`; read back exact expected pre/post states and unique markers. A unique landed result becomes verified without repeating the call. Exact pre-state after an ambiguous issued call does not prove nonexecution; no automatic reissue. Conflicting/partial/unknown state stays held. |
| Replace add verified, remove not issued | Both edges deliberately remain. Refresh authority/facts before removing. Refusal/revocation holds this intermediate graph, describes it explicitly and does not silently roll back or issue remove. A later valid original decision may resume only if still exact/current; otherwise a new authenticated reconciliation card must bind this intermediate state and the remaining delta. |
| All native steps verified, final readback changed | Hold `post_effect_conflict`; never stamp done, claim work or restore earlier facts. Inspect preserves exact verified steps and conflict. Reconciliation uses a new card only after the previous record is archived as `superseded_with_verified_effects`, binding predecessor and actual current state. Unknown effects cannot be superseded. |
| Audit preparation read fails | No audit intent was issued; retry the read/build safely. Prepare and persist the exact bounded payload/hash/unique marker before saving `audit_issued`, then call comments-add. |
| Audit issued, answer lost | Search exact unique marker/payload under fresh readback; one match verifies without reposting, multiple/conflicting matches hold. No match after an ambiguous call remains unknown; do not resend. |
| Done | Exact native/parent/class/protection checks, unique audit and local current/reservation/fence effects verified; archive original and transitions before admitting a successor. No automatic worker resumption. |

`--inspect` is read-only and includes all management requests, not only reclaim, returning schema/phase/reason, record/facts digests, known issued/verified steps and safe next actions. It never exposes credentials or unchecked raw payloads. `--settle` operates only on the expected exact record digest and appends journal/archive transitions; it cannot change a task, reissue writes, cancel an ask or erase unknown outcomes. New effectful reconciliation uses the ordinary authenticated plan/apply path with the predecessor reference and exact current state. If an audit outcome remains irreducibly unknown, retain that lane held and report it; other isolated lanes remain usable. A separately scoped audited repair may be proposed through Marmot, never silently inferred from refusal.

Legacy records are not applied under broadened classification. Inspect exposes their original bytes/digest and old phase. Zero-issued records may be archived only after the same no-effect proof and current ask read; old ambiguous posting, moving, comment-issued or unrecognized phases stay held unless existing readback uniquely establishes their actual effects. There is no automatic abort-and-overwrite. Old records still valid under the original implementation-only contract may complete under the exact retained old bundle before upgrade; they are not silently upgraded. Rollback to that bundle is permitted only with no active format-2 records; otherwise retain format-2 read-only inspection and fail closed until a reviewed compatible forward runtime is restored. Archive preservation and rollback refusal are installer checks.

## 6. Packaging, prerequisites and escalation

The existing installer hardcodes old reviewed program bytes and cannot deploy this amendment unchanged. The implementation therefore includes a new manifest-bound management installer mode in the harness script and the matching pinned shim. It first validates the **existing** installed controller helper/manifest, original queue binary and harness digest without refreshing their pins. It accepts only an exact reviewed candidate Git commit with a closed three-file closure (`bin/btq`, `bin/btq-manage.py`, `bin/btq-supervise`) plus exact shim/installer source commit/hash, and authenticated deployment authority binding that candidate manifest. The retained `btq` and `btq-supervise` hashes must equal the baseline; only management module bytes change. No arbitrary caller checksum or dirty checkout is a release authority. Stage the content-addressed bundle/shim/manifest, verify imports resolve to those staged files and the canonical repo remains the pinned queue identity, then atomically switch only the management facade. Preserve the prior facade and all request records. Controller helper, canonical binary, native database, policy, membership and services are outside this deployment delta. A failed preflight makes no installed changes. Prove the prior facade remains usable before switching; validate new inspect/plan on disposable state before live readiness. This is proposed installer support, not a claim it exists today.
