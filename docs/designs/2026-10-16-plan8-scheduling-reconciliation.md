## 3. One recurring owner, finite registry and cadence

Propose host-only `[wsd] timer_owner = "internal" | "systemd"`, default internal. Owner changes require restart; reload refuses them. Internal mode preserves current recurring loops and their fatal-task handling and refuses external scheduled ingress. Systemd mode omits only internal recurring pickup/reconcile loops; startup recovery, event pickup, manual control and quota one-shots remain.

| Registered job | Recurring owner | Effect/policy owner and activation condition |
|---|---|---|
| `pickup` | Systemd monotonic wake, default 60s | WSD BACKSTOP lane; core slice |
| `reconcile` | Systemd monotonic wake, default 300s | Existing WSD recovery lane; unresolved target effects still held by their actual owner |
| `babysitter` | Separate systemd oneshot/timer, 300s | Read-only health/alert producer, §7; no task control |
| `backup_bundle` | WSD snapshot companion to actual Beads backup owner, §8 | WSD journal + schedule-store backup; native backup remains its existing owner's operation |
| `reminder_sweep` | Disabled pending compatibility | Plan6C owns due predicates, attempt ledger and deliveries; ADR15-minute policy sweep is not a delivery-deadline poll |
| `daily_digest` | Disabled; eventual calendar default 08:00 UTC | Approved Plan6 producer/outbox owns content, idempotency and receipts |
| `forge_poll` | Disabled, phase2 | Separately approved forge-bridge intake/identity/decision contract, ADR17 §§12/14; **not Plan5 intake** |
| `user_schedules` | Disabled in this proposed slice | No accepted command/calendar/file-Bead registry; explicit §1 human deferral required |

Existing `backstop_seconds` and `reconcile_seconds` remain the effective cadences in both modes, appear in configuration check/health/install output and bind the manifest. Systemd mode accepts integer seconds 1–86400; nonintegral/out-of-range values refuse the switch before changes. Defaults are 60/300; a prior 20-second setting renders a 20-second timer, never silently 60. Internal mode retains its current validation. Cadence changes require restart and regenerated units/manifest.

For pickup/reconcile, render `OnBootSec=5s`, `OnUnitActiveSec=<effective seconds>`, `AccuracySec=1s`, `RandomizedDelaySec=0`, `WakeSystem=false`. The oneshot is bounded below; it enqueues without waiting for lane completion. There is no UTC slot key to duplicate/suppress a wake. A late activation issues one current wake; missed intervals are coalesced, not replayed. These monotonic timers continue on an offline/unsynchronized host. Suspend or manager downtime can delay them; startup recovery covers lost wakes, not lost effects.

The immutable installation manifest binds version1, UUID `installation_id`, UUID `generation`, service UID, canonical config/state/queue location identities (no credentials), reviewed release/unit hashes, effective cadences, enabled finite registry and sorted workstream allowlist (at most128 valid existing workstream slugs). `generation` is the single term for schedule/configuration generation; it changes only through approved installation, not each daemon boot. No alternate dynamic job strings, imports, shell commands or actor parameters exist. Trusted same-service-UID assumptions apply: matching manifest data is consistency evidence, not a credential against a malicious same-UID process.

## 4. Idempotent wake ingress, origin and bounds

Propose `wsd scheduled-wake pickup|reconcile` as a narrow client over the existing private control socket, plus a strict corresponding request variant. Exact fields: `op="scheduled-wake"`, `version=1`, lowercase UUID strings `installation_id`, `generation`, `request_id`, and `job` in `{pickup,reconcile}`. Unknown/duplicate/missing keys, wrong types and noncanonical UUIDs refuse. No targets or occurrence digest come from the caller; WSD selects the exact installed allowlist. Keep **4096 bytes including the newline**, and additionally cap this tiny serialized variant at1024 bytes; do not raise shared socket limits.

WSD validates owner, loaded manifest and readiness (startup recovery completed, not maintenance/stopping) before enqueue. Pickup calls `_backstop` through a **distinct scheduled lane key** `("scheduled-pickup", None)`, never `_operator_pickup` or the manual/event pickup key. Reconcile uses `("scheduled-reconcile", None)` and `reconcile_one`. Both use the existing job-error wrapper, per-workstream operation locks and quota rearming. Duplicate wakes join only queued scheduled work. A later wake while one runs can queue one further job per key; backlog is bounded at one running and one queued scheduled job of each kind per lane. No job starts after the existing shutdown boundary.

This is at-least-once wake delivery. It is safe to issue a later wake after timeout because scheduler/recovery effect guards, not wake exactly-once, govern actions. There is **no durable wake intent, not-issued proof, tick-status settlement or uncertain wake ledger**. Losing a wake during process failure is covered by startup and the next timer. A wake response is not proof that a native write, review, launch, send or task completed.

Origin association is explicit and bounded. Each submitted/joined wake has its `request_id` observed as scheduled ingress; WSD maintains on the queued scheduled job a count, first and last request IDs and up to64 individual request IDs, plus `origins_truncated` for further joins. On start, emit a single ordinary journal event containing that bounded association and BACKSTOP origin; task-action records retain their existing identities. If the journal fails, normal job failure/recovery rules apply. This is diagnostic association, not a durable promise for every lost/socket-timeout request. Manual and scheduled origins cannot coalesce; a truncated set is never presented as complete attribution. Completed job origins need not survive as replay keys.

New response variant has exactly `version=1`, echoed `request_id` (null only when invalid/unreadable), `status` in `{queued,refused}`, `reason` in `{none,invalid_request,owner_mismatch,generation_mismatch,manifest_mismatch,not_ready,maintenance,stopping,unsupported_job}`, `targets` integer0–128 and `joined` integer0–targets. `queued` requires reason none and means admission of all target lane submissions in the same event-loop turn, with no await/effect between validation and submission. Shutdown cannot interleave that turn; refuse before any submission if not all lanes are open. `refused` has targets/joined0 and is pre-enqueue only. Unexpected partial submission error closes scheduled admission and returns no success; later wakes remain harmless and normal shutdown/recovery owns any admitted work. This partial case is transport-unknown, never claimed definite-unsent. Runtime job outcomes are health observations, not fields inferred from this admission reply.

The oneshot has a five-second total monotonic connect/write/read deadline and1024-byte response cap. Invalid/oversized/timeout response records only `wake_unconfirmed`; there is no blind claim of success or irreversible uncertainty hold. One request per job per activation, no immediate retry loop; the next timer retries naturally. Systemd `TimeoutStartSec=10s`, no automatic oneshot `Restart=` loop. This prevents old uncertainty work from starving fresh pickup. Workstreams remain independent after admission.

## 5. Effect scheduling without a second authority

Only effectful jobs need persistent deduplication. New private schedule-store schema1 is **owned solely by the WSD process**, through a dedicated maintenance/effect lane and RLock-protected connection; the CLI runner never opens or writes it. Babysitter has a separate observation store and no access to this writer. Reuse journal infrastructure helpers for private directories, SQLite online backup and transaction/busy semantics while retaining a distinct strict versioned schema (do not construct a mutating Journal over a different schema). Missing after prior installation, corrupt, unexpected schema or failed upgrade refuses effect admission and reports a hold; it never blocks idempotent core wakes merely because an effect history is missing.

Proposed typed `effect-wake` is a separate request variant on the same4096-byte socket, carrying version/install/generation/request UUIDs and registered effect `job` only. It returns bounded enqueue/refusal, not effect success. WSD computes eligibility and exact slot from its installed registry and clock; the caller supplies neither opaque keys nor invented slots. At most one queued/running evaluation per effect job, round-robin among enabled jobs. One pass has30 seconds, at most8 producer calls, each at most5 seconds subject to remaining total budget; reserve at least one call for a newly due job if any, then alternate unresolved reconciliation and new due jobs. Producer calls with a larger required budget cannot activate under this contract. Per-effect unknown can hold that job but cannot starve other jobs or wakes.

Stable effect identity is canonical JSON array `[1, installation_id, generation, job, slot]`, hashed with SHA256 by the authority. `job` is the registry ID and schedule ID; there is no separate ambiguous namespace. `slot` is an integer UTC day number for calendar daily jobs; calendar resolution pins timezone, intended local time and chosen UTC offset alongside it. One configured civil occurrence per day: repeated local time chooses first offset; a nonexistent time advances to the first valid instant. Calendar sequence must strictly increase; backward UTC never reopens a consumed slot. For future interval effects the immutable registry defines integer UTC anchor A/period P and `slot=floor((now-A)/P)`; reject negative/pre-generation-start slots. Any such adapter must first be admitted with its exact producer contract. Coalesce missed *unissued* slots to latest eligible; record aggregate skipped count, never replay each.

Per `(installation_id,generation,job)` keep O(1) `highest_consumed_slot`, `skipped_count`, latest terminal receipt summary, and at most one unsettled occurrence. Write intent and dispatch mark before calling producer. States: `prepared` (no dispatch mark; safely resumable), `dispatched`, `succeeded`, `definite_unsent`, `uncertain`, `held`. A committed dispatch mark without a compatible authoritative receipt is uncertain, including after restart. Later slots of that job wait until its actual producer settles it. No absence-at-a-point-in-time claim proves an old in-flight request unsent. Producer settlement must fence late issue, or affirmatively prove effect outcome; without that support, retain uncertain and request genuine Marmot recovery consent, never replay. Other jobs continue.

A success receipt means its exact adapter-defined effect (backup artifact or durable producer enqueue); actual remote delivery/operator acceptance remains separate. Definite-unsent may retry the same slot only if the producer proves it cannot arrive later. Advancing high-water and storing terminal result is one store transaction. High-water covers all old slots even after recent detail compacts. Keep recent terminal receipts up to30 days and at most4096 rows globally, evicting oldest terminal detail only; no dedup dependency on these rows. At most8 enabled effect jobs and8 unsettled rows per active generation; retain unresolved old generations (at most16 total generations with unsettled effects, then refuse only new effect-generation activation). No 100k lifetime limit or routine rotation of core scheduling. Full raw history belongs to producer audit/retention policy; count/hash compaction is disclosed, not fictitious complete history.

Effect clocks start unready on each process/boot. Proposed readiness envelope: installation/generation, boot ID, clock epoch, UTC and monotonic samples, durable highest admitted UTC and typed reason `{ready,recovering,unsynchronized,rollback,jump,invalid_config}`. Require store recovery, valid timezone, affirmative platform synchronization evidence, and two samples at least30 monotonic seconds apart with elapsed discrepancy at most2 seconds; refuse calendar admission behind durable UTC high-water. Rollback/jump or synchronization loss clears readiness; monotonic samples never span boots. This gate applies only effect due evaluation. Pickup, reconcile, observation and ordinary deterministic commands continue. Plan6C is not presumed to implement this proposed envelope.

## 7. Health and a bounded observation-only babysitter

Add a version1 snapshot producer to the serving event loop **before startup recovery begins**, with `recovery_status=in_progress`; long lane recovery does not falsely imply dead process. Mark state dirty on transitions. Every30 seconds the event loop captures one immutable bounded summary and delegates its atomic private-file write/fsync to a worker, at most one outstanding write. It does not write on each workstream transition. A stuck writer yields stale snapshots, never an independent thread advertising fresh health. The loop-sampled sequence/time, not write completion time, is the liveness sample. Startup/recovery stalled beyond600 seconds reports recovery-stalled separately while continuing heartbeat. Serialization is at most256KiB and128 workstream aggregate entries, no task text/transcripts/prompts/credentials.

Snapshot required fields: version/install/generation/process UUID/boot ID, monotonic sample/sequence, UTC sample, owner/effective cadences, recovery status `{in_progress,complete,failed}`, recovery-start monotonic time, last scheduled pickup/reconcile admission and completion per workstream, and bounded counts/oldest age for each registered effect's pending/uncertain/held state. WSD is the sole source for its effect backlog. Maintenance receipt has exact affected owner/generation, expiry, source artifact hash and max30-minute duration; it suppresses only expected liveness alerts, never task gates, and cannot renew itself indefinitely.

Observer validates private owner, no-symlink regular file, size/schema/identity, sequence and sane timestamps; it never constructs Journal/queue or reads credentials. Current general status is not asserted read-only. Proposed snapshot inspection is the only required health surface. Stale means sane UTC age>90s or future>30s, or unchanged sequence across90 local monotonic seconds; invalid boot/clock evidence is unknown. On observer restart only sane UTC can establish initial age. Valid advancing same-process samples restore liveness; new process has explicit recovery state.

Closed observation codes and precedence: `maintenance` for valid unexpired matching maintenance; otherwise `unavailable` for missing/unreadable snapshot, `unknown` for schema/identity/clock invalidity, `stale` for age/sequence failure, `recovery_failed`, `recovery_stalled`, `wake_overdue` (healthy completed recovery but no scheduled admission for greater than2×effective cadence+10s), `effect_hold` (clock/store/capacity/uncertainty holds), or `healthy`. Enabled dependent jobs only; disabled jobs are listed as disabled, not overdue. A running lane can be reported as pending independently of wake liveness, without claiming task failure. A valid recovery in progress before600s is healthy with recovery progress. Maintenance expiry immediately re-evaluates other conditions.

Each nonhealthy, nonmaintenance code opens its own persisted episode keyed by install/generation/code; unchanged condition does not repeatedly notify. Clearing that code produces one recovery notice (even if another code remains). Fixed plain-text templates: `Plan8 health: <code>. Scheduled work status requires attention. Remote delivery unconfirmed.` and `Plan8 health: recovered from <code>. Other holds may remain. Remote delivery unconfirmed.` Allowed substitutions are the closed code only; structured private state carries counters/times. No model or task action is called. The5-minute observer's30-second pass deadline gives worst nominal detection after the90-second threshold of a further300+30 seconds; this is not a five-minute task-recovery guarantee.

Reuse `admind/alerts.py` reader/file contract; it is not an existing writer API. Add one shared safe writer (coordinate the proposed 6C helper, never two competing implementations) with a distinct `p8_` namespace, fixed template/code/episode input, no caller path, private-directory verification, O_EXCL/O_NOFOLLOW0600 temporary file, file fsync, atomic rename and directory fsync; matching final bytes settle idempotently and conflicting bytes refuse. The final shared-helper contract must be compatible before both consumers activate. File shape remains: atomic safe ID1–64chars, RFC3339 created_at, redacted safe text; file receipt is local reporting only. Actual membership/policy/outbox rules govern remote delivery. Keep at most256 outstanding alert files; at capacity retain a bounded per-code pending/latest summary and overflow count locally, and emit a fixed service-journal capacity diagnostic. Drain summaries fairly after space returns; disclose that intermediate repeated episodes were coalesced. **Never gate WSD admission on observer capacity.** Observer owns only its private episode/pending state, not WSD's store. The observation store has at most the finite codes for current and previous generation; older undelivered summaries coalesce by code with count, not unlimited episode records.

Same-manager failure is an explicit residual: disabled/dead user-manager timers can stop core wakes and observer simultaneously without generating a new file. Existing internal `serve` timer-fatality handling cannot detect an external timer's death. Deployment verifies timers and records this limit; no external dead-man or admind heartbeat endpoint is claimed implemented. An independently hosted watchdog would be a separate design, not hidden new architecture or authority.

## 8. Backups, coordination and maintenance

The proposed `backup_bundle` owner uses **the actual existing Beads backup schedule and owner**, not an unrelated03:15 default. Installer inventory must identify the owner's canonical unit/command and effective schedule. Static preparation saw a03:15 daily timer; that is not proof of current enablement or a portable default. Render a narrowly approved companion invoked in the same backup cycle immediately after the existing Beads backup attempt, without changing native backup identity or adding a second Beads invocation. A failing Beads backup still allows the two local snapshots; bundle outcome is partial and names that failure. If the owner cannot expose a supported companion seam without unauthorized changes, backup activation holds pending a scoped deployment solution; core wakes do not. This meets “timed with Beads backups”, not cross-store atomicity.

Proposed WSD maintenance request queues one `backup_bundle` on its dedicated lane. It derives destinations from private installation configuration, never a caller path. With no open transaction, call existing locked `Journal.backup` on the daemon-owned connection off the event loop. The Journal RLock spans check and whole SQLite copy; other lane journal writes can wait for the copy. Do not acquire workstream operation locks while holding that journal lock or call backup from inside a transaction. Then, under its own connection lock, snapshot the WSD-owned schedule store using `backup_to`; never acquire both database locks simultaneously. JournalBusy/failed integrity/output is failure, not backup success. Snapshot copies are independently consistent and carry individual capture times, hash, schema version and source generation; not an atomic Beads+journal+schedule checkpoint.

The bundle backs up the schedule store in the **same daily cycle**, solving its owner/cadence gap. Retain seven daily/four weekly verified bundles, private directory0700/files0600. Publish the bundle manifest atomically only after both snapshots are checked; include actual Beads backup reference/status from the existing owner's supported receipt, or explicitly `native_backup_reference=unknown`. An unknown native receipt cannot be labeled full backup success. Schedule dispatch evidence precedes copy; crash after copy/before result settles only by exact verified artifact manifest under the installed trusted owner. Missing/partial artifacts are not success; retry is permitted only after the old in-process backup can no longer write (process exit plus supported exclusive maintenance ownership), with unique attempt destination, never replacing retained success. Optional producer sends do not inherit this local-backup retry rule.

Backups and restore rehearsal use SQLite backup APIs, not raw WAL-file copies. Test restore in a disposable location, verify integrity/content/permissions. Do not restore an old schedule store while keeping newer effects replayable. After any restore, effect admission is held until producer reconciliation/high-waters establish a safe boundary; if impossible, genuine Marmot recovery decision must retire the old generation and choose a nonreplaying new boundary. Core startup/native recovery remains real. Timer activation never authorizes live DB restore.

## 10. Installation, owner switch and rollback

Extend reviewed immutable release/unit renderers and installer; no editable checkout units or invented existing flags. Preserve exact archive/pinning/preflight/adoption checks. Deployment inventories every prior/proposed timer, service and cron owner with canonical path, hash, enablement, running state and config bytes. Similar cadence does not authorize disabling unrelated Hermes pickup/escalation, queue supervisor or Beads backup. Only enumerated owners covered by actual Marmot deployment authority can change.

Switch steps: (1) record baseline/config/unit backups and publish exact deviations; (2) enter maintenance and close scheduled ingress; (3) disable previous timers **and stop/wait their active oneshots**, verify no matching process remains; (4) drain/stop WSD under existing bounded shutdown, preserve running-agent/session scopes; (5) install validated release/config/manifest/units; (6) start WSD, verify recovery and snapshot; (7) enable only matching new timers and verify actual scheduled BACKSTOP admission and absence of duplicate loops. A failed quiescence/drain/readback holds activation. No timeout is proof a native action failed.

A wake has no durable pending row; lost wakes resume via startup/next timer. Effect prepared rows remain safely unissued; dispatched/uncertain rows are retained, not retired as unsent by a generation change. New generation may activate core wakes while old uncertain effects stay held and visible; the same effect job cannot admit new slots until reconciliation settles its prior generation. No automatic effect replay during switch.

Rollback closes new ingress, disables timers, stops/waits all active new oneshots, and drains/stops new WSD before restoring **the predecessor's exact compatible config and units**, including removal of unsupported new `timer_owner` keys via byte-for-byte config restoration. Restoring only the old executable would cause 076's unknown-key error78; never claim that rollback works. Preserve new schedule-store evidence and never ask an old binary to migrate/read it. Retain separate incident snapshots; don't roll back native history/policy/groups/claims/worktrees/session identities. Start predecessor only with its matched owner/config bytes, verify healthy internal mode and disabled external timers. If old effect formats cannot be interpreted, keep those effect jobs inactive and preserve data for supported recovery. Rollback does not settle unknown effects or erase results.
