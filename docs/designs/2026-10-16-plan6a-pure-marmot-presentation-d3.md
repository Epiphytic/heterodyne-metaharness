## 2. Pure API and validation boundary

Proposed module `heterodyne.wsd.presentation` exports `classify(input) -> ClassificationResult`, `render(view, policy) -> RenderResult`, and `render_card_pair(card, policy) -> CardPairResult`. `render` refuses approval/question kinds with Invalid(protected-pair-required); protected kinds are accepted only by render_card_pair, including Missing(protected). The card argument is a protected Available or Missing view, including rendered_at/source sections when available; Pair returns workstream/control **texts only**, atomically; no destination or send operation. It exists to require identical protected content/digest across mirrors except their configured control mention. Partial pair success is not a result.

Inputs are closed immutable version-1 records with tagged unions, validated at every public call, including directly constructed Python objects. No unknown field/enum, bool-as-integer, NaN, negative count, invalid scalar, naive/non-UTC timestamp, duplicate identity/key, lone surrogate, or malformed optional union is accepted. `Invalid(code)` is an API result distinct from render Withheld. Validation errors never echo values. No callbacks, handles, arbitrary metadata dictionaries, raw native IDs, destination/reply IDs, receipts, executable action or authority capability crosses an output boundary.

Dates are UTC instants with integer microsecond precision; canonical representation is `YYYY-MM-DDTHH:MM:SS.ffffffZ`. Input size is UTF-8 bytes of canonical JSON: sorted object keys, compact separators, ensure_ascii=false, enum strings, UTC format above, lists in their explicit order. Reject before regex screening when over 256 KiB; a text field is at most 4096 Unicode scalars/16 KiB UTF-8; 100 rows per named collection; 1024 SectionStatus entries maximum. Classification body has its own 256-KiB UTF-8 limit and is not run through presentation redaction. No environment-dependent normalization, truncation or clock reads. LF is the only accepted multiline separator.

No I/O at import or call: clock, randomness, environment reads, mutable global policy, DB, process, filesystem or transport. Immutable regex/constants from `config.secret_scan` may be reused; do not call `show`, `load`, admind.redact or its global login-directory setter. At this baseline the parent config package imports os and binds a default environment argument; that is not itself an environment read. An import audit records actually executed module initialization and rejects actual I/O/registration and imports of service/process pipelines, rather than banning inert references to os/re/typing. If that audit fails, extract the existing scanner constants into a pure leaf with unchanged public re-exports and existing scanner tests; do not fork their policy. This extraction is the only permitted dependency refactor, reviewed in the later implementation diff.

## 3. Classification: finite precedence, no authority

ClassificationInput: version; surface(workstream|control); ingress(unverified|rejected|replayed|verified); suspended(bool); event(Text(body)|ReactionAdded(glyph)|ReactionRemoved(glyph)); placement(root|thread); target(none|stale|unknown|current-task|current-approval|current-question). All header enums must be valid. `verified` means a future trusted ingress established native sender allowlist, account/group registration and replay status; the text cannot set it. This API cannot verify that assertion or authorize any effect.

Evaluate in this order:

1. Valid header with ingress other than verified -> `Ignored(unverified|rejected|replayed)`, regardless of forged, oversized or malformed body. An invalid header -> `Invalid(schema)`. Unauthenticated text gets no diagnostic reply.
2. Verified payload encoding/size/type invalid -> `Invalid(payload)`. Native reaction is distinct from text containing emoji. ReactionRemoved -> `Ignored(reaction-removal-unproven)`; no undo claim. ReactionAdded to current approval while suspended -> `Ignored(trust-suspended)`; to current approval otherwise -> `DeferredDecision(native-reaction)`; to current question -> `Ignored(question-reaction-unsupported)`; all others -> `Ignored(unhandled-reaction)`. Neither returns approve/deny/choice or a dispatch argument.
3. Detect command candidates after skipping leading Unicode whitespace, using a fixed Unicode15.0 White_Space table. If the first nonwhitespace scalar is `/`, only U+0020 may surround/separate the accepted command: any tab/NBSP/other whitespace yields InvalidCommand(multiline-or-control), never intake. Trim U+0020 at both ends for grammar. This applies regardless of thread target. LF/CR/tab/other control in that command -> `InvalidCommand(multiline-or-control)` before recognizing mutations. Split on one-or-more U+0020; case-sensitive, no quoting/aliases/interpolation.
4. Exact query grammar below -> `ReadQuery(query, optional selector)`, even when suspended; future ingress must still authorize read policy. Unknown command -> `InvalidCommand(unknown-command)`; wrong query arity/selector -> `InvalidCommand(arguments)`. Recognized mutation -> `UnsupportedIn6A(mutation)` without arguments/intent. Suspended mutations also never dispatch.
5. Noncommand text in a suspended current-approval thread -> `Ignored(trust-suspended)`; suspension alone does not discard task intake/steering/questions. Root workstream -> `DeferredIntake(workstream-text)`; root control -> `Ignored(control-noncommand)`; current task/approval/question thread -> `DeferredSteering(thread-text)`; absent/stale/unknown thread -> `UnresolvedTarget(missing|stale|unknown)`. Literal `👍`, `yes` or `/` later in prose never becomes a reaction or decision.

Query enums/grammar: Workstreams=`/workstreams`; Status=`/status`; BeadStatus=`/status <bead>`; Approvals=`/approvals`; Queue=`/queue`; QueueFor=`/queue <ws>`. Selectors use existing `wsd.ids.SLUG`: `[a-z0-9][a-z0-9._-]{0,127}`. They remain selectors, never paths/options; even a selector containing adjacent dots must be resolved against an existing authorized binding by the later consumer. Native IDs never enter query output. Unsupported recognized mutation names are exactly `/approve`, `/deny`, `/pause`, `/resume`, `/stop`, `/harness`, `/trust-group`; trailing single-line text is ignored, never parsed for execution. The release spelling remains ADR17's open naming decision; `/release` is unknown here. Unknown future commands require an ordinary contract update, not invented aliases.

ClassificationResult is exactly the variants above; finite reason enums are the parenthesized strings in this section. It renders no acknowledgment or error text. A later consumer may use only fixed reviewed notices, not raw body echoes.

## 4. Typed views, source sections and completeness

PresentationView = Available(kind, surface, rendered_at, sections, payload) | Missing(kind). Kinds: task, workstreams, workstream-status, control-status, bead-status, approvals, queue, approval, question, fyi, notice. Missing ordinary kind -> `Unavailable(missing-snapshot)` with fixed `Data unavailable; try again later.` Missing protected kind -> `Withheld(missing-required)` with the exact kind-specific notice in §7. No source is silently converted to zero/empty.

Each SectionStatus has identity `(source, optional workstream safe label, collection)`, original observed_at or explicit unknown, availability(reachable|cached-unreachable|unavailable), completeness(complete|incomplete|unavailable), refresh(pending|idle), count(null | {shown,total}), required(bool). Source is configuration|beads|wsd-journal|account-usage; collection is configuration|state|holds|running|ready|parked|held|deferred|approvals|needs-human|candidates|pause|recent-events|usage|decisions|transcripts|launches|closed-yesterday|open-approval-labels|idle-workstreams|accounts-hit-limit. Collection rows have one corresponding status. Enumerated collections require integer `0 <= shown <= total`; shown equals supplied row count; unknown total is unavailable, not invented truncated count. Scalar/unavailable sections have null count. Per-collection rows <=100; no shared count is reinterpreted for several lists. `required` is fixed by the kind profile below, not caller-selected to disguise a missing requirement.

`complete` is derived: all present required/optional sections reachable and complete, no sanitization/omission/unknown field required by the profile. Optional unavailable sections render explicit unknown and make aggregate incomplete without erasing available required facts. For ordinary views a missing/unavailable required section yields Unavailable. Protected cards use Withheld(required-source) for missing/unavailable required sections, Withheld(stale-approval) for any existing required stale/cached-unreachable/future/unknown-time section; first check missing/unavailable, then freshness, then other protected content rules. Unsafe protected content yields Withheld. CardPairResult never returns Unavailable. Unknown scalar facts remain unknown, not zero. No raw source/provenance values appear in errors.

Fresh iff `0 <= rendered_at - observed_at <= 30_000_000` microseconds; exact 30s fresh, 30s+1µs stale. No duplicated cache-state flag. Future observation yields an unknown/time-unverified section with fixed warning; it is never made fresh. A 6B producer may conservatively reject such source data before rendering; 6A's rule does not oblige that producer to forward it. Original observation times never become refresh/render times.

Every ordinary data response (task, workstreams, workstream-status, control-status, bead-status, approvals, queue) ends with `Observed <oldest valid required UTC, or unknown>; rendered <UTC>`. FYI has its header/body/no-reply line and this time footer. Notice and protected kinds have no generic time footer: Reminder is exactly its specified line; other Notice variants use only their variant text, with Digest subject to ordinary pagination but no generic footer. Relative durations say `at render time`; reset/resume uses absolute UTC.

Status warnings coalesce by source and normalized state across all selected workstreams/collections, using the oldest valid original observation UTC (or unknown if any is unknown). One line per affected source, never one per collection: `⚠️ <Source>: <state>; as of <UTC or unknown>`. For beads unreachable use exactly `⚠️ beads unreachable, data as of <UTC or unknown>`. State severity precedence is unavailable, unreachable, time unverified, stale; refreshing, stale. Per-row unknown markers and collection counts preserve finer distinctions without multiplying banner lines. For four affected sources, sort by the fixed source order configuration,beads,wsd-journal,account-usage and render exactly three lines: `⚠️ configuration: <state>; beads: <state>`, `⚠️ wsd-journal: <state>; account-usage: <state>`, `Warnings as of <oldest UTC or unknown>`. This explicitly coalesces dates to the oldest safe bound. At most three warning lines total. Every page repeats this bounded warning summary before data; missing data is never silently called empty. Cached-unreachable warns even if younger than30s.

### 4.2 Protected approval/question records

Approval: bead, optional purpose(design|execution), what, exact_effect, excludes, why, context_summary, evidence[], digest12, lifecycle(current|stale|superseded), content_revision, digest_revision, source_eligible, answer_policy(wsd-standard|unsupported). content_revision/digest_revision are opaque equality-only tokens from **one owner atomic snapshot**, never displayed. Equality alone is not a proof of native binding: later adapter must prove the real owner read/digest operation and native admission separately. All five parts, excludes, evidence, exact effect and digest are required. Noncurrent, unequal revisions, source_eligible=false or stale/unreachable/unknown required source -> whole Withheld, no footer. Missing purpose simply labels `Approval`; unknown purpose is Invalid, not guessed. Unsupported answer policy -> Withheld(unsupported-answer-policy), not an unknown schema enum.

Exact_effect is EffectText consisting of Literal spans and PublicHash spans; concatenation is exactly the owner's canonical typed payload, without normalization. PublicHash is tagged sha1(40 lowercase hex)|sha256(64 lowercase hex) and may only exempt identifier scanning for that precise span. It cannot exempt a secret-pattern match, login path or cross-span secret. Arbitrary opaque tokens/public keys are not PublicHash. `excludes` is mandatory protected text; explicit `none` is allowed only if genuinely provided by the owner. Renderer never invents exclusions or silently edits effect text. Invalid/unrenderable content gives a cannot-approve-as-written notice with reason; it does not write a deny decision.

Question = Plain(title,context,question,answer_instruction) | Choice(title,context,question,choices[2..6],recommended_label-or-none). Choice labels match `[a-z][a-z0-9-]{0,15}`, unique by exact equality, with safe nonempty descriptions; recommendations must name a choice. Yes/no uses literal `yes` and `no`; recommended no renders `Recommended: no` and only `Reply with a choice label.`. Plain renders the supplied protected literal answer instruction. No reaction answer legend for questions, no generic thumbs conversion, no guessed recommendation and no admind answer-policy change. FYI is distinct Fyi(title,body), always `FYI: no reply needed`, never an answer prompt.

### 4.3 Typed evidence, not a substring URL check

EvidenceRef is a closed union. Repo identity is an explicitly supplied HTTPS forge origin, owner/name components `[A-Za-z0-9_.-]+`, neither dot/dotdot; no credentials, port, query, percent escape, whitespace, backslash or Unicode host. Forge kind github|gitlab selects exact structural paths. Repo identity is configuration/provenance, not inferred from user prose. Full commits are 40 lowercase hex; no floating branch accepted. Positive decimal PR number; line ranges have positive integers and end>=start.

- File(repo,commit,path,line_start?,line_end?): GitHub `/owner/repo/blob/<commit>/<path>#Lx-Ly` or GitLab `/owner/repo/-/blob/<commit>/<path>#Lx-y`. Path is nonempty slash-separated ASCII `[A-Za-z0-9._-]+`, no empty/dot/dotdot component. Fragment absent when no line, one line when end absent. Renderer constructs the URL; never accepts an arbitrary URL field.
- Commit(repo,commit): GitHub `/owner/repo/commit/<commit>`, GitLab `/owner/repo/-/commit/<commit>`.
- PullRequest(repo,number,head): PR link `/owner/repo/pull/<n>` or `/owner/repo/-/merge_requests/<n>` **plus separately displayed immutable Commit(head)**; floating PR alone is invalid evidence.
- Range(repo,base,head): two full distinct commits, GitHub `/owner/repo/compare/<base>...<head>` or GitLab `/owner/repo/-/compare/<base>...<head>`; display `BASE..HEAD` with both literal pins, not a claimed semantic equality of three-dot web diff and native range. Exact range contents must be supplied by the owner if forge view differs.
- BeadContext(short_bead,digest12,accessible_detail: File|Inline): a bead number alone is not a permalink. Detail includes that content binding; no invented native URL.
- OperatorDoc(title,content_digest12): owner-proven no-forge immutable document covered by the actual ask digest. Render `Document: <title>; digest <digest12>; request the complete document from the approval owner via Marmot (approve-bead --doc).` This is an operator lookup pointer, not a URL, path, terminal-consent route or claim the renderer opened the document. The trusted owner must support that exact documented retrieval; otherwise Invalid(unsupported-reference).
- Inline(title,full_text): no-forge immutable doc/excerpt already covered by the owner's digest, complete protected text, no fake hyperlink. If too large, Withheld(content-too-large), requiring a real accessible pinned reference or redrafted ask; never silently shorten it.

Structural acceptance proves neither reachability nor authorization. Future admission proves the actual GitHub object is published/accesssible and the operator can read full content. 6A only emits atomic links; no fetch, shortener or shell. Unsupported forge refs require an explicit compatible reference adapter, not a made-up URL. Approved context can always use complete Inline when it fits.

## 5. Notices, exact templates and deterministic packing

Notice union: AllBlocked(workstream,blocked_beads_count,approval_count,reason); AllAccountsExhausted(workstream,role,reset-or-unknown); AccountChanged; DeliveryUnconfirmed(card_safe_label); Reminder(card_safe_label, safe reference EvidenceRef); Digest(closed_yesterday[],open_approval_labels[],needs_human[],idle_workstreams[],accounts_that_hit_a_limit[]); TrustSuspended; CannotApprove(reason); Terminal(busy|usage|not-found|unsupported|unavailable|narrow-query). Payloads are supplied observations, never due predicates. Digest has a separately counted section for each of its five lists. No receipt/timer/re-gate or task change is computed.

Fixed terminal texts: busy=`Read service busy; try again later.`; usage=`Use /workstreams, /status [bead], /approvals, or /queue [workstream].`; not-found=`Item unavailable in this scope.`; unsupported=`This action is unavailable on the read surface.`; unavailable=`Data unavailable; try again later.`; narrow-query=`Too much detail; request a narrower view or complete details from the owner via Marmot.` These finite notices contain no echoed selector. CannotApprove=`Cannot approve as written: <fixed reason label>. Ask owner to correct the card; no decision recorded.` Reasons map to fixed labels in §7. TrustSuspended=`Group trust suspended; reads require current authorization; actions remain held.` AccountChanged uses the exact recovery sentence in §4.1. AllBlocked=`<workstream>: all <N> beads blocked on <M> approvals: <reason>`; AllAccountsExhausted=`<workstream>: all <role> accounts exhausted; reset <UTC or unknown>`; DeliveryUnconfirmed=`Delivery unconfirmed: <label>; operator attention needed.` Reminder=`Reminder: <label> — <safe reference>` only, no repeated full card. No notice mentions the operator. Actual alert/recovery owner retains escalation if a notice cannot be rendered/delivered.

Ordinary header is `<Kind>: <safe label or title>`; Kind labels are Task, Workstreams, Status, Bead, Approvals, Queue, FYI, Notice. Task line2=`<reaction> <state/reason>`; line3=`<agent> · <role> · <branch>`; subsequent field/row lines use the ordered names in §4 and `label: value`, ordered collections as supplied, unknown=`unknown`, none=`none`. Join row fields with ` · ` and row lists with LF. One field/list entry is one atomic line unless wrapping ordinary safe prose is needed. Account windows and events use the explicit field order above. Safety/availability warnings precede data; absolute-time footer follows it. The later implementation must commit exact byte fixtures for every kind/variant and expose all fields in this order; it may not omit inconvenient fields to fit a card.

Approval single-message template: optional `Approval (design|execution)`/`Approval` plus bead and configured control mention on line1; `What: ...`; `Effect:`; opening fence; exact effect lines; closing fence; `Excludes: ...`; `Why: ...`; `Context: ...`; one `Link: <typed ref>` line per evidence output (PR and pinned head use separate lines); exact `👍 approve · 👎 deny · ❤️ always · reply to steer`; `Context digest: <digest12>`. No time footer for protected cards (their freshness is a precondition, not silently omitted source warnings). With one-line effect and one evidence line this is12 lines including header; additional typed links and complete wrapped parts consume the remaining36-line budget. A larger effect or wrapped section that exceeds36 lines withholds; five mandatory parts/excludes/footer are never sacrificed. Fence length is max(3,longest consecutive backtick run in exact effect+1); same opening/closing fence, no language label. Code content stays byte-exact. Question uses `Question: <title>[mention]`, `Context: ...`, literal question, choices in supplied order (`label: description`), optional `Recommended: label`, then literal instruction or `Reply with a choice label.` Entire question <=36 lines. Single card has no part marker. Workstream/control pair differs only by mention, and is withheld together if either variant fails.

Policy max_chars is an integer 200..4000 (default2000); measure Unicode scalar values of final text including escaping, markers, fences, LF, mention and footer; maximum prose/exact-effect line width is120 scalars. Each generated typed URL is an independent atomic line up to512 scalars (still inside max_chars and protected3200 cap); ordinary labels cannot use this exception. A long header wraps its safe label before a separate fixed mention line; never split or escape the mention. Approval cannot wrap exact effect: >120 -> Withheld(content-too-wide). Ordinary safe prose wraps at last U+0020 <=120, otherwise before scalar121; links and protected spans stay atomic. Recheck all limits after escaping/wrapping. Raw source text is scanned whole before any formatting, wrapping or truncation; there is no ordinary silent truncation.

Ordinary pages have <=8 physical lines and <=max_chars; greedy maximal **ordered atomic lines**, including repeated header/time footer and relevant warning lines. First page ends `↳ part 1/n`, later pages start `↳ part i/n` after the kind header; single page has no marker. Compute greedy packing with one-digit markers, then if needed two-digit markers; recompute until marker digit width is stable, at most two complete passes. Actual part count determines n; require n<=20. Never move data ahead of its warning. Too-wide ordinary atomic ref/line or infeasible header/warning framing -> NeedsDetails with the fixed owner-lookup text. If rows exceed20 parts, render the maximal ordered complete-row prefix fitting19 parts and reserve the final part for explicit `Showing N of M; remaining details unavailable here; request complete details from the owner via Marmot.` Counts bind the actual supplied source total, aggregate complete=false. No cursor, implicit pagination or claim all rows displayed; this specifically supports /approvals and /workstreams with no narrower command. No partial parts survive NeedsDetails. The explicit bounded prefix result is Rendered(complete=false), not a hidden truncation. For incomplete collections append `<collection>: showing N of M; more available`; unavailable sections show `<collection>: unknown`. The flag `more available` describes source completeness, not a cursor/fetch promise.
