## 4. Queue publication, lock order and bounded work

Reuse `Store.load/save`, supervisor record_scope and Coordinator.operation rather than introducing a second coordinator. All supported record and summary writers (scan, hold, mark, summary-abandon, pinning and recovery projection) must share the existing host supervisor serialization domain. Under it perform exact observed-bytes CAS, unique same-directory exclusive temporary creation, fsync, replace and directory fsync. Temporary cleanup owns only its exact file. Atomic replace alone is not CAS. Explicit reload establishes a fresh observation epoch; summary writes carry an actual observed expected value instead of silently reading the latest at save. Expose one source-owned epoch boundary instead of private `_versions.clear` coupling.

Remove the scan-wide gate SH lifetime. Listing is only a hint: read under one finite gate admission, release, then reacquire turnstile SH → gate SH for each bounded per-bead refresh/examine/act scope. Repeat enrollment, exact roots, issue/current-authority and record observation after reacquisition. Never hold the host store lock while waiting for turnstile/gate; order remains admission → host serialization → bounded journal sections, with journal lock released before network/child work. Queue recovery/backup retains turnstile EX → gate EX → journal/inner locks; no admind RPC under EX. No nested scan/outer operation borrowing is introduced.

Each bead scope has a monotonic deadline no greater than5seconds from admission, including external work: subprocess/transport timeout is bounded by remaining budget, stop/reap proof is required for child completion, and uncertain/late effects retain the durable UNKNOWN receipt. If the current external API cannot enforce that bound, refuse before launch or stop the scan with typed HOLD; do not extend backup's30second wait or workers'5second admission budgets. Between scopes an EX waiter gets priority via the existing turnstile. Enrollment drift after a maintenance window refuses the next scope; no stale full-scan capability is cached across release. Offline timing is acceptance evidence, not a production SLA.

Typed maintenance HOLD (`exit_code=75`, including independently loaded module classes and child75) must escape per-bead catches and reach CLI/timer health status. Known per-record malformed inputs may be reported locally; programming defects and systemic admission/storage failures must not become exit0 “healthy” scans. Preserve the actual child-output classification and unknown-outcome receipts.

Reserve configured new-post and open-ask budget before possible remote post/notice, durably retain issuance intent, and conservatively keep the slot on unknown/delivered/failed-local-publication results. Only positive no-send evidence can release it. Update in-memory scan accounting before any fallible follow-up save/comment; on uncertain persistence stop additional dispatch with HOLD. A restart derives outstanding occupancy from retained posting/ambiguous/effect records, never assumes absence or reposts an unknown request. Replacement releases an old slot only after existing positive terminal evidence. Keep existing configured caps, operation1024 bound/90percent reserve, descriptor limits, generation1..3 and30second permit initiation unchanged. Recovery-side supervisor selectors must resolve to exact enrolled roots; basename coincidence, arbitrary64hex and generic ask SQLite projection remain unsupported/HOLD.
