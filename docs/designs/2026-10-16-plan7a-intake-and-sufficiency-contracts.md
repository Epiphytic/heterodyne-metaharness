## 3. Closed grammar, validation layers, and privacy

Proposed later pure implementation: `src/heterodyne/gatekeeper/contracts.py`, `validate.py`, `project.py`, and named offline tests. Python3.12/msgspec already exist; no dependency is added. The following is the complete v1 grammar. Every object has exactly its listed keys; only `?` keys may be omitted (omitted and explicit null are different). Wire structs are frozen and forbid unknown fields. Reject duplicate JSON keys, nonfinite numbers, invalid UTF-8/surrogates, bool-as-int, and trailing input. `[]` means an empty list, not omitted; `null` is explicit. No untyped Python objects, executable values, or provider-specific payloads are accepted.

**Primitive types.** `ID` is 1..128 ASCII letters/digits or `_:.+-`; `BeadID` matches queue6fe `[a-z][a-z0-9-]{0,31}-[0-9a-z]{5}`. `SHA` is40 lowercase hex; `Digest` is64 lowercase hex. `PosInt` is1..2147483647, `Offset` is0..2147483647, each excludes bool. `Text` is a nonempty UTF-8 string <=4KiB; `Title` is nonempty <=200 Unicode code points and <=4KiB; `Body` is nonempty <=16KiB. All three are `PublicText`: the whole value must be unchanged by the configured existing redactor, with no C0/C1 controls except newline/tab. Blank-only text refuses. Full digests remain typed private fields, never a prose redaction bypass. No Unicode normalization occurs.

`NativeValue` is a bounded JSON tree: null, bool, signed64-bit integer, `Text`, list of NativeValue, or object of distinct `ID` keys to NativeValue; <=8 container levels, <=512 total tree nodes, <=32 members/items per container. Floats are outside this profile. Every scalar string must pass the same privacy check. This finite inert-data profile preserves admitted values exactly; it is not an action registry or permission to execute an object. Native6fe permits more values by truthiness; unsupported native values yield a local invalid-profile error, not a claim that the native gate rejected them.

**Native reference profile.** Queue6fe `REF_FIELDS=(kind,id,repo,path)`, `_resolve`, and `Resolution.resolved` are the source contract. Plan7A supports this explicit strict subset of native-accepted shapes; it does not normalize/add/remove keys before hashing:

| Ref variant: exact keys and types | Resolved identity |
|---|---|
| `{kind:"file",id:SHA,repo:Text,path:Text}` | SHA of the exact native Git blob/tree object returned for that path |
| `{kind:"commit",id:SHA,repo:Text}` | same SHA (native resolver requires a commit object) |
| `{kind:"range",id:SHA+".."+SHA,repo:Text}` | same ordered pair string |
| `{kind:"bead",id:BeadID}` | recomputed native linked-ask Digest, including its recursively resolved refs |

Native `_resolve` allows the four named keys and ignores some in individual variants; this v1 profile deliberately rejects unused `repo/path` on bead refs, `path` on commit/range refs, extra range endpoints, and extra ref keys. Repository/path strings are inert native locator values, not fetched, executed, converted to URLs, or claimed public by this pure component. Actual lookup, object existence, linked-bead cycle/depth limits, and infrastructure uncertainty remain native-adapter responsibilities. Private locator values must never be sent to a model merely because this grammar can retain them; a future egress projection needs its own reviewed adapter contract.

`NativeAsk` is `{effect:NativeValue,excludes:NativeValue,why:NativeValue,risks:NativeValue,refs:[NativeRef],targets?:[BeadID]}`. The first four must be truthy under native6fe's JSON/Python semantics; refs has1..32 items; present targets has1..32 unique IDs. These are exactly queue6fe's ASK_FIELDS and optional-target rule. In particular **purpose is not an accepted native6fe ask key**: product076 Readout's optional purpose does not extend that queue schema. A later queue extension needs an explicitly pinned compatibility revision, not an unseen extra field. `Candidate={title:Title,description:Body,ask:NativeAsk}`. This preserves whole native values, not a rendered summary, and does not replace native lint/digest or later action validation.

`ResolvedIdentity` is the variant-correlated SHA, ordered SHA pair string, or Digest specified in the table. `ResolvedRef={ref:NativeRef,resolved_id:ResolvedIdentity|null}`. `ContextItem={source_id:ID,kind:"task"|"doc"|"diff"|"excerpt",content_id:Digest,text:Text,ref:NativeRef,resolved_id:ResolvedIdentity}` has **all six keys**. `content_id` hashes exactly text UTF-8; resolved_id has the corresponding variant's type from the table. task requires bead ref, doc requires file/commit ref, diff requires range ref, excerpt permits any variant. Source IDs are unique. An excerpt hash is not proof a whole source was read; caller supplies already resolved evidence. No read, network fetch, or native authority is created by this claim.

`Origin={event_ref:ID,creator_ref:ID,session_ref:ID|null}` is common to intake/sufficiency. These are opaque references to upstream authenticated provenance; accepting an ID does not authenticate a sender or create a session. Permission subject is `{task_id:BeadID,session_ref:ID,tool_name:ID}`. `PolicyRevision={id:ID,sha256:Digest}` refers to the host policy snapshot supplied by the eventual policy owner; Plan7A neither loads nor trusts a model-selected policy. It is required on all requests, and changing it invalidates the request binding.

**Request envelope.** Exact common keys are `{format:1,kind:"intake"|"sufficiency"|"permission",request_id:ID,workstream_id:ID,subject_id:ID,revision:PosInt,policy_revision:PolicyRevision,context:[ContextItem],snapshot_sha256:Digest}` plus exactly the kind-specific fields in §§4,5,7. snapshot_sha256 hashes canonical UTF-8 JSON (sorted keys, separators comma/colon, ensure_ascii=false, no Unicode normalization) of this whole request except itself. This is a gatekeeper input identity, not the native context_digest, action key, launch receipt, or Marmot delivery receipt. Common context may be empty; <=32 items.

**Result envelope.** Exact keys are `{format:1,kind:<same kind>,request_id:ID,revision:PosInt,snapshot_sha256:Digest,outcome:<kind-specific tagged union>}`. outcome uses discriminator `status`, independently of kind. All five echoed identity/version fields must match the validated request. Native approval/task identity is bound by its inclusion in the request hash; there is no additional undeclared echoed approval_id. Every kind has the same exact failure outcome `{status:"unavailable",reason_code:"timeout"|"unavailable"|"bad_output"|"unsafe"|"oversize"}`; no arbitrary diagnostic prose or other fields occur in that variant. A future adapter normalizes exceptions into this envelope only when there is a valid request to bind.

**Local validation result.** `Check[T]` is exactly `{status:"valid",value:T}` or `{status:"invalid",stage:"request"|"result",code:"schema"|"unsafe"|"oversize"|"binding"|"invariant",field:ID|null}`. There are no separate `Invalid`, `UnsafeInput`, `UnsafeResult`, or unwrapped scalar result types. Unsafe content uses code unsafe at its actual stage. Missing required lint is schema-invalid; an explicit failed lint is a valid request variant, handled by §5 precheck. Invalid requests project to `HoldInvalidInput` without echoing unsafe content; only a **valid safe request** with an unavailable or invalid result can project to raw-unreviewed intake. Sufficiency errors project HoldUnavailable, permission errors EscalateProposal. Every capitalized projection name in §§4–7 is a local enum value only (CreateMinorProposal, ConfirmMaterialProposal, RawUnreviewedProposal, HoldInvalidInput, SufficientProposal, EnrichmentProposal, NeedsGrooming, HoldUnavailable, ReturnToOrigin, CannotApproveNotice, AllowProposal, DenyProposal, EscalateProposal). Projection enums carry no hidden fields and create no native metadata. The separate pure `enriched_candidate(request,verified_result)->Check[Candidate]` returns the exact §5 candidate transformation; no other builder is implied. These enums are not wire judgments or native approval decisions.

**Bounds.** Entire request <=128KiB UTF-8; result <=32KiB; <=32 context items/open tasks, <=16 acceptance criteria/dependency edges/gaps, <=8 additions. Original/description use Body, other prose Text/Title; NativeValue retains its separate bounds. Exceeding any bound refuses the whole value, without truncation/sampling. A caller can prepare a distinct bounded snapshot, explicitly marking incomplete intake context; it cannot silently retry less context as equivalent input.

Three distinct async Python protocol methods define eventual adapters: `classify(IntakeRequest)->IntakeJudgment`, `assess(SufficiencyRequest)->SufficiencyJudgment`, `permission(PermissionRequest)->PermissionJudgment`. Each Judgment is its kind's result envelope. Fakes implement these interfaces for offline contract tests; no external adapter or scheduler is implemented. Validate before any future egress and never forward secrets, credential paths, private locators, raw transcripts, or authentication identities under the excuse of summarization. Prompt injection remains untrusted data. Models' advisory results confer no native authority.

## 4. Intake classification and rewrite

`IntakeRequest` adds exactly `original:Body`, `origin:Origin`, `target:{workstream_id:ID,repo_id:ID}`, `context_complete:bool`, and `open_tasks:[{id:BeadID,title:Title,description_digest:Digest}]`. Target workstream_id must equal the envelope workstream_id; open-task IDs are unique. Host-validated opaque target IDs are provided by the eventual router, not chosen by a model. An empty original refuses. The open-task list is explicitly bounded snapshot context; lack of an entry does not prove that task absent globally.

`IntakeJudgment.outcome` is exactly one of:

- `{status:"proposed",materiality:"minor"|"material",title:Title,description:Body,acceptance:[Text],dependencies:[{task_id:BeadID,type:"blocks"}],change_flags:ChangeFlags,reason:Text}`; acceptance is nonempty, dependencies may be empty.
- The common unavailable outcome from §3.

`ChangeFlags` is an object with exactly these six boolean keys: `target_changed`, `requirements_changed`, `question_to_action`, `destructive`, `outward_facing`, `context_incomplete`. Any true flag forces `material`; context_complete=false requires context_incomplete=true. Proposed targets cannot differ from the request: a requested target change is represented in the reason and `target_changed`, for later human confirmation, never an effective target override. Duplicate/self/unknown dependency IDs refuse; a future native adapter still must validate full-graph cycles and eligibility. No arbitrary edge type, task label, agent identity, approval ID, policy change, or executable action belongs in the result.

Model-declared materiality is advisory: an empty/incomplete task snapshot cannot establish a conflict-free dependency plan. The pure projection `intake_disposition(request,verified_result)` returns `CreateMinorProposal`, `ConfirmMaterialProposal`, or `RawUnreviewedProposal`; it creates no bead. Material means the ADR §5.1 list, with uncertainty treated as material. Typos/reference clarification alone can be minor. Deterministic checks enforce the declared flags, but cannot prove that an LLM correctly preserved intent; that is accepted ordinary advisory-model risk. Fixture review specifically covers missed semantic changes. The eventual router retains original and rewrite together for operator correction.

A valid material proposal maps later to `kind:confirm` without `agent:` routing; dispatch waits for authenticated confirmation/correction. For a valid safe request, a verified unavailable result or invalid result maps to raw-text `unreviewed` intake per ADR §5.1, with an explicit diagnostic; it does not fabricate a minor rewrite. Full routing must still apply native task/design/policy gates before any raw or confirmed task can run. Plan7A does not implement that route or change the raw fallback into authority.

## 5. Sufficiency is a separate gate

`SufficiencyRequest` adds exactly `approval_id:BeadID`, `native_context_digest:Digest|null`, `lint:Lint`, `candidate:Candidate`, `resolved_refs:[ResolvedRef]`, `groom_failures:0|1|2` (integer, not bool), `origin:Origin`, and `enrichment_used:bool`. subject_id must equal approval_id. resolved_refs is1..32 entries in exact candidate.ask.refs order, each row.ref equal to that native ref. The authoritative whole candidate comes from the future native adapter, never reconstructed from Readout lines. A caller's assertion of a digest or lint cannot grant native authority.

`Lint` is exactly `{status:"passed",gaps:[]}`, `{status:"failed",gaps:[Text]}` (nonempty), or `{status:"unavailable",reason_code:<common failure enum>}`. Passed requires a nonnull native_context_digest and every resolved_id nonnull; failed allows null identity/digest for confirmed missing or malformed evidence, with genuine gaps; unavailable allows nulls for infrastructure uncertainty without inventing absence. The pure precheck consumes this explicit union before calling assess: failed => NeedsGrooming, unavailable => HoldUnavailable, passed => eligible for assessment only after the supplying native adapter's real checks. Missing lint or contradictory union values are local schema/invariant errors, never model-eligible.

`SufficiencyJudgment.outcome` is exactly one of:

- `{status:"sufficient",reason:Text,additions:[],gaps:[]}`.
- `{status:"enrich",additions:[{source_id:ID,start:Offset,end:Offset,quote:Text}],reason:Text,gaps:[]}`; additions nonempty, unique (source_id,start,end) tuples.
- `{status:"groom",gaps:[{field:"what"|"effect"|"why"|"context"|"refs",detail:Text}],reason:Text,additions:[]}`; gaps nonempty.
- The common unavailable outcome from §3.

The semantic question is ADR §5.9: can an operator decide from this card alone without guessing? Required what/effect/excludes/why/context/risks/alternatives and immutable evidence must remain intelligible together. A link's existence does not substitute for decision context. An LLM cannot approve missing typed action fields, undisclosed effects, or unpinned refs. Native `ask` keys remain exactly the queue's current schema; no new `gatekeeper_*` key is smuggled into native metadata.ask.

For `enrich`, offsets are Unicode code-point offsets into one supplied context item's text, `0<=start<end<=len(text)`, `quote == text[start:end]`. No ellipsis or paraphrase is accepted as an exact quote. The pure enrichment proposal preserves title and every NativeAsk field byte-for-byte; it appends only `\n\nGatekeeper-added context (source <source_id>; ask reference <N>):\n<quote>` to description, in additions order. N is the 1-based position of the byte-equivalent ContextItem.ref in candidate.ask.refs; no match => NeedsGrooming. Identical duplicate refs use their first position. This is an explicit marker referring to the root ask refs, not a fabricated approve-bead document number or URL. This deliberately limits automatic enrichment to already supplied pinned evidence. Unsupported assertions or any required change to effect/excludes/refs return `NeedsGrooming`, not a broader rewrite. Source mapping and quote offsets are retained in private proposed evidence, and the visible description uses the exact marker above; the existing native card shows the unchanged pinned refs themselves. Whole-content safety/size checks still apply.

Enrichment is **not sufficient**. A later consumer must atomically replace the whole candidate object, recompute native lint/resolution/digest and card, and obtain a fresh sufficient judgment over that exact new candidate. At most one enrichment cycle per submission revision; enrichment_used=true plus an enrich result yields `NeedsGrooming`. This flag is supplied by the eventual durable consumer, never trusted as a model-controlled reset. An old sufficient judgment is invalid for a new digest, source snapshot, policy revision, or changed card content. No supplement can be approved off-card or behind a free-text digest marker.

The pure projection returns `SufficientProposal`, `EnrichmentProposal`, `NeedsGrooming`, or `HoldUnavailable`. None posts a card or grants approval. A passing semantic proposal does not bypass native `postable`, group authentication, redaction, whole-card size, action validation, or human approval. Future posting must fresh-check both native state and the exact judgment binding after any await, outside then inside the short existing commit boundary as appropriate to its final design; Plan7A claims no implemented atomic integration.

## 6. Grooming, unavailable results, and terminal recovery

Pure `groom_disposition(groom_failures)` maps 0/1 to `ReturnToOrigin`, 2 to `CannotApproveNotice`; it does not mutate counters. A future consumer durably increments failures only after a genuine returned revision is re-evaluated and still fails, not on retries, duplicate events, model outages, or delivery uncertainty. Revisions are identified by native digest and source revision. A stale reply cannot consume a newer revision's budget. Grooming steers the **originating parked session** or the recorded creator, never a replacement agent invented for this purpose; it also counts within the existing three-nudge/no-progress budget when actually delivered as steering.

At two failed grooms the ADR requires a control-group cannot-approve-as-written notice listing gaps, deny as the default, and no approval buttons. This means **recommend deny**, not automatically record denial on silence. The operator can explicitly deny or groom; there is no approve-as-written path. Missing origin, dead session, exhausted nudge budget, or unknown delivery holds for an authenticated Marmot question. The eventual consumer retains the pending ask and origin evidence, releases unrelated work, and never fabricates a resumed session or resolved notice. No counter is reset by restart, a fresh model request, or task reassignment.

Timeout, invalid/unsafe/oversize input or output, endpoint error, stale native digest, and unreadable policy all remain typed failures. For sufficiency the result holds or returns correctable input gaps to origin; no outage becomes a human approval request for the incomplete ask. A separate content-free operational notice/question may explain the hold through the authorized control route. Recovery is a fresh native read and explicit resubmission of a corrected revision or restoration of the same dependency, with prior evidence retained; no automatic looping retry, self-unhold, alternate writer, or permission-classifier workaround.

Before the release shipping BOTH wsd and the semantic gatekeeper, any eventual relay judgment is **shadow only**. It cannot block or authorize historical valid phone approvals. That release must enforce passing sufficiency for every relayed approval, with no interval where both ship without enforcement. Plan7A neither ships a gatekeeper nor ends the interim exception. Activating either shadow or enforcement requires its own reviewed integration, real predecessor completion, and deployment authority.

## 7. Permission port: no decision/approval conflation

`PermissionRequest` adds exactly `subject:{task_id:BeadID,session_ref:ID,tool_name:ID}`, `intent:Text`, `tier:"grey"`, `action_ref:{kind:"fixture",id:ID}|null`, `budget_ms:60000`, and `elapsed_ms:0..2147483647` (integers, not bool). subject_id must equal subject.task_id. action_ref is **only an inert fixture identity**, not a native action ID/payload, opaque provider object, or permission to dispatch. There is no native action payload field in Plan7A. Real Plan5 typed action binding is a later integration prerequisite; this grammar cannot silently carry an executable payload.

`PermissionJudgment.outcome` is exactly `{status:"allow",reason:Text}`, `{status:"deny",reason:Text}`, `{status:"escalate",reason:Text}`, or the common unavailable outcome from §3. There is no scalar string judgment or alternate exception shape. A result of another kind cannot be decoded as PermissionJudgment. `permission_disposition` maps local invalid input/result or unavailable to EscalateProposal and any elapsed_ms>=budget_ms to EscalateProposal before considering allow/deny. Otherwise valid allow maps to AllowProposal, deny to DenyProposal, and escalate to EscalateProposal. The future integration must enforce the ADR's **total 60-second** grey-zone budget across queueing/model/validation, with no retry reset. Plan7A performs no wait or scheduling; elapsed_ms is an injected fixture value, not a production clock attestation.

Deterministic hard-deny and operator-only floors are evaluated **before** this port and cannot be downgraded by `allow`. No existing action, policy, secret-access, deployment, or message-send authority changes. `allow` means only an advisory grey-zone result under the unchanged sandbox/native gates; an action still requires its own authorized path and wsd-act validation. Permission failure escalates under §5.3; sufficiency failure cannot bypass §5.9 by being mislabeled an escalation. The later Plan5 integration owns durable audit of tier/decider/reason, action state, idempotency, decision write/readback, and unknown execution reconciliation. Plan7A has no approval metadata writer or executor credentials.
