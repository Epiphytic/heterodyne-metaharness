## 3. Closed grammar, preparation, privacy and egress

Later pure implementation comprises `gatekeeper/contracts.py`, `validate.py`, `project.py`, named offline fixtures, and the small shared redaction extraction below. Python 3.12/msgspec already exist. No dependency, endpoint, model call, transport or runtime writer is added. Every object has exactly its listed keys; only `?` keys may be omitted. Reject unknown/duplicate keys, invalid UTF-8/surrogates, bool-as-int, nonfinite numbers, floats and trailing bytes. Omitted and null differ; no normalization or executable objects occur.

**Canonical identities.** `J(x)` is UTF-8 JSON with lexicographically sorted object keys, separators comma/colon, ensure_ascii=false, no trailing newline or Unicode normalization; only the finite scalar types below occur. Every derived digest is SHA-256 of exactly J(x), unless explicitly defined as a raw-byte or Git-object hash. `ID` is 1..128 ASCII letters/digits or `_:.+-`; `SHA` is 40 lowercase hex; `Digest` is 64 lowercase hex; `PosInt` is 1..2147483647; `Offset` is 0..2147483647, integers excluding bool. `BeadID` is the existing admind read profile fullmatch `[a-z0-9]{1,16}-[a-z0-9.]{1,32}`. **`TargetID` is separate**, queue6fe BEAD_ID fullmatch `[a-z][a-z0-9-]{0,31}-[0-9a-z]{5}`; native targets require it. Existing short/dotted IDs can identify/read beads but cannot be native ask.targets. Neither grammar claims global existence.

`Locator` is private nonempty UTF-8 <=4KiB with no C0/C1 controls. `Text` is nonblank UTF-8 <=4KiB; `Title` also <=200 Unicode code points; `Body` <=16KiB. These three are PublicText: unchanged by the explicit pinned redaction context, no C0/C1 except newline/tab. Full digests belong to typed identity fields, not arbitrary prose. `PrivacyContext={format:1,login_dirs:[Locator],rule_revision:SHA,sha256:Digest}` has <=16 unique directories each <=512bytes, in sorted lexical order. rule_revision is the **product commit**, not a blob, containing both pinned redact.py and secret_scan.py; require their manifest blob/hash identities. sha256=SHA256(J(the other three fields)). No environment reads or process-global configuration mutation is permitted.

**Shared redaction seam, explicitly in scope.** Product076 redact.py currently compiles login directories into `_login_dirs`. Later implementation extracts its existing directory compiler and `_pass`/MAX_PASSES/UNSTABLE loop into shared internal functions taking an explicit compiled directory pattern. New `redact_with_dirs(text,paths)` uses that same compiler/kernel and no globals; existing `set_login_dirs`, `redact`, continuation/spans and all existing callers keep their default behavior and installed API. Do not copy patterns/loops into gatekeeper or install a second policy. Existing secret_scan.py remains the pattern source. Required byte-for-byte fixture comparison against pinned076 covers default/global callers, continuation/spans, ordering, boundary matching, PEM, controls, hex adjacency, idempotence and unstable fallback, plus interleaved explicit contexts proving no global mutation. This narrow reusable extraction is part of pure scope; changing installed default privacy behavior is not.

`NativeValue` is null, bool, signed64-bit integer, Text, list or object of distinct ID keys to NativeValue; <=8 container levels,512 total nodes,32 items/members per container. Every string passes PublicText. Native truthiness permits more: a valid native float, large/unsafe text or unused ref key is **profile-ineligible**, not native-invalid.

| NativeRef exact variant | Native resolved identity |
|---|---|
| `{kind:"file",id:SHA,repo:Locator,path:Locator}` | Git blob/tree SHA from native resolver |
| `{kind:"commit",id:SHA,repo:Locator}` | same commit SHA |
| `{kind:"range",id:SHA+".."+SHA,repo:Locator}` | same ordered SHA pair string |
| `{kind:"bead",id:BeadID}` | linked native-ask Digest |

Queue6fe `_resolve` allows some unused keys; this deliberate strict subset rejects them before judgment. No repo/path fetch, resolution or digest replacement occurs in the pure component. Actual object existence, linked cycles/depth and infrastructure read failures remain native-adapter responsibilities. `NativeAsk={effect:NativeValue,excludes:NativeValue,why:NativeValue,risks:NativeValue,refs:[NativeRef],targets?:[TargetID]}`: first four truthy by native Python/JSON semantics, refs1..32, present targets1..32 unique. ASK_FIELDS/REF_FIELDS/REF_KINDS and target_ids from queue6fe are authoritative. Native has no purpose key. `Candidate={title:Title,description:Body,ask:NativeAsk}` preserves complete admitted values; native lint/digest still apply.

`ResolvedIdentity` is the correlated type above. `ResolvedRef={ref:NativeRef,resolved_id:ResolvedIdentity|null}`. `ContextItem={source_id:ID,kind:"task"|"doc"|"diff"|"excerpt",content_id:Digest,text:Text,ref:NativeRef,resolved_id:ResolvedIdentity}`. Source IDs unique; content_id=SHA256(exact text UTF-8). task requires bead ref, doc file/commit, diff range, excerpt any. **Sufficiency context is narrower:** only doc/excerpt with a file ref; text is the entire UTF-8 blob, no replacement/normalization. SHA1(`blob <byte length>\0` + exact bytes) must equal resolved_id and the matching resolved_refs identity. Reject tree/partial-excerpt proof and mismatched candidate refs as correctable origin gaps before invocation. Commit/range/bead native refs remain valid but cannot supply automatic semantic quotes. The <=4KiB whole-blob/PublicText restriction deliberately excludes real large ADRs/designs, CRLF documents, manifests with64hex and secret-bearing sources. They require an origin-authored safe card or grooming; **automatic context/enrichment is unavailable**, not sufficient by default. No bounded excerpt proof or silent truncation is invented here. The human ask must disclose this concrete limitation.

`Origin={event_ref:ID,creator_ref:ID,session_ref:ID|null}` and `PolicyRevision={id:ID,sha256:Digest}` are private host facts, not authentication by accepting strings. Request `revision` is a positive monotonic snapshot revision allocated by the future durable owner for this subject, changed whenever any judged input changes; no retry reset. It is distinct from sufficiency external submission_revision. Exact common request keys are `{format:1,kind:"intake"|"sufficiency"|"permission",request_id:ID,workstream_id:ID,subject_id:ID,revision:PosInt,policy_revision:PolicyRevision,privacy_sha256:Digest,context:[ContextItem],public_bindings:PublicBindings,snapshot_sha256:Digest}` plus the fields in §§4,5,7. snapshot_sha256=SHA256(J(whole request except itself)); privacy_sha256 must match verified PrivacyContext. Native digest/action/session/delivery namespaces remain separate. All list ordering is significant. Empty context is allowed, <=32 items.

**Typed local preparation, distinct from model output.** `FieldPath` is a JSON Pointer UTF-8 string <=4096bytes: empty means whole input, otherwise slash-separated escaped key/index segments; `~`→`~0`, `/`→`~1`; arrays use canonical decimal indexes, objects their complete actual keys including `:.+-`/uppercase. It addresses the full bounded tree, no8-segment limit. `Gap={code:"schema"|"profile"|"unsafe"|"oversize"|"binding"|"invariant"|"native_lint"|"semantic",field:FieldPath,detail:Text|null}`. Origin-profile/native diagnostic gaps use detail=null; safe fixed labels are derived locally, never rejected prose. Semantic detail is safe model Text. More than64 gaps becomes one content-free whole-input oversize gap, with full original diagnostics retained privately by the future origin owner.

`HostCode="timeout"|"unavailable"|"unreadable_policy"|"stale_digest"|"egress_unsafe"|"egress_oversize"`; these codes **cannot be selected by a model**. `Prepared[T]={status:"ready",value:T}|{status:"origin_gap",gaps:[Gap]}|{status:"host_failed",reason_code:HostCode}|{status:"invalid_host",field:FieldPath}`. Before constructing T, pure preparation classifies authenticated-origin shape/privacy/profile failures, context/ref mismatch and bounded native-lint diagnostics as origin_gap, including native-valid asks outside the profile. Host configuration absent/unreadable/outside permission1..60000ms is host_failed/unreadable_policy; native readback digest mismatch is host_failed/stale_digest. Internal envelope/host metadata corruption is invalid_host. This is proposed caller classification over supplied facts, not a native reader or provenance attestation. Required private original retention and safe origin route remain future integration gates. Shadow profile diagnostics do not change current valid relay approvals.

`Check[T]={status:"valid",value:T}|{status:"invalid",stage:"request"|"result",code:"schema"|"unsafe"|"oversize"|"binding"|"invariant",field:FieldPath}` is a content-free validator result only, not exception provenance. Host request checks are consumed into Prepared before invocation. `Attempt[J]={status:"completed",result:Check[J]}|{status:"host_failed",reason_code:HostCode}`; only the trusted future host adapter can create host_failed. No exception is normalized into a model result. Models return exact `{format:1,kind:<same>,request_id:ID,revision:PosInt,snapshot_sha256:Digest,outcome:<kind union>}`. Echo all common identities exactly. The sole common model failure is `{status:"unavailable"}` with **no reason_code or prose**. Invalid model data stays completed/invalid; host config/digest faults remain host failures even if a model attempts to assert them.

All Gap lists in origin_gap and grooming projections are nonempty, <=64; an Attempt.completed invalid Check must have stage=result. Prepared consumes request-stage checks. All three disposition functions take exactly `(prepared:Prepared[Request],attempt:Attempt[Judgment]|null)`. For ready request, null is legal only for deterministic prechecks (failed/unavailable lint or elapsed deadline); an eligible request with null holds/escalates rather than claiming success. Nonready inputs must have null Attempt, otherwise reject as invalid_host. Output is a closed `Projection` union: `{status:"HoldInvalidInput"|"NeedsGrooming",gaps:[Gap]}`; `{status:"HoldUnavailable"|"EscalateProposal",reason_code:HostCode|"invalid_host"|"bad_output"|"model_unavailable"|"model_escalate"|"deadline"}`; or `{status:"CreateMinorProposal"|"ConfirmMaterialProposal"|"RawUnreviewedProposal"|"RawConfirmProposal"|"SufficientProposal"|"EnrichmentProposal"|"ReturnToOrigin"|"CannotApproveNotice"|"AllowProposal"|"DenyProposal"}`. Names are proposals, never native metadata/authority. origin_gap maps intake→HoldInvalidInput and sufficiency→NeedsGrooming with the exact safe gaps, permission→EscalateProposal/unavailable. These reason codes are host-assigned, not selected from model prose. invalid_host maps respective HoldInvalidInput (one schema gap), HoldUnavailable/invalid_host, EscalateProposal/invalid_host. Other failures follow §§4–7. `enriched_candidate(ready_request,valid_judgment)` returns `{status:"candidate",candidate:Candidate}|{status:"groom",gaps:[Gap]}`; no posting builder is implied.

**Bounds and enrichment output.** Whole request<=128KiB; decoded model response<=32KiB with strict scalar/list/depth bounds; <=32 contexts/open tasks,16 acceptance criteria/dependency edges,64 gaps,8 additions. An enrich quote is Text<=1KiB (not4KiB), so at most8KiB of quotes plus bounded envelope fits32KiB; typed limit violations, including ninth addition/1KiB quote overflow, are a content-free oversize Gap and NeedsGrooming for sufficiency, not outage. Raw response>32KiB is also completed invalid/oversize and maps to NeedsGrooming, without parsing/truncating. Aggregate appended marker+quote limit8KiB and full description16KiB remain independent atomic grooming checks. Binding/schema/unsafe output failures still hold; no malformed output becomes sufficient.

**Meaningful privacy-safe egress, not opaque aliases alone.** `Alias` is a decimal string1..32 without leading zeros. `RepoView={label:Text}` is a meaningful operator-recognizable public repository label; `CwdView={repo:RepoView,path:Text}` is its actual public repo-relative cwd (dot or normalized slash-separated components, no absolute path, empty/./../ components or controls). `RefView` is `{alias:Alias,kind:"file",id:SHA,repo:RepoView,path:Text}`, `{alias,kind:"commit",id:SHA,repo:RepoView}`, `{alias,kind:"range",id:SHA+".."+SHA,repo:RepoView}`, or `{alias,kind:"bead",id:BeadID}`. File paths are exact native repository-relative paths and PublicText, not host repo locators; unsupported/private paths refuse egress. SHA/IDs are typed evidence identities, no raw SHA256 prose. `PublicBindings={target:{workstream:Text,repo:RepoView}|null,ref_repositories:[{ref_index:Offset,repo:RepoView}],cwd:CwdView|null}` is supplied by the eventual trusted owner from authenticated repository/workstream/cwd registry data; its mapping is frozen into request identity. For sufficiency only, every candidate file/commit/range ref has exactly one matching zero-based ref_index row; no extras/duplicates. Intake/permission ref_repositories=[]; their ContextItem refs are not projected as card refs. Intake requires target only, permission cwd only; sufficiency neither. Host resolves private repo and cwd identity against this admitted mapping before calling the pure component. This component checks complete structural mapping, never pretends labels authenticate physical paths. Unavailable/ambiguous mapping is a host failure, no alternate-summary call.

Pure `egress(ready_request,PrivacyContext)` returns Check[DTO] with common `{format,kind,request_id,revision,snapshot_sha256}` plus intake `{original,target:{workstream:Text,repo:RepoView},context_complete,open_tasks:[{alias,title}],context:[{alias,text}]}`, sufficiency `{card:{title,description,effect,excludes,why,risks},refs:[RefView],targets:[TargetID],context:[{alias,text}]}`, or permission `{tool_name,intent,cwd:CwdView,input:NativeValue,invocation_sha256:Digest}`. Targets is the exact native list, or[] if omitted; whole request still binds omission. Cwd/input represent the exact call, not intent alone. No private repo locator, source_id, Origin, session, login dirs or raw policy enters egress. Newline/secret rules apply to all public text and typed NativeValue input. Missing meaningful safe projection becomes host_failed/egress_unsafe or egress_oversize before call, never a degraded model judgment. Intake target labels permit judging target_changed; exact ref identities/public paths/native targets permit sufficiency judgment. Future real adapters must prove physical equivalence/privacy and cannot silently redact argument bytes.

Three proposed async protocols are `classify(IntakeEgress)->IntakeModelJudgment`, `assess(SufficiencyEgress)->SufficiencyModelJudgment`, `permission(PermissionEgress)->PermissionJudgment`, not installed APIs. ModelJudgment uses the exact result envelope, with intake dependency task_id and sufficiency addition source_id replaced by Alias. Host normalizer resolves those two fields through frozen ordered maps only, rejects unknown aliases, validates again; no repair elsewhere. Private source IDs never appear in visible markers or model DTOs. Models' advisory results confer no native authority. Fakes suffice for this pure component; actual provider authentication, subprocess/error/deadline handling and sources remain later reviewed integration obligations.

## 4. Intake classification and rewrite

`IntakeRequest` adds exactly `original:Body`, `origin:Origin`, `target:{workstream_id:ID,repo_id:ID}`, `context_complete:bool`, and `open_tasks:[{id:BeadID,title:Title,description_digest:Digest}]`. Target workstream_id must equal the envelope workstream_id; open-task IDs are unique. Host-validated opaque target IDs are provided by the eventual router, not chosen by a model. An empty original refuses. subject_id is a pre-native submission ID allocated by the future ingress owner, not an as-yet nonexistent bead. description_digest is SHA-256 of exact UTF-8 description bytes with no normalization; the description itself is not implied available. All dependency targets must come from open_tasks, so none can target this new submission. Existing-task editing is outside this intake contract. The open-task list is explicitly bounded snapshot context; lack of an entry does not prove that task absent globally.

`IntakeJudgment.outcome` is exactly one of:

- `{status:"proposed",materiality:"minor"|"material",title:Title,description:Body,acceptance:[Text],dependencies:[{task_id:BeadID,type:"blocks"}],change_flags:ChangeFlags,reason:Text}`; acceptance is nonempty, dependencies may be empty.
- The common unavailable outcome from §3.

`ChangeFlags` is an object with exactly these six boolean keys: `target_changed`, `requirements_changed`, `question_to_action`, `destructive`, `outward_facing`, `context_incomplete`. Effective materiality is computed by the host: material if any flag is true, context_complete=false, or the model says material; otherwise minor. A false context_incomplete flag cannot override host context_complete=false. Contradictory declared flags do not create an invalid-result downgrade path. Proposed targets cannot differ from the request: a requested target change is represented in the reason and `target_changed`, for later human confirmation, never an effective target override. Duplicate/self/unknown dependency IDs refuse; a future native adapter still must validate full-graph cycles and eligibility. No arbitrary edge type, task label, agent identity, approval ID, policy change, or executable action belongs in the result.

Model-declared materiality is advisory: an empty/incomplete task snapshot cannot establish a conflict-free dependency plan. The pure projection `intake_disposition(prepared,attempt)` returns `HoldInvalidInput`, `CreateMinorProposal`, `ConfirmMaterialProposal`, `RawUnreviewedProposal`, `RawConfirmProposal` or `HoldUnavailable`; it creates no bead. Material means the ADR §5.1 list, with uncertainty treated as material. Typos/reference clarification alone can be minor. Deterministic checks enforce the declared flags, but cannot prove that an LLM correctly preserved intent; that is accepted ordinary advisory-model risk. Fixture review specifically covers missed semantic changes. The eventual router retains original and rewrite together for operator correction.

A valid material proposal maps later to `kind:confirm` without `agent:` routing; dispatch waits for authenticated confirmation/correction. For a valid safe request, only a host adapter failure explicitly categorized timeout/unavailable maps to raw-text `unreviewed` intake per ADR §5.1, with an explicit diagnostic. Model-originated unavailable, malformed/unsafe/oversize output, binding failure map to RawConfirmProposal: original safe text retained as unreviewed, mandatory confirmation before dispatch, never unattended minor fallback. Attempt provenance is exactly §3. Host timeout/unavailable alone permits RawUnreviewedProposal; other host failures hold with safe origin correction where applicable, and never become model-origin failures. Model unavailable or invalid output gives RawConfirmProposal only for a ready safe request. This changed fallback cannot be enforced under a27 alone: a genuine ADR amendment, actual native approval and later integration/deployment are mandatory; it does not fabricate a minor rewrite. Full routing must still apply native task/design/policy gates before any raw or confirmed task can run. Plan7A does not implement that route or change the raw fallback into authority.

## 5. Sufficiency is a separate gate

`SufficiencyRequest` adds exactly `approval_id:BeadID`, `native_context_digest:Digest|null`, `lint:Lint`, `candidate:Candidate`, `resolved_refs:[ResolvedRef]`, `origin:Origin`, `submission_id:ID`, `submission_revision:PosInt`, `base_candidate_sha256:Digest`, `enrichment:{status:"unused"}|{status:"used",base_description:Body,additions:[<the exact addition objects below>]}`. subject_id must equal approval_id. resolved_refs is 1..32 entries in exact candidate.ask.refs order, each row.ref equal to that native ref. The authoritative whole candidate comes from the future native adapter, never reconstructed from Readout lines. A caller's assertion of a digest or lint cannot grant native authority.

`Lint` is exactly `{status:"passed",gaps:[]}`, `{status:"failed",gaps:[Gap]}` (nonempty native_lint codes/detail=null), or `{status:"unavailable",reason_code:HostCode}`. Future native adapter retains the full arbitrary native diagnostics privately with a discoverable protected evidence locator, and produces safe content-free bounded gaps via the pure sanitizer; it never puts repr(native values) into PublicText. Overflow folds to one whole-input native_lint gap while the private original remains complete. A genuine failed lint therefore remains a valid failed request, not an unsafe/oversize request. Passed requires a nonnull native_context_digest and every resolved_id nonnull; failed allows null identity/digest for confirmed missing or malformed evidence, with genuine gaps; unavailable allows nulls for infrastructure uncertainty without inventing absence. The pure precheck consumes this explicit union before calling assess: failed => NeedsGrooming, unavailable => HoldUnavailable, passed => eligible for assessment only after the supplying native adapter's real checks. Missing lint or contradictory union values are local schema/invariant errors, never model-eligible.

`SufficiencyJudgment.outcome` is exactly one of:

- `{status:"sufficient",reason:Text,additions:[],gaps:[]}`.
- `{status:"enrich",additions:[{source_id:ID,start:Offset,end:Offset,quote:Text}],reason:Text,gaps:[]}`; quote additionally <=1KiB; additions nonempty, unique (source_id,start,end) tuples.
- `{status:"groom",gaps:[{field:"what"|"effect"|"excludes"|"why"|"context"|"risks"|"alternatives"|"refs",detail:Text}],reason:Text,additions:[]}`; gaps nonempty.
- The common unavailable outcome from §3.

The semantic question is ADR §5.9: can an operator decide from this card alone without guessing? Required what/effect/excludes/why/context/risks/alternatives and immutable evidence must remain intelligible together. A link's existence does not substitute for decision context. An LLM cannot approve missing typed action fields, undisclosed effects, or unpinned refs. Native `ask` keys remain exactly the queue's current schema; no new `gatekeeper_*` key is smuggled into native metadata.ask.

For `enrich`, offsets are Unicode code-point offsets into one supplied context item's text, `0<=start<end<=len(text)`, `quote == text[start:end]`. No ellipsis or paraphrase is accepted as an exact quote. The pure enrichment proposal preserves title and every NativeAsk field byte-for-byte; it appends only `\n\nGatekeeper-added context (source alias <A>; ask reference <N>):\n<quote>` to description, in additions order. This literal marker prefix is reserved: unused input descriptions containing `Gatekeeper-added context (` anywhere are invalid. Used input must be exactly reconstructed from marker-free base_description and the retained validated additions; arbitrary preexisting markers or edits refuse. A is the public decimal context alias from the frozen ordered map, never private source_id. On reassessment the retained private additions rederive the same alias map; the public marker contains no private locator. N is the 1-based position of the byte-equivalent ContextItem.ref in candidate.ask.refs; an unmatched context has already been a correctable origin gap before model invocation, so this transform has no separate unreachable mismatch branch. Identical duplicate refs use their first position. The marker names a root-ask ordinal only. It is never an approve-bead `--doc N` argument: native Resolution.docs can deduplicate or expand linked evidence. Any later document command needs a fresh validated native docs mapping, not this number. This deliberately limits automatic enrichment to already supplied pinned evidence. Unsupported assertions or any required change to effect/excludes/refs return `NeedsGrooming`, not a broader rewrite. Source mapping and quote offsets are retained in private proposed evidence; source_id remains private, and the visible description uses the exact marker above; the existing native card shows the unchanged pinned refs themselves. The complete transformed candidate must pass all original privacy/profile/request bounds and description <=16 KiB. The sum of appended marker+quote bytes is at most 8 KiB, in addition to <=8 additions; aggregate overflow returns NeedsGrooming atomically, without a partial candidate.

Enrichment is **not sufficient**. A later consumer must atomically replace the whole candidate object, recompute native lint/resolution/digest and card, and obtain a fresh sufficient judgment over that exact new candidate. At most one enrichment cycle per (submission_id, submission_revision). This identity is allocated by the future durable consumer from an external submitter revision; native digest changes caused by enrichment do not change it. base_candidate_sha256=SHA256(J(original Candidate)) covers the exact original candidate, unchanged across the enrichment/reassessment pair: unused must hash candidate directly; used must hash the reconstructed candidate with base_description and unchanged title/ask. Used additions must pass the same quote/source checks; enrichment replay metadata is a proposed durable-consumer contract, never a model claim. A used enrichment plus another enrich result yields NeedsGrooming. The consumer must persist this transition; a fresh model request, reassessment digest, or restart cannot reset it. A genuine external corrected submission may advance submission_revision while preserving the saturated grooming count. An old sufficient judgment is invalid for a new digest, source snapshot, policy revision, or changed card content. No supplement can be approved off-card or behind a free-text digest marker.

Model groom gaps map to code=semantic, their safe detail and full JSON Pointer: what→/candidate/title, effect/excludes/why/risks/refs→/candidate/ask/<field>, context→/context, alternatives→/candidate/description. A synthetic gap for bounded enrichment overflow uses oversize at /candidate/description; a repeated enrichment uses invariant there. Failed native lint uses its exact safe Gap list. Completed invalid/oversize output becomes NeedsGrooming/oversize at the whole input; completed schema, unsafe or binding errors hold as bad_output. Host failures hold with their actual HostCode; completed unavailable holds model_unavailable. A valid sufficient/enrich/groom maps respectively SufficientProposal/EnrichmentProposal/NeedsGrooming (after all atomic enrichment checks).

The pure `sufficiency_disposition(prepared,attempt)` projection returns `SufficientProposal`, `EnrichmentProposal`, `NeedsGrooming`, or `HoldUnavailable`. None posts a card or grants approval. A passing semantic proposal does not bypass native `postable`, group authentication, redaction, whole-card size, action validation, or human approval. Future posting must fresh-check both native state and the exact judgment binding after any await, outside then inside the short existing commit boundary as appropriate to its final design; Plan7A claims no implemented atomic integration.

## 6. Grooming, unavailable results, and terminal recovery

There is no SufficiencyRequest.groom_failures field. The single pure `groom_disposition(groom_failures_after)` takes the count AFTER processing the current confirmed failure: 0/1 maps to ReturnToOrigin and 2 to CannotApproveNotice; it does not mutate counters. The retained count saturates at 2, never grows to an unrepresentable 3. Initial failure with no returned revision has count 0; first genuine returned revision still failing sets 1; second sets 2. Operator-groomed later submissions are still assessable with count 2: a sufficient result can proceed, another failure remains CannotApproveNotice. No automatic third return-to-origin is created. A future consumer durably increments failures only after a genuine returned revision is re-evaluated and still fails, not on retries, duplicate events, model outages, or delivery uncertainty. Submission revision identity is independent of the per-candidate native digest as specified in §5. Native digest still binds each assessment snapshot. A stale reply cannot consume a newer revision's budget. Grooming steers the **originating parked session** or the recorded creator, never a replacement agent invented for this purpose; it also counts within the existing three-nudge/no-progress budget when actually delivered as steering.

At two failed grooms the ADR requires a control-group cannot-approve-as-written notice listing gaps, deny as the default, and no approval buttons. This means **recommend deny**, not automatically record denial on silence. The operator can explicitly deny or groom; there is no approve-as-written path. Missing origin, dead session, exhausted nudge budget, or unknown delivery holds for an authenticated Marmot question. The eventual consumer retains the pending ask and origin evidence, releases unrelated work, and never fabricates a resumed session or resolved notice. No counter is reset by restart, a fresh model request, or task reassignment.

Timeout, invalid/unsafe/oversize input or output, endpoint error, stale native digest, and unreadable policy all remain typed failures (stale_digest and unreadable_policy are host-only HostCode members; models cannot select them). For sufficiency the result holds or returns correctable input gaps to origin; no outage becomes a human approval request for the incomplete ask. A separate content-free operational notice/question may explain the hold through the authorized control route. Recovery is a fresh native read and explicit resubmission of a corrected revision or restoration of the same dependency, with prior evidence retained; no automatic looping retry, self-unhold, alternate writer, or permission-classifier workaround.

Before the release shipping BOTH wsd and the semantic gatekeeper, any eventual relay judgment is **shadow only**. It cannot block or authorize historical valid phone approvals. That release must enforce passing sufficiency for every relayed approval, with no interval where both ship without enforcement. Plan7A neither ships a gatekeeper nor ends the interim exception. Activating either shadow or enforcement requires its own reviewed integration, real predecessor completion, and deployment authority.

## 7. Permission port: no decision/approval conflation

`PermissionRequest` adds exactly `subject:{task_id:BeadID,session_ref:ID,tool_name:ID}`, `intent:Text`, `invocation:{cwd_id:ID,input:NativeValue,sha256:Digest}`, `effective_budget_ms:PosInt`, and `elapsed_ms:0..2147483647` (integers, not bool). subject_id must equal subject.task_id. invocation.sha256 is the canonical JSON SHA-256 of `{subject,cwd_id,input,policy_revision}` with the same canonicalization as the request; exact arguments, session, tool and opaque cwd identity are thus bound. The host invocation is inert data and is never executed by this port; only its exact privacy-safe input projection may enter the explicit permission egress DTO. AllowProposal applies only to these exact bytes. The eventual Plan5 adapter must validate the actual cwd identity/action mapping and argument equivalence before any execution. No fixture action_ref, constant tier, or executable payload port is invented here. The permission egress carries exact privacy-safe tool/input and meaningful public cwd data; a descriptive intent alone is insufficient. Context and policy remain host-controlled, and permission result is advisory until actual hook/native input equality is established by later integration. effective_budget_ms is the frozen host-prepared effective policy in milliseconds,1..60000. Raw policy conversion/availability is classified by Prepared before constructing the bounded request: >60000, zero, missing, malformed or unreadable policy yields host_failed/unreadable_policy. It never becomes a model-selectable reason or a generic schema error. This profile does not claim the installed setting itself is hard60seconds.

`PermissionJudgment.outcome` is exactly `{status:"allow",reason:Text}`, `{status:"deny",reason:Text}`, `{status:"escalate",reason:Text}`, or the common unavailable outcome from §3. There is no scalar string judgment or alternate exception shape. A result of another kind cannot be decoded as PermissionJudgment. `permission_disposition(prepared,attempt)` maps nonready, local invalid result or model unavailable to EscalateProposal and any elapsed_ms>=effective_budget_ms to EscalateProposal before considering allow/deny. Elapsed deadline uses reason_code=deadline; unavailable uses model_unavailable; malformed output uses bad_output; actual host failure preserves HostCode. Otherwise valid allow maps to AllowProposal, deny to DenyProposal, and model escalate to EscalateProposal/model_escalate. All are exactly §3 Projection objects. The future integration must enforce the ADR's **total effective configured** grey-zone budget (at most 60 seconds in this profile) across queueing/model/validation, with no retry reset. Plan7A performs no wait or scheduling; elapsed_ms is an injected fixture value, not a production clock attestation.

Deterministic hard-deny and operator-only floors are evaluated **before** this port and cannot be downgraded by `allow`. No existing action, policy, secret-access, deployment, or message-send authority changes. `allow` means only an advisory grey-zone result under the unchanged sandbox/native gates; an action still requires its own authorized path and wsd-act validation. Permission failure escalates under §5.3; sufficiency failure cannot bypass §5.9 by being mislabeled an escalation. The later Plan5 integration owns durable audit of tier/decider/reason, action state, idempotency, decision write/readback, and unknown execution reconciliation. Plan7A has no approval metadata writer or executor credentials.
