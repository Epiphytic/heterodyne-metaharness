## Chosen narrow interface

Add a host admin Codex transport owned by the existing admind process. It owns one private stdio app-server child and one admin thread, not a shared background daemon, public listener or second Marmot store. Launch pinned Codex with explicit bypass flag, --no-daemon, and app-server --listen stdio://. Pin explicit config approval_policy=never, sandbox_mode=danger-full-access and medium reasoning. Thread and turn RPC parameters repeat the approved effective policy; check actual RPC responses and a real command turn rather than trusting argv. Refuse unsupported policy/config/version before migration effects.

Split settings role capabilities: admin executor admits Claude or qualified Codex; summarizer remains Claude-only, including explicit resolve-time rejection of Codex summarizer. Continue adapter-neutral account selection and environment filtering from AU-11, remove the other adapter's selector from the child environment, never copy login credentials or modify user-wide Codex config/hooks. Read the selected existing account in place; missing or different credentials hold. The model is selected explicitly, never silently substituted. This migration is host admind only, not the sandbox manager or workstream workers.

Factor the admin executor operations already used by daemon (readiness, send, interrupt, bounded diagnostics, explicit new, login match) into a narrow adapter interface. Retain Claude's path and all its guards. Codex uses structured RPC events; no synthetic Claude hooks, fabricated SessionStart event, screen scraping or Claude transcript fallback. `!tail` for Codex shows bounded redacted transport diagnostics and actual recent assistant text, identified as Codex diagnostics; `!interrupt` sends turn/interrupt for the exact active thread/turn. Unknown or mismatched IDs produce a hold, never a fallback Escape into another pane. Optional display/TUI is not authority and is not needed for this PoC.

## Durable binding and receipt semantics

Store a versioned executor binding through Store's supported transactions: adapter, model, effort, effective policy, account key, pinned binary digest/version, launch nonce, native thread ID and owning admind instance. Do not reinterpret old Claude agent_session as a Codex thread. Keep old launch/session metadata in an immutable migration record accessible to audit, and extend adapter matching so the new configuration cannot adopt an old live Claude pane merely because login matches. An upgrade from untagged state is unknown until the explicit migration validates the observed old executor.

Initialize RPC, then issue thread/start exactly once under a durable issued marker. Save its actual native thread ID and returned policy before declaring ready. This is a new Codex conversation, not a resume or native translation of Claude history. A bounded, redacted controller handoff supplies the existing mandate, durable evidence links, pending-input/unknown-effect summary and authority boundaries as context, never replaying old commands or asserting old work completed. Check startup and turn policy against the enrolled tuple, not only launch flags. No tools/turn are run for readiness before deployment authorization.

Use daemon's existing reservation and publication/outbox paths. Before turn/start persist the original Marmot input identity, canonical prompt digest, launch/thread binding, request ID and issued status. One external turn issuance at a time. On accepted response correlate the actual returned turn ID; on turn/started or matching start response create a native Codex prompt receipt that anchors the same original reservation, not a Claude UserPromptSubmit hook. Buffer bounded early notifications while the start response is pending, keyed by thread/turn; if attribution is ambiguous hold rather than guessing. Do not resend turn/start on timeout, daemon crash or a lost response. An RPC error only proves no effect if the protocol explicitly proves rejection before acceptance; other errors are uncertain.

Only item/agentMessage completed text for the bound thread/turn contributes to the reply; never send reasoning/tool outputs as assistant reply. Accumulate within current output bounds. turn/completed status completed is the normal terminal proof; failed/interrupted retains an explicit failure/interrupt receipt, with any partial answer identified as partial through existing publication semantics. Unexpected/missing IDs, malformed frames, output overflow, policy mismatch, stream loss or client request for interactive approval create a durable hold. Never auto-approve an unexpected request or silently fall back to Claude.

Persist terminal reply evidence before publication, then use the existing Marmot outbox and record its actual send/message receipt. Preserve original sender/auth and reply-to identity all the way through input -> reservation -> prompt receipt -> native turn -> assistant reply -> outgoing Marmot receipt. Delivery uncertainty stays uncertain and is never retried as a new execution. Repeated/late native events are idempotent by launch/thread/turn/item, and old launch events cannot complete a new reservation. Native RPC IDs and Marmot message IDs remain different fields.

## Supported migration operation and deployment

Implement one source-owned admin migration operation in the daemon's existing owner/control path. It takes a pinned deployment decision reference, expected old binding/process/account/store identity, target artifact and config digests. No caller-provided shell command, DB script or replacement arbitrary pane argv. Existing authorized host controller invokes it; no request for Liam to run commands.

1. Install reviewed source as a dormant artifact from current main plus this minimal change; verify manifests and root/service ownership. Capture deployment decision, approved design URL and deviations. Never deploy the old checkout wholesale.
2. Acquire existing sole-owner lock and a durable migration/intake-dispatch fence. Snapshot queued/reserved inputs, active ask IDs and unknown-effect holds using supported read-only Store APIs, and record old Claude process/session/launch/account evidence. Freeze executor dispatch while keeping host admind decisions, ingress and publication functional.
3. Verify no active execution turn is being killed. Idle pane screen alone is insufficient: inspect durable busy/in-flight/hook-uncertain evidence. Existing uncertainty remains fenced. If evidence cannot distinguish an active old turn, hold for exact disposition; do not clear it as part of migration. Unsent queued inputs are retained; already issued or uncertain inputs are never replayed automatically.
4. Consume the finite approved migration intent durably before retiring the exact old executor. Preserve its conversation/transcript metadata. Terminate only that verified old process/session through the existing owned transport; do not kill the unrelated host controller, worker panes or receiver. Confirm exit before issuing any Codex launch. A crash after issue leaves HOLD; no automatic repeated replacement/new conversation. Merely restarting admind cannot authorize migration.
5. Atomically publish the enrolled Codex executor profile selection for this admind instance, leaving summarizer and group identity unchanged. Launch the new exact child and establish its binding. The same store, operator policy, group and receiver remain the sole authority; no identity/credential copies or private-directory permission widening.
6. Carry old uncertain reservations into a separate retained quarantine record and leave their uncertainty gates in force. Only genuinely never-issued queued inputs become eligible for the new executor after qualification; reviewed state-machine transitions must demonstrate this without clearing a global hold. A finite qualification input can be admitted separately while old unknown effects stay held, with no permission to execute old pending commands.
7. Require the live verification below before marking migration complete. If failed, hold new dispatch and report actual old/new state. Rollback is not an automatic Claude restart or input replay; any executor replacement uses a new finite operator decision and preserves original evidence.
