## 1. Problem and bounded departure

Authenticated answers already settle in admind, but the current controller does not reliably continue until another user message. Add a deterministic bridge from explicitly enrolled exact admind asks to the **same existing Codex app-server thread**. Preserve run/native identity, existing daemon process, workdir, task ownership, queue route and policy. No new coding process, thread/start, thread/resume, manager, tmux adoption or conversation is permitted. Manager health stays an honest diagnostic.

This is an explicit proposed exception to spec/escalation-workstream.md's independent one-shot dispatch for one enrolled existing escalation-kind controller. Ordinary Supervisor.tick_run continues to skip escalation runs. The old retired ESCALATION.md is provenance, not authority to replace this session. Human approval covers targeted same-thread notification and the read-to-start race in §5. No original task approval, native gate, pause or ownership rule is removed. The bridge never accepts native permissions, edits Beads, claims/reclaims tasks, merges, deploys, invites members or changes policy. A wake is a notification, never an approval or authority to execute answer text. This is neither full Plan8 nor a general chat router.

## 3. Proposed interface and enrollment

Add approval_wake/ and bin/workstream-approval-wake only; no ordinary CLI/legacy inbox migration. Strict schema1 enrollment JSON <=64KiB: run_uuid, native_uuid, role=worker, daemon_binding, workdir, deployed_bridge_revision, admind_client_binding, legacy_activation_snapshot_sha256, asks[]. daemon_binding pins current PID/start_ticks/boot_id, executable realpath+SHA256/version, exact Unix socket path/owner/mode/listener inode and protocol/schema hashes. Verify /proc identity and socket ownership/listener association; no argv/environment/credentials are collected. Existing registered native lineage must match independently. No latest/alias/thread-list discovery. Replaced daemon or changed native holds for explicit verified re-enrollment; no automatic adoption or session resume.

Admind binding pins configured executable/hash/settings identity and exact configured endpoint, not caller-supplied arbitrary sockets. Ask entry: exact ask_id, expected_kind question/merge/approval, expected_summary {title,bead,digest12}, retained original_post_artifact_sha256, origin_task_ids (<=16), enrollment_nonce UUID. Successful original post record binds the actual returned ID. Missing record is a source-binding diagnostic, not invented full-digest proof. Summary digest12 is a consistency check only; subsequent work reads genuine full native approval evidence. No list or guessed ask IDs. Enroll after an already-authorized post; retained post record precedes idempotent enrollment. Posting timeout never creates an invented ID.

At most64 active asks/run, one binding generation and one active notification attempt. Duplicate exact enrollment is no-op; changing a source's original artifact refuses. New asks within deployed exact run scope need no additional design/deploy permission. Pause stops new input while retaining observation/tombstones. No application-level wait flag or regex exception is needed: an idle assistant asking for a Marmot response remains eligible when that exact answer changes. Native pending permission/user-input requests are NOT answered by the bridge.

## 5. Sole backend: same existing-daemon WebSocket

Client connects ONLY pinned existing Unix socket, validates listener/PID/UID/mode and RFC6455 upgrade, then initialize/initialized. No new codex process/proxy/server, thread/start/resume, turn/steer, approval response or configuration mutation. WebSocket client handles bounded frames, IDs, ping/pong and server notifications. Ignore unknown non-request notifications for compatibility; any outstanding server request needing permission/user input causes HOLD, never a synthetic response. Do not print/store transcript, credentials or unsolicited payloads. Use <=2MiB frame/response and15s per read,30s total final effect critical section; timeout/disconnect is explicit unknown.

Lifecycle reads are thread/read {threadId:EXACT,includeTurns:false}, and thread/turns/list {threadId:EXACT,limit:1,sortDirection:desc,itemsView:notLoaded}. Require exact registered thread/session/cwd, loaded runtime status idle, supported direct-input eligibility, latest turn status completed OR interrupted, no native active/waiting flags or outstanding approval/user-input request. Active, notLoaded, systemError, failed/unknown lifecycle, malformed identity or conflicting reads hold; do not resume. A valid interrupted turn plus actual idle is eligible: Esc is not a permanent deadlock. A completed assistant prose question is not a native prompt. Never fetch whole rollout/includeTurns=true or rely on a 62MiB transcript scan. Bounded pagination is used only for exact acknowledgment/recovery below.

Retired same-run effect services are verified disabled/inactive on EVERY effect pass: hermes-escalation.service and timer, plus exact deployment-inventoried old ingress/drain units. Unknown unit status or an executing legacy actor holds. Never turn units on/off in run-once; changes need the deployment's explicit authority. The source-backed locks are acquired nonblocking in fixed order: own watcher lock, run drain.lock, run oneshot.lock, workstreams/.supervisor.lock, then a short bridge DB transaction. On any contention release all, observe later; never wait while holding a partial chain. This preserves escalation's drain→oneshot order; manual direct _run_one and supervisor submit are fenced too. Enroll/pause/settle never acquire a legacy lock after holding bridge DB. Ask reads and queue guards occur outside the effect chain; recheck exact guard proof age <=2s under the locks, otherwise release and refresh. No database transaction spans socket calls. Release locks after one bounded effect; no lock spans a model execution.

Preserve task_blockers.assert_worker_unblocked semantics, including opt-in blocker policy and allow_review_edits. Restricted Beads facade exposes enabled/config and _queue(run) returning a wrapper around the hash-pinned trusted installed Queue, NOT Beads._queue's ambient SourceFileLoader. Its only queue I/O is show(EXACTID) and bd('list','--id',EXACTID,'--all','--limit','0'); deny all other argv/methods, pickup/claim/update/gate resolve and ready-list. This is not a stronger all-task design approval requirement: unchanged legacy opt-in semantics remain, and actual subsequent task actions have their own native gates.

Under all locks refresh daemon identity, run stop/route/input facts, service state and the same latest idle turn twice with final proof age <=2s. Omit ALL model/cwd/effort/policy/plugin overrides. No steer or native confirmation. Once sending persisted, any crash/timeout/rejection whose pre-write nature is unproved is uncertain, NEVER blind-retried. ## 6. Watcher, deployment and rollback

One proposed pinned hermes-approval-wake@RUN.service executes watch RUN, Restart=on-failure with5s–60s backoff, UMask0077. One pass observes <=4 asks, reconciles acknowledgment and at mostone guarded effect, then waits10s interruptibly. Shared watcher flock prevents overlap. Optional future five-minute backstop invokes SAME run-once; busy exits healthy and never gains another retry budget. It shares the user-manager/host failure domain; it cannot revive a dead host or coder. It neither starts consumers nor picks Beads. Source/storage failures restart observation safely; no restart replays uncertain input. Enabling this watcher/backstop is a later explicit deployment choice, not this design's current authority.

Implementation sequence: strict standalone enrollment/journal/RO legacy+Queue facade; bounded AskGet/status/dedup; exact pinned WebSocket protocol/idle and acknowledgment adapters; uncertainty/recovery/notice path; narrow installer and units. Implementation records dependency choice and exact closure in normal code review. Do not modify/import broad supervisor/tick paths. No application tests or model workload were run by this design-only task.
