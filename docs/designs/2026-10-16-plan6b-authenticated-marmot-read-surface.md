# Plan6B: authenticated Marmot read surface

Status: proposed design for btq-63iz7; no review verdict, human approval, implementation admission or deployment is claimed. Source baseline is `07637745fe75dc614109a0b8ba72d3489f262a97`. The adjacent input manifest pins the actual texts and source inspected. Names introduced below are proposed contracts, not existing APIs.

## 1. Scope and sequencing decision

This slice admits a future native ingress adapter and bounded read-query service for wsd: normalize authenticated Marmot messages, verify registration and fresh policy, persist replay and query-response mappings, project authoritative observations into the separately approved Plan6A presentation schema, and answer `/workstreams`, `/status`, `/status <bead>`, `/approvals`, `/queue [ws]`. Reading Beads never claims work or mutates it. Local ingress/cache/response journals are derived communication state, not task or approval authority.

The roadmap's full Plan6 predecessor remains Plan5 plus S4. The proposed **new human sequencing decision** is narrower: after compatible Plan6A is genuinely approved and implemented, permit standalone read-only 6B implementation and offline acceptance before complete Plan5. This exception does not permit starting a consumer, sending a message, deploying a service or claiming Plan6 complete. A later exact deployment approval must separately admit any early read-only live rollout and disclose the incomplete predecessor. If the operator does not approve that explicit exception, implementation waits for the full predecessor. This document does not decide the exception on the operator's behalf.

Excluded: unthreaded task intake, steering, approval/question answers, any Plan5 decision port or writer, task/label/dependency/status changes, claims, release/pause/resume/trust-group handlers, managed-install commands, membership/invite/repost operations, task/approval/question card creation or mirroring, reminder/digest scheduling, timers, consumer startup/cutover, gatekeeper changes, installation, deployment and live acceptance. Existing admind questions/approvals remain exclusively through authenticated Marmot and its native flow. No terminal/chat approval substitute exists.

The existing btq-rd4z5 invite-recovery scope, held btq-qrljq managed-install routing and btq-56v6h wording work remain separate. Plan5/e7knb owns the sole decision-writer/executor protocol; 6A/0bkbo owns pure presentation; later 6C owns full card outbox/mirroring/join visibility/reminders; later mutation integration owns command cutover. These are ownership boundaries, not new task admissions.

## 3. Verified transport and missing seams

At source076, `marmot/control.py` implements `marmot.agent-control.v2`, strict known-event decoding and bounded NDJSON frames (1 MiB). `subscribe(account, group, on_ack)` acknowledges before reading events. `InboundMessage` has account/group, MLS sender key, self flag, native message ID, text, timestamp and optional reply target. `ReactionAdded` has actor/target and optional event ID. `GroupStateChanged` reports membership/admin changes. `send_final` accepts reply target and idempotency key and returns native message IDs. This is the native supported control socket; no second process may open its MLS home.

`group_info` exposes group ID and count in this client, **not a member list or authenticated identity census**. No list-groups, history fetch, gap replay, authoritative read-after-unknown-send or idempotency-retention guarantee is established by this client. S4 demonstrated threads and reactions; its raw scratch logs were deleted and reaction removal was untested. Joining members cannot see historical cards; a successful add/count is not visibility evidence. 6B does not solve invite, join or history recovery.

Reuse candidates: `Journal.inbox_add` deduplicates `(surface,event_id)` and preserves pending entries; `inbox_finish` records terminal state. Its free-form payload and existing key lack the typed account/group/provenance partition required here. `Journal.snapshot` and `Wsd.status` provide derived scheduler state; the latter is string-valued and lacks complete presentation DTOs. `CtlRequest` multiplexes status and mutating operations on a service-user socket. `Beads.ready/show` are candidate reads, but a general Beads/Queue object exposes writes and cannot cross the new read boundary.

Missing work must be explicit implementation, not guessed existing support: typed replay storage/migration, registration/trust epochs, fresh normalized read policy, a restricted snapshot port with provenance, read-only projections for approvals/pickup rank/account/launch observations, minimal durable query-response state, and typed native mapping. No handler may forward arbitrary CtlRequest, native bd arguments, SQL, command text, paths or a caller-chosen method name.

## 4. Restricted architecture

A future `wsd.marmot_read` component has only four injected capabilities: native ingress subscription, restricted `ReadProjectionPort`, a private derived journal, and `ReadReplyPort` limited to an already validated query-response record. It cannot import decision/executor/Parker/managed-install/queue-write dispatch. Transport capability wrappers expose only their narrow methods, not a shared all-method client. The service user remains trusted; Python wrappers are not claimed as a hostile same-user sandbox. A fake-capability test proves no excluded method is reached, and a transitive import check protects accidental widening.

`ReadProjectionPort.read(request: ReadRequest) -> ProjectionResult` is **proposed**, with the closed version-1 contract below. Its implementation and caller identity are fixed by approved configuration. A local producer owns all source reads and normalization; the ingress receives only immutable validated DTOs, never a general Beads/Journal/client object. If served over IPC, private owner/mode/socket-peer checks bind the configured wsd instance/run. No request contains a mutation opcode or arbitrary method. Do not expose the existing unrestricted control socket to Marmot text. A read-only consumer must be deployable without starting pickup, timers, action executors or a second scheduler: if source architecture cannot provide that isolation, the early-live slice remains disabled pending a separate integration design.

### 4.1 Closed request and response contract

Records are immutable, reject extra fields, and use explicit `version=1`; enums reject unknown variants. Strings are UTF-8, bounded before allocation, with the 6A safe-label rules where displayed. Internal identifiers are never displayed automatically. `ReadSelector` is exactly one tagged variant: `Workstreams`, `Status`, `BeadStatus(label: SafeLabel)`, `Approvals`, `Queue`, or `QueueFor(workstream: SafeLabel)`. These correspond in order to the six grammar forms in §6. Labels select only within the independently supplied scope; no selector contains paths, commands, native IDs or a scope override.

`ReadScope` contains `surface: workstream|control`, `route: {account_id: AccountIdHex, group_id: GroupIdHex}`, `registration_epoch: u64`, `workstreams: tuple[WorkstreamBinding]` (1–100), and `producer_binding: ProducerBinding`. A `WorkstreamBinding` is `{name: SafeLabel, queue_identity: OpaqueId, repository_identity: OpaqueId}`; a workstream surface has exactly one binding, a control surface only explicitly registered bindings. `ProducerBinding` is `{name: SafeLabel, release_commit: 40-lowercase-hex, run_id: OpaqueId, boot_id: OpaqueId}`. `OpaqueId` is a nonempty configured identifier of at most128 ASCII bytes, not a filename or executable selector. Route identifiers use §5's separate validators. The registration owner constructs this scope; requester input cannot supply it. `ReadRequest` contains only `version`, `selector`, `scope`, and `request_id: OpaqueId` generated locally for correlation. Account and group identity, producer, run, repository, queue and registration epoch must match exactly, not by display name alone.

`ProjectionResult` is a tagged union: `Available(envelope: ProjectionEnvelope)`, `Unavailable(reason: source-unreachable|source-budget|missing-data|ordering-unproven|producer-restarted)`, `Rejected(reason: invalid-request|scope-mismatch|ambiguous-selector|not-found|invalid-source|generation-regression)`, or `Busy`. Not-found and scope-mismatch collapse to identical public wording. No error carries raw source values. Timeout is `Unavailable(source-budget)`, not an empty Available. Source malformation is rejected; known missing data may be represented by an explicit unknown field only where the compatible 6A schema allows it. There is no generic dictionary escape hatch.

`ProjectionEnvelope` fields are exactly `version`, `request_id`, `selector`, `scope`, `generation: u64`, `capture_started_ns: u64`, `capture_finished_ns: u64`, `observed_at: UTC timestamp`, `sources: tuple[SourceObservation]` (1–100), and `view: PresentationView`. Generation is positive and monotonic within the exact producer boot/run; capture finish is not before start. Each `SourceObservation` contains `origin: native-beads|wsd-journal|account-usage-journal|host-config`, `workstream: SafeLabel|null` (null only for shared host/account configuration), `observed_at: UTC timestamp`, `availability: reachable|cached-unreachable|unavailable`, and `completeness: complete|incomplete|unavailable`. It also has `shown: u32|null`, `total: u32|null`: both nonnull for enumerated collections, `shown <= total`, and both null for scalar/unavailable observations. Duplicate `(origin,workstream)` entries are invalid; separate account observation times and trusted/untrusted flags remain in the 6A payload. Total means an actual verified source total, never an estimate. No available complete view can contain an unavailable required source; incomplete fields must be representable honestly in 6A or the result is Unavailable.

`view` is the separately approved compatible 6A `PresentationView`, not a duplicate payload schema: Workstreams → workstreams; Status → workstream-status/control-status according to scope; BeadStatus → bead-status; Approvals → approvals; Queue/QueueFor → queue. All other 6A kinds, especially task/approval/question, are forbidden here. The view surface, scope, observation times, supplied `now`, availability, completeness, counts and cache state must agree with this envelope. The consumer supplies a fresh `now` and derives render-time age/cache state from preserved observations; it cannot alter source facts. The exact final compatible 6A implementation/pin and schema tests are an implementation prerequisite; its current provisional text is not approval. If that schema changes incompatibly, reconcile this design before implementation rather than accepting extra fields.

The finite origins above describe observation ownership, not new task authority. Envelope identity is authenticated by the fixed local producer/IPC binding; a message, arbitrary file or unsigned disk cache cannot become an authorized producer. No remote caller selects a source. Coherence is per captured source, not an atomic multi-store snapshot. Do not retimestamp older components or manufacture freshness. Changed producer/run/scope invalidates in-flight adoption, and disk caches never grant policy, membership or consent authority.

It must not parse `Wsd.status`'s comma-separated display strings or forward general `CtlRequest`. Existing methods below are source076 reuse points; access is wrapped in a fixed read-only allowlist. Native calls are bounded by §8's inclusive time/bytes limits, and neither source errors nor a native exception trigger fallback to a write API.

## 5. Registration, normalization and authorization

Registration is an operator-managed immutable runtime view loaded from supported host configuration, with exact local signing account, native group, kind (workstream/control), permitted workstream names, registration epoch and trusted-group baseline. This design creates no group, identity, invitation or new registration mutation API. One group has one configured meaning; duplicate/conflicting routes refuse startup. The adapter never infers a group from text, a title, a public label or count.

Before accepting each command: subscription ACK is current for that exact account/group; a successful `group_info` in the same subscription generation returns the expected group with positive count; registration is current; fresh validated policy resolves the native sender to exactly one allowlisted approver; sender is not self; native account/group/message IDs are valid protocol values. Compare outer event account as well as group to the subscribed route. Use separate validators and normalize valid hex case once. `PubkeyHex` is exactly64 hex characters (32bytes), using the actual NIP-19 decoder's length/checksum rules for configured npubs and an equivalent strict hex check for native sender keys. Source076 `marmot/nip19.py:npub_to_hex` explicitly checks `len(raw) == 32`; `admind/settings.py:operators` demonstrates normalization and duplicate-key refusal, not the wsd allowlist policy. `MessageIdHex` and known Nostr reaction event/target IDs are exactly64 hex characters, matching source076 `admind/daemon.py:MESSAGE_ID` and its message/reaction checks. An account signing-key identifier uses `PubkeyHex` only where the configured native account contract identifies it as that public key; otherwise `AccountIdHex` is a bounded even-hex route identifier checked against exact configured account and subscription, with no inferred key length.

`GroupIdHex` is **not** a public-key/message validator: it is nonempty even-length hex, between2 and512 hex characters (1–256bytes). That ceiling is a proposed local resource bound, not a native fixed-length claim. `AccountIdHex` when not a signing-key ID uses the same local syntax/ceiling. Source076 `control.py:InboundMessage`, `GroupInfo` and `group_info` type group IDs as strings and establish no universal32byte bound; S4 does not establish one either. Valid syntax is insufficient: the normalized group must exactly equal the configured registration and same-generation native `group_info` result. A registered16byte group is accepted; a synthetic32byte group is also accepted when the fake/native-supported response and exact registration agree. Unsupported native group forms fail closed rather than being coerced. Odd/empty/nonhex/oversize, a valid but differently registered group, or a mismatching native response are rejected. No actual deployed group identifier is required in committed fixtures. Malformed identifiers yield value-free rejection. Text is valid decoded Unicode, at most 4096 characters and within 16 KiB UTF-8, with 6A controls/formatting refusal. Reject invalid types/unknown versions before any command parsing. Remote timestamps are observations, not freshness authority.

An authenticated message does not prove current group membership by itself beyond the supported MLS transport. Never manufacture a member list. Detected membership/admin/identity changes and trusted count mismatches record a durable trust hold and invalidate query outputs for that group. This slice conservatively suppresses **read disclosure too** while held, although ADR §3.4 specifically mandates approval suspension. Other groups continue independently. Baselines are not adopted from the first count or after reconnect. The existing/future authorized trust-recovery owner must establish the exact trusted registration/baseline; 6B has no `/trust-group` implementation and never clears a hold. Recovery instructions say to ask the admin agent through Marmot, without creating a terminal consent route or claiming a trust endpoint already exists. Initial deployment or a trust-recovery change is blocked unless a supported recovery procedure and actual initial trusted baseline are recorded. This is a real deployment prerequisite; ordinary unchanged-source implementation edits do not require a new registration permission.

On disconnect invalidate live readiness; reconnect ACK and same-generation `group_info` are required before serving again. Positive unchanged count only detects the supported count property; unchanged-count membership swaps by a same-user socket actor remain the ADR residual risk. Readiness checks use a monotonic maximum 30-second group-observation age; stale verification triggers a coalesced check outside the command critical path and withholds sending until success. Failed group reads/policy loads close disclosure temporarily; no stale authority fallback. This adds no membership mutation or automatic rearm.

Reload fresh validated policy and registration before projection selection, after any await and immediately before **each** outbound part. Capture versions only for race detection, not reusable authority. A currently removed sender, changed scope, hold or unreadable policy suppresses all remaining parts and records a value-free reason; it cannot undo a part already sent. Query results do not include another requester's source text or arbitrary transcript data. Every response retains its authenticated requester key and exact group/account/registration epoch throughout queueing and restart.

## 6. Grammar and scope

Use the genuinely approved compatible 6A classifier, not admind's effect-bearing `!` parser. Its provisional input at `7903439e1a7ce5d738e502d0e7589d073ab4ac16` is an input only; changes from its ongoing review must be reconciled before 6B approval/implementation. Parse the entire trimmed string, case-sensitive single-line ASCII-space grammar and 6A safe selectors. Resolve a display selector to an exact configured workstream/native bead through the restricted projection port; ambiguity, collision or mismatch returns a fixed unavailable/not-found result without guessing a task.

| Query | Workstream group | Control group |
| --- | --- | --- |
| `/workstreams` | Only its registered workstream row; explicit scoped view | All workstreams explicitly registered to this control surface |
| `/status` | Its workstream status and account observations | Registered control aggregate plus open approvals/needs-human |
| `/status <bead>` | Exact bead only within its registered workstream | Exact bead within configured accessible workstreams |
| `/approvals` | Its workstream's open approvals oldest-first | Accessible workstreams, oldest-first with stable tie-breaker |
| `/queue` | Its workstream, producer pickup order | Accessible workstreams, visibly partitioned by workstream |
| `/queue <ws>` | Only the same registered workstream | Only a configured accessible workstream |

The stricter workstream isolation is an explicit new read-scope rule; a workstream group cannot list other workstreams or use bead labels to traverse scopes. Not-found and out-of-scope use the same public wording. Renderer gets a bounded scoped DTO, never an unfiltered global snapshot to redact later. Safe transcript display location is a configured label/link only, no file content, live pane, raw UUID, filesystem probe or agent instructions.

Authenticated read commands may be threaded under any message in the same allowed group; target association adds context but is not authority. A missing reply map does not stop an explicit exact read query. Unknown slash commands, mutation names, ordinary text and reactions are durably classified ignored/unsupported; they never reach an LLM, create a Bead, answer a card or receive a positive action acknowledgement. Non-allowlisted/unregistered/replayed input receives no reply. Authenticated malformed queries may receive a fixed usage response subject to the same limits/freshness checks. Do not echo rejected text, guessed identities or hidden target existence.

## 7. Durable replay, mappings and minimal replies

Proposed new typed journal records are communication state only. Replay key is `(local account, native group, event kind, native event/message ID)`; namespacing never permits one physical event to dispatch twice. Account/group are checked against the subscription before insertion. Each accepted query row contains exact normalized requester provenance, registration epoch, bounded parsed selector, local acceptance time, native reply target, policy version for audit and terminal-state reason. A unique constraint claims the event and creates its response reservation in one transaction **before** any projection or send. A crash cannot produce another reservation. The same key with different payload/provenance is a protocol conflict and quarantines that key; first accepted provenance is never overwritten. Untrusted input audit retains only fixed reasons, lengths and correlation hashes, not full stranger text/identity.

Query states: accepted → preparing → ready → sending → delivered; suppressed, unavailable, unsupported and uncertain are durable terminal outcomes. Shutdown/startup recovers accepted/preparing by rebuilding from a fresh scoped projection and current authority; never reuse a ready payload that bypassed fresh validation. Ready can be resumed only with exact stored rendered bytes/hash and per-part provenance checks. Before sending persist a unique attempt and part index/key. If process stops after that mark without a definite send result, that part and logical response become **uncertain**, not automatically resent. Pending later parts stop. New explicit commands have new native IDs and are allowed. Unknown delivery cannot hold unrelated senders/groups hostage.

The minimal read-reply queue is included because commands otherwise have no observable response; it is **not** 6C's general card outbox. At most 20 deterministic parts per response using exact approved 6A bounds; replies thread part1 under the native query, subsequent parts under the genuine part1 receipt. `send_final`'s returned nonempty well-formed message IDs are real receipt evidence, not proof the operator read it. A definite pre-send refusal leaves the result unsent; retry only if transport proves no effect and limits permit. Timeout/socket loss/malformed success or lost reply is uncertain. Do not assume idempotency keys have indefinite native dedup retention; no blind retry of unknown sends and no fabricated receipts.

Durable `ReadReplyRef` binds response/part revision and text hash, route/registration epoch, native query ID, actual returned native IDs and current/superseded/uncertain state. This maps own read responses for threading/dedup/restart; it does not turn a reply/reaction into consent. A future `ExternalCardRef` import, if needed for context, must come only from the configured authoritative card writer via the restricted projection envelope with canonical task/decision identity and revision, route and genuine receipt mapping. 6B cannot invent or update a task/approval mirror from inbound quoted text. Absent or stale owner mapping stays unresolved. No re-post after restart or journal loss: that behavior belongs to separately admitted 6C; explicit read commands still function.

Replay tombstones and send evidence are retained, never age-evicted automatically; removing them could redispatch old queries or repeat unknown sends. Journal-loss/corruption holds ingestion and delivery until separately authorized recovery, retaining the original file; no empty replacement. Migration is transactional, keeps prior rows/indexes/triggers/FK identities, marks legacy missing provenance nonselectable, rolls back on any failure and proves exact preservation/readback. Disk pressure refuses new reservations rather than discarding history. A retention design may later introduce a proven native replay horizon; none is assumed here.

## 8. Bounded cache, scheduling and outage behavior

Cache key includes producer identity/release/run, registration epoch, scope, selector, projection version and generation. It holds only validated display DTOs, maximum 256 KiB each and 16 MiB total; LRU eviction affects display snapshots only, never replay/tombstone/mapping/send records. At most 100 rows per source page, explicit shown/total/completeness and 6A bounded pages. Larger sources return honestly incomplete views only with verified total/order facts; otherwise return Unavailable under §4.2, with no hidden readiness computation or implicit pagination command. No truncation can make an empty/complete claim.

At age **greater than 30 seconds** request one asynchronous coalesced refresh per scope/selector. Age exactly30 is fresh; future UTC data is invalid. Use monotonic capture age within a boot; persisted snapshots after restart are stale until refreshed (their old UTC observation can still be displayed). A new producer snapshot with older generation or changed scope is not adopted. Failed refresh retains original observed times and sets cached-unreachable. No snapshot returns fixed unavailable, never empty or ready. Partial source failure is explicit per-section and overall incomplete; old data cannot be mixed into a fresh complete label. Do not infer account authority/capability from unknown or advisory usage.

Commands do not wait on Beads or remote group reads for their one-second target. With a stale snapshot, schedule refresh and answer the old scoped view with age/stale/refreshing; on known read failure use `⚠️ beads unreachable, data as of HH:MM UTC`. If group/policy verification is unavailable, disclose **no** cached content; record suppressed and recover on a new explicit query after readiness. Freshness of content never substitutes for freshness of authorization. Replies queued across waits re-evaluate content age; the final warning reflects send-time age, or the unsent response is rebuilt atomically before the first part. Once part1 is sent, keep the same snapshot/parts and observation time for all remaining parts; only suppress on authorization failure, never splice a new snapshot mid-message.

Bounded admission: 64 accepted in-flight queries globally, at most8 per requester/group; one active refresh per cache key, at most4 refresh workers, a shared bounded 5-second source-read budget including subprocess/IPC cleanup; one send at a time per group, fair round-robin across groups/requesters. Coalesce duplicate selectors only for projection work, not requester provenance. On overload authorized requests get at most one fixed busy reply per requester/group per30 seconds, itself counted within these limits; unauthenticated traffic gets none. Persist logical busy reservation before sending; no unbounded queue or reply amplification. Refresh failure has a monotonic 5-second retry backoff triggered only by a subsequent command, not a new timer. Stop cleanly cancels owned work and joins workers; no effect-bearing subprocess or leaked background pickup.

Target: under1second from validated durable query to committed response/unavailable/busy reservation on the local warm-cache path, including fresh local policy reads, measured at p99 over1000 synthetic requests. Track separately actual native reply latency; remote availability prevents a universal sub-second delivery guarantee. A test with a slow fake transport must still show local bounded handling and honest pending/uncertain state, never a false delivered assertion. No production benchmark or timer is authorized by this document.
