## 1. Scope and sequencing decision

This slice admits a future native ingress adapter and bounded read-query service for wsd: normalize authenticated Marmot messages, verify registration and fresh policy, persist replay and query-response mappings, project authoritative observations into the separately approved Plan6A presentation schema, and answer `/workstreams`, `/status`, `/status <bead>`, `/approvals`, `/queue [ws]`. Reading Beads never claims work or mutates it. Local ingress/cache/response journals are derived communication state, not task or approval authority.

The roadmap's full Plan6 predecessor remains Plan5 plus S4. The proposed **new human sequencing decision** is narrower: after compatible Plan6A is genuinely approved and implemented, permit standalone read-only 6B implementation and offline acceptance before complete Plan5. This exception does not permit starting a consumer, sending a message, deploying a service or claiming Plan6 complete. A later exact deployment approval must separately admit any early read-only live rollout and disclose the incomplete predecessor. If the operator does not approve that explicit exception, implementation waits for the full predecessor. This document does not decide the exception on the operator's behalf.

Excluded: unthreaded task intake, steering, approval/question answers, any Plan5 decision port or writer, task/label/dependency/status changes, claims, release/pause/resume/trust-group handlers, managed-install commands, membership/invite/repost operations, task/approval/question card creation or mirroring, reminder/digest scheduling, timers, consumer startup/cutover, gatekeeper changes, installation, deployment and live acceptance. The existing btq-rd4z5 invite-recovery scope, held btq-qrljq managed-install routing and btq-56v6h wording work remain separate. Plan5/e7knb owns the sole decision-writer/executor protocol; 6A/0bkbo owns pure presentation; later 6C owns full card outbox/mirroring/join visibility/reminders; later mutation integration owns command cutover. ## 3. Verified transport and source boundaries

At source076, `marmot/control.py` implements strict `marmot.agent-control.v2` NDJSON with a 1 MiB frame limit. Subscription ACK precedes serving events. Authenticated inbound message fields include native account/group/sender, self flag, message ID, text, timestamp and reply target. Reactions can lack an event ID; group-state events have none. `group_info` proves the returned group/count, not an identity census. `send_final` returns a list of message IDs. No history replay, unknown-send readback, native deduplication lifetime, group-ID universal fixed length or canonical multipart root is established. These limitations are contractual, not imagined transport features.

Source076's `Journal` is **not** a read capability: construction creates missing files, its working connection switches WAL, and `snapshot`/`usage_cache` use `BEGIN IMMEDIATE`. `wsd.btq.factory` constructs the general queue. The pinned queue constructor reads write-capable credentials and can mkdir even when a caller wants a read; `make_state=False` alone does not solve credentials or `bd`'s 20-second timeout. `ready --limit 0` is unbounded and hides paused queues. No read component constructs these objects, invokes these helpers, uses their environment, or parses display strings from `Wsd.status`.

The scheduler's `_candidates` first considers resumable/overdue rows, then new ready rows, skipping/gating candidates and honoring pause only for new claims. A native ready list is not the next actual pickup order. Calling the scheduler to discover order would mutate state. This design therefore requires a separate read-only candidate observation described below; it never presents a native ready list as a guaranteed launch prediction.

## 4. Restricted producer and closed read contract

The proposed consumer receives only four capabilities: subscribe to its configured native route; `ReadProjectionPort.read(ReadRequest)`; its own derived journal; and a response-only native send wrapper. It cannot import executor/Parker/decision writer/managed-install/general queue or general CtlRequest dispatch. These are new proposed interfaces, not installed APIs. Python capabilities assume a trusted service user and do not claim hostile same-user confinement.

The proposed source producer is a bounded read handler in the already running source owner, using that owner's existing initialized connections. It serves a fixed query table with parameterized SELECTs in a bounded **deferred read transaction**, not Journal.transaction, new Journal construction, new indexes on the runtime DB or a scheduler tick. It does not start the owner. Its private IPC checks socket owner/mode and peer identity and binds exact configured producer/release/run/boot. Consumer imports must not initialize source state. When the owner is absent the journal-derived source is unavailable; early read implementation remains useful offline and native-only sections may remain available. A standalone live consumer cannot start pickup, reconciliation, timers or action executors to obtain data.

Native reads require a new fixed-operation bounded adapter under this same proposed contract. It must use an explicitly provisioned read-only native account, fixed repository/server binding and a bounded process wrapper; it does not construct Queue or load wsd writer credentials. No caller supplies argv, SQL, credential path or repository. Provisioning of the real read role/transport and its tested operation shapes is a deployment prerequisite, not a claim that the role exists now. Read wrappers cap decoded bytes (256 KiB), item counts (100 per collection), process count and elapsed time, kill/join their own process group on timeout, and include cleanup in the five-second aggregate source budget. No unbounded native enumeration or in-process cancellation of an uninterruptible queue call is permitted. Missing supported count/order/limit contracts produce explicit unavailable sections while adapters are completed; adding a fixed nonmutating adapter within these bounds is implementation work, not a new design permission cycle. Native source effects or credential privileges beyond this contract require reconciliation.

### 4.1 Versioned records and collection accounting

Immutable version1 records reject extra fields and unknown tags. Before JSON allocation the projection IPC rejects frames over256 KiB; after bounded decode it enforces field/type/count limits. This differs from native ingress: native text is already decoded inside its 1 MiB frame before the stricter text check (§5). Safe display labels follow compatible 6A rules; internal IDs never render automatically.

`ReadSelector` is Workstreams, Status, BeadStatus(safe bead label), Approvals, Queue or QueueFor(safe workstream label). Request fields are version, selector, locally generated request_id (1–128 ASCII bytes), and owner-supplied scope. Scope fields are surface(workstream/control), route(account/group), registration_epoch(u64), 1–100 WorkstreamBinding(name, queue_identity, repository_identity), and ProducerBinding(name, release_commit40hex, run_id, boot_id). Workstream surfaces have exactly one binding; control surfaces list only registered bindings. Opaque identities are 1–128 ASCII bytes, not paths. Input text cannot set scope or producer.

Result is Available(envelope), Unavailable(source-unreachable|source-budget|missing-data|ordering-unproven|producer-restarted), Rejected(invalid-request|scope-mismatch|ambiguous-selector|not-found|invalid-source|generation-regression), or Busy. All not-found/out-of-scope responses use identical fixed wording. Errors contain no raw source values. Timeout never becomes an empty result.

Envelope fields: version, request_id, selector, scope, positive generation, capture_started_ns, capture_finished_ns, observed_at UTC, 1–1024 SourceObservation rows, and compatible 6A view. Generation is increasing only inside an exact producer boot/run; capture_finish >= capture_start. Each observation has origin(native-beads|wsd-journal|account-usage-journal|host-config), workstream(nullable only for shared configuration/account facts), **collection**(configuration|state|holds|running|approvals|candidates|recent-events|usage), observed_at, availability(reachable|cached-unreachable|unavailable), completeness(complete|incomplete|unavailable), and shown/total. Identity is `(origin,workstream,collection)`; duplicates reject. A selector has at most eight collections per workstream plus shared observations; the 1024 cap accommodates100 workstreams without conflicting with the256-KiB envelope cap. An overlarge envelope returns source-budget rather than discarding scope silently. Counts are independent per collection; scalars/unavailable have null counts, enumerated available collections have actual verified nonnegative totals and shown<=total. Unknown totals cannot become an honest truncated count.

No atomic snapshot across stores is promised. Every section preserves its own observation time and provenance. Complete is allowed only if every required section is complete/reachable. Unavailable optional sections are explicit unknowns; they cannot turn into empty lists, zeros or inferred approvals. Projection validation verifies producer/scope binding independently of display labels.

## 5. Registration, trust recovery and authentication

A proposed supported operator configuration schema, `marmot_read` version1, contains enabled(defaultfalse), a private journal identity/path, producer endpoint/binding, finite routes, and bounded policy/cache settings only. Each route binds account64hex, group evenhex1–256bytes, kind, 1–100 permitted workstream bindings, positive registration epoch, trusted initial group/count baseline and recovery owner. Reject duplicate/conflicting routes and **any alias of admind's configured own account/group**, comparing normalized native identities before startup. Account IDs are exactly32-byte public keys at this pinned protocol, as are sender/message/reaction target IDs; there is no loose account fallback. Group length is a local resource limit, not an assertion of universal native length.

Configuration is installed through a proposed supported `wsd-read-config` operator script: `validate`, `plan`, and `apply --expect-digest=...` publish a canonical private config atomically after exact before/after validation. It manages read configuration only, never task/approval/member state. This is planned implementation under 6B, **not an installed command today**, and personal CLAUDE.md preferences do not authorize terminal file surgery. Genuine approvals and questions remain exclusively Marmot; script execution consumes an already recorded approved deployment/recovery instruction and does not create approval evidence. No group creation, invite or automatic baseline adoption is included.

Trust recovery has an explicit owner: the configured admin agent/operator workflow obtains an authenticated Marmot approval for the exact old/new route epoch, group baseline and held-state digest; the same supported config script validates that native decision binding, increments epoch and publishes that approved registration, preserving the prior hold/history. A 6B hold is never cleared in place by inbound text, matching count, reconnect or first observation. The consumer can leave the old epoch held and serve the newly approved epoch only after ACK and group_info. This is a narrow registration recovery procedure, not `/trust-group` implementation or membership mutation. Deployment is blocked until that supported script, real approval validation and initial trusted baseline are tested and available; no indefinite undefined future owner is advertised as recovery.

Membership/admin/identity change or count mismatch durably holds only the affected route and stops disclosure there. Write a bounded control-alert record and attempt one fixed value-free alert to a **separately trusted configured control route**, never the held route; if no trusted control route is available persist pending alert and expose local doctor status without leaking through another group. Alert delivery uses the same uncertain-send discipline and no unlimited retry. This minimum trust-safety notice is not general6C card mirroring. Repeated identical holds coalesce. Reconnect does not reset holds; no auto-rearm.

Before command reservation and after every await/before every part: current route registration, fresh uniquely normalized Policy.approvers key, not-self, exact account/group binding, current subscription ACK and successful same-generation group_info matching baseline. No stale authority cache. Group observations expire after30 monotonic seconds. A stale observation creates **waiting-auth**, coalesces a check within the command's bounded admission lifetime and resumes the same query on success; it is not immediately terminally suppressed. Definite revocation/hold/scope change is suppressed terminally; timeout/unreachable becomes auth-unavailable terminally with no reply, allowing a new explicit query later. On an idle route the first valid query can wait for this bounded check rather than always disappearing. Disclosure still requires fresh authorization.

Native frames have already been decoded within1MiB before text validation; do not claim otherwise. Text limit is4096 Unicode code points (therefore at most16KiB valid UTF-8), plus compatible6A control/format refusal. Invalid types/IDs/version reject before grammar handling. Native timestamps are observations, never local freshness authority. No identity census is invented from counts, and unchanged-count swaps by privileged local actors remain the ADR residual risk.

## 7. Separate journal, bounded replay and complete state machine

Create a **separate6B database**, private owner/mode/path with symlink refusal, schema `marmot_read` version1. Never add tables, indexes or version markers to wsd's exact-schema runtime journal. Only explicit first-install initialization may create it; a missing previously initialized DB holds ingress/delivery, preserving evidence rather than silently replacing history. Startup opens/validates existing private state, bounds recovery batches and does not start any transport automatically. Proposed tables: metadata/schema/identity; route epochs/holds/alert reservations; query reservations; snapshot cache; response revisions/parts/attempts/receipts; replay epochs/quotas. Typed constraints and named indexes support all bounded recovery/query lookups.

Replay reservation applies to **authenticated read/usage/unsupported messages with a valid native message ID**, key `(account,group,message,event-ID)`. It atomically claims that key and exact immutable requester/registration/selector/reply target before projection/send. Same key with changed provenance/payload quarantines, never overwrites. Message IDs cannot dispatch twice under different parse categories. Reactions without IDs and group-state events do not enter this query table: reactions are always effect-free ignored; state events idempotently latch the route hold keyed by current epoch+reason, with no requirement to synthesize a replay identity. Malformed/nonallowlisted/ordinary input creates no per-event row. Record only capped hourly counters by fixed reason/route; do not persist stranger text or identity or reversible public-key hashes. Optional diagnostics use a private rotating keyed HMAC solely within a bounded window, never exported as a durable identity. No correlation is needed for authorization.

Durable query transitions (every transition validated in one transaction):

| State | Next / recovery rule |
| --- | --- |
| reserved | waiting-auth or preparing; exact event reservation exists before effects |
| waiting-auth | preparing on fresh proof; auth-unavailable/suppressed on bounded failure; restart rechecks |
| preparing | ready with complete response revision; or fixed unavailable/not-found/usage/unsupported/busy/narrow-query response; restart rebuilds fresh |
| ready | before any attempt recheck authority and freshness; obsolete unsent revision may be atomically superseded/rebuilt; otherwise sending |
| sending | persist attempt+part/key before native call; definite single receipt -> part-confirmed; definite no-effect refusal -> bounded unsent retry; lost/malformed/timeout -> uncertain |
| part-confirmed | next part only under current authorization and same response revision; lastpart -> delivered; revocation -> partial-suppressed; aging budget -> partial-expired |
| uncertain / partial-uncertain | terminal, no automatic resend or later parts; preserve all genuine receipts |
| suppressed / auth-unavailable | terminal, no disclosure or retry; new native query may proceed |
| delivered | terminal with response semantic outcome(success/unavailable/not-found/usage/unsupported/busy/narrow-query); do not confuse delivered notice with available data |

Quota refusal before ordinary reservation uses one dedicated bounded busy slot per permitted requester/route per30seconds; if that slot is occupied/rate-limited, aggregate counter only/no reply. Native duplicate detection remains authoritative in the retained epoch. At most64 active queries globally,8 per requester/route,4 source workers,1 send per group, fair round-robin. Fixed backoff5seconds; no background retry timer. A send attempt has a bounded deadline; cleanup is joined.

Responses have <=20 deterministic parts and a revision digest over snapshot identity, original observation times, rendered-at UTC, bytes and part order. Part1 replies to query; subsequent parts require **exactly one** well-formed native ID from each successful send and use the unique first-part ID. For a returned list of zero/multiple/duplicate/malformed IDs, retain the exact bounded returned receipt evidence, mark uncertain/partial-uncertain and stop. Do not arbitrarily select a root or resend. Multiple IDs are not silently interpreted as failure-before-effect; a future proven native root contract can be separately reconciled.

Send-time freshness is checked before first attempt: rebuild an unsent old revision rather than reusing a false fresh label. Every rendered response includes absolute observed-as-of and rendered-at timestamps; relative wording is explicitly **at render time**. Multipart uses one snapshot/byte revision, finishes within30seconds of first attempt and never substitutes a fresher chunk. Restart may resume a ready revision only before its first attempt and within its freshness bound, otherwise atomically rebuild. Any attempted part without definite result is uncertain on restart. Old rendered bytes never gain new timestamps. Authorization is always fresh independently of content freshness.

Storage is bounded:16MiB cache plus64MiB non-cache logical budget and filesystem headroom reserve; individual rows capped and transactions check limits before admission. Authenticated reservations/attempts/replay evidence are never evicted to accept more traffic. At capacity stop new ordinary reservations with bounded doctor/control alert, and do not create infinite busy rows. Recovery/alert slots are preallocated/bounded. Normal operation below quota is finite; large deployments need explicit archived replay-epoch rollover, not automatic age deletion. Proposed `wsd-read-config rollover` stops ingestion, freezes old epoch and retains its immutable DB/digest, then requires authenticated scoped recovery approval before a new native subscription/registration epoch is admitted; old-epoch message IDs cannot be replayed as new queries. Without a native replay boundary proof, HOLD rather than erase history. This is a safe bounded capacity limit, not indefinite free storage or a proven rollover today.

Schema upgrades are6B-only transactional copies with exact source/destination versions, old rows/keys/FK/index/trigger checks, fsync+atomic publication and failure rollback; runtime DB untouched. Downgrade stops6B and retains new DB/receipt; never overwrite newer query/send evidence with backup. No old runtime inbox is automatically imported as trusted6B provenance. Legacy ambiguous rows, if explicitly migrated in a reviewed fixture, are nonselectable quarantine. Journal corruption/loss holds; operator uses supported doctor/recovery procedure through the authenticated approval flow, never empty replacement.

## 8. Stable cache identities, generations and bounded refresh

Stable cache/refresh identity is `(producer logical identity, projection schema, registration epoch, scope digest, selector)`, **not** generation/boot/run. Each validated entry stores producer release/run/boot, positive generation, capture/observation times and the immutable envelope. Single-flight uses that stable key. Maintain an active producer binding separately: fresh reads must match it; a changed binding starts a new generation domain, invalidates pending adoption and marks retained same-scope entries **historical stale**. A persisted old-run entry is eligible only as explicitly historical display after fresh current authorization and unchanged scope/schema; it never establishes the current run, generation or authority. Scope/policy/registration changes cannot reuse another scope's bytes. Reject a generation regression within the same domain, not generation1 after a genuinely new bound boot.

Entries <=256KiB; total cache16MiB LRU, eviction has no effect on replay evidence. Collection pages <=100rows; shown/total and incomplete flags remain per collection. At age>30seconds trigger one coalesced refresh; exactly30 is fresh. Monotonic age only within a boot; restart entries are stale and retain original UTC. Future UTC invalid. Failed refresh retains old facts, marks failed sections cached-unreachable and never changes their observation time.

A cold query starts/joins a bounded refresh and waits up to the shared5second inclusive source/cleanup budget; it is not guaranteed to fail just because cache is empty. Warm queries reserve a current snapshot immediately and schedule refresh without blocking on source IO. A missing/failed cold source gives a fixed unavailable notice; stale cache gives source-specific age/failure warnings. Fresh policy/group verification remains mandatory even for historical cache. Target warm local p99<1second for1000fake requests measures durable local response reservation, not network delivery; cold path is explicitly up to5seconds plus bounded native send, not subsecond. Source stalls must not prevent other groups' fair handling or leave leaked processes.
