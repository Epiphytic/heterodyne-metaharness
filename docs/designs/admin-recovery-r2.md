# Unattended same-thread admin recovery — approval candidate r2

Supersedes the manual one-shot proposal. The single independent Claude Opus HIGH review of r1 returned REVISE. This revision incorporates those findings and the operator receipt requirement; human design approval is pending. Private review and runtime custody evidence are not included.

## Supervisor and recovery authority

Reuse the enrolled admin systemd unit and a timer/oneshot outside its cgroup. Reconciler allowlist: read bounded local health, read durable state, CAS recovery controller phases, stop/start only the enrolled unit, emit deterministic status. No native client, credentials, model or chat decision. Only the successor daemon in recovery-only admission mode can read native history and resume; reconcile by durable readback. Every start path (boot, Restart=, manual and reconciler) must validate phase and binding before opening native or dispatch admission; open incident or unconfirmed epoch defaults held, with only exact authorized recovery phase eligible for native resume. Intentional stop/maintenance and security holds override automatic action. Use a nonblocking kernel-released unit-scoped flock plus durable CAS, never lease expiry alone. Bound total tick work; systemd coalesces overlapping starts of the same oneshot. Persist backoff with boot ID and wall deadline; use monotonic within boot and requalify after boot or clock ambiguity.

Classify with generation-bound daemon and exact native peer health, acceptance age and independently verified correlated progress. Missing ack triggers investigation, not restart veto or proof of nonexecution. Confirmed enrolled executor death triggers recovery; a hang requires consecutive deadline misses AND verified degradation of the local owner/socket, not upstream timeouts alone. Responsive native active work stays untouched even when quiet beyond 90 seconds; a documented provider/tool max-turn budget may trigger degraded alert, not fencing solely on elapsed time. Healthy idle and advancing work stay untouched. Qualify KillMode=control-group and descendant containment including delegated subgroups; refuse external owners/surviving children, don't kill outside enrollment or treat stale socket removal as proof. Verify cgroup empty and owner/socket generation before starting successor. Fence stale epochs at Store and at last controllable publication sink, not only sender; journal a publication already in flight as uncertain, never resend ambiguous publication blindly.

## Durable phases

Incident key is prior binding epoch plus monotonic incident sequence (and original TURN/ingress IDs when present). Each effect key is incident + phase, never a new timer tick. On evidence drift or crash read the recorded phase; no effect reissued solely because no acknowledgement arrived.

| Phase | Contract and after-crash rule |
|---|---|
| OBSERVE | Read-only classification; healthy returns without effects. |
| FENCE_INTENT | Transaction closes admission and advances store/sink fence before stop; preserve exact source/profile, owner and row preimages, then stop exact enrolled invocation. After crash require readback of exact invocation exit and empty isolated cgroup, or proof stop was never issued; otherwise held. |
| START_INTENT | After fence proof record successor admission scope; start only held unit. After crash adopt only matching verified recovery-mode invocation or prove start unissued; conflicting/unknown owner remains held. |
| RESUME_INTENT | Successor validates complete paginated exact-thread prefix and quiescence, records one-shot native resume intent before effect, resumes exact ID without prompt. Continue only from matching definitive native ownership and loaded history readback; unknown effect remains held, no rekey. |
| COMMIT | One Store transaction CASes original preimages and successor proof, appends immutable predecessor→incident/evidence→successor chain, archives original and retires exact active slots only, or changes nothing. Duplicate commit is readback. Later successor failure starts a new incident under its committed epoch. |
| DEGRADED | Persist blocked phase and evidence, bounded qualified attempts (initial 15/30/60s backoff), then low-rate read-only checks. Positive changed evidence may unblock only the specific safe transition. |

Record trusted native history watermark (count/sequence and prefix digest) before each ordinary dispatch, retain it with the intent and update on confirmed completion. Full prefix match plus unique provenance-correlated post-watermark user item is required to attribute history; identical text alone is insufficient. Unexpected extra items, changes, partial history or unresolved active upstream work hold the affected thread. Local fencing is not upstream quiescence. Exact verified terminal suffix preserves actual native disposition; absence plus positive quiescence and qualified history retires as UNKNOWN, not nonexecution. No recovery reply publication even for a recorded terminal turn; disposition/status only. Preserve raw original TURN/hash/sequence, prompt, ingress and disposition; archive outcome separately and install permanent authenticated-message tombstone excluded from later admission and cleanup. Validators verify the append-only successor chain, not mutable bypass flags. N+1 is available only to genuinely new authenticated input after commit.

## Readiness, admission and chat receipts

No queue in this scope. Refuse new ingress while known offline, held or unready; record a durable authenticated rejection when the ingress/Store is available. At dispatch verify current epoch, native peer/owner and unexpired readiness under the same admission fence that serializes dispatch with revocation. Reserve once and persist submission intent before any wire start. If readiness is lost after check, classify by durable evidence: proved no authorization/admission is NOT ACCEPTED; durably admitted but proven not submitted is ACCEPTED / NOT SUBMITTED (retire without automatic retry); once submission may have crossed the wire, ACCEPTED / SUBMISSION UNCERTAIN unless exact native acknowledgement is recorded. Transport loss cannot be made atomic with Store state and must never cause replay. No forwarding to a known dead/unready generation and no rebinding a reserved dispatch to a replacement peer.

On authenticated ingress bind group, sender and transport message ID; atomically write the disposition and deterministic anchored receipt outbox intent. A connector-owned, non-Codex emitter publishes to the original authorized chat/reply anchor using stable receipt identities and authenticated sender context, with current recipient authorization. Show admission ACCEPTED vs NOT ACCEPTED separately from dispatch state NOT SUBMITTED / NATIVE ACKNOWLEDGED / SUBMISSION UNCERTAIN, and eventual retirement; never imply queued, acknowledged or completed from acceptance. If queueing is ever separately approved, show QUEUED explicitly, not as native acceptance. Receipt retries require sink dedup or positive evidence of nonpublication; use lookup rather than blindly duplicating uncertain sends. No visible receipt means UNCONFIRMED, not rejection; no reply proves nothing. Authenticated lookup by original message ID after outage reads authoritative disposition plus independent outbox publication status, distinguishes delayed/lost publication from durable rejection where proven, and returns UNCONFIRMED when no decisive record exists. Do not expose records to other senders/groups. Disposition notice explains UNKNOWN and no replay without advising a retry of potentially effectful work.

Persist and dedup host journal/status independent of chat/model. Deployment requires an explicitly enrolled host alert route whose operator delivery is demonstrated while admin is offline; concrete enrollment not established by this design. Escalate persistent hold there; options are continue hold or separately approve a supported evidence-acquisition/repair path; a human decision cannot declare missing quiescence proof or waive no replay. If evidence remains unavailable the exact thread remains degraded; do not substitute another thread.
