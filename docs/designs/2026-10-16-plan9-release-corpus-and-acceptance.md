## 3. Finite evidence protocol

These are proposed **acceptance evidence** formats, not native database schemas or APIs. JSON objects reject duplicate/unknown keys and nonfinite numbers. `ID` is a nonempty opaque identifier <=128 characters; `SHA` is40 lowercase hex; `Digest` is64 lowercase hex; `UTC` is a timezone-explicit UTC timestamp with fractional seconds allowed; `Count` is a nonnegative integer, not bool. `Artifact={id:ID,sha256:Digest,role:ID}` addresses a private immutable evidence file through the capture inventory, never a raw secret. `Authority={native_bead_id:ID,decision_ref:ID,context_digest:Digest,adr_revision:SHA}` is a projection of an actual readback, not authority minted by the protocol. All receipts use `format:1` and an opaque `run_id:ID`; actual IDs are allocated only by execution.

Five top-level receipt types have exactly the following keys (detailed row types below):

| Type | Additional exact keys after format/run_id |
|---|---|
| Entry | `type:"entry",created_at:UTC,release:Release,prerequisites:[Gate],design_authority:Authority,deployment_authority:Authority,workstream:Workstream,corpus:[Corpus],drills:[Drill],observation:Observation,evidence:[Artifact]` |
| Event | `type:"event",seq:Count,at:UTC,monotonic_ns:Count,boot_id:ID,segment_id:ID|null,previous_sha256:Digest|null,event:EventKind,actor:Actor,refs:[Artifact],detail:Detail` |
| Segment | `type:"segment",segment_id:ID,entry_sha256:Digest,start_event_sha256:Digest,end_event_sha256:Digest|null,start:UTC,end:UTC|null,duration_ns:Count|null,release_sha256:Digest,status:"running"|"interrupted"|"qualified",reason:"none"|"manual_intervention"|"release_change"|"observation_gap"|"clock_uncertain"|"invariant_failure",evidence:[Artifact]` |
| Assessment | `type:"assessment",at:UTC,segment_sha256:Digest,coverage:[Coverage],drill_receipts:[Artifact],archive_receipt:Artifact|null,unresolved:[ID],result:"not_qualified"|"qualified_pending_archive"|"release_complete",evidence:[Artifact]` |
| Archive | `type:"archive",at:UTC,assessment_sha256:Digest,repositories:[ArchiveRow],result:"held"|"complete",evidence:[Artifact]` |

An Assessment with result=not_qualified or qualified_pending_archive has archive_receipt=null. Only release_complete requires a nonnull archive_receipt resolving to an Archive with result=complete. Archive.assessment_sha256 references the exact earlier qualified_pending_archive Assessment, whose archive_receipt is null; the final Assessment references the Archive through its Artifact. This directed prearchive-assessment→archive→final-assessment sequence contains no self/circular hash. The final Assessment retains the same qualified Segment identity and revalidates the applicable evidence; an Archive cannot qualify a failed segment.

`Actor={kind:"automatic"|"operator"|"observer",identity_ref:ID}`. `Detail={code:ID,subject_refs:[ID],expected:ID,observed:ID}` contains only fixed runbook codes and opaque IDs, never prompts or credentials. `EventKind` is exactly `entry|approval|corpus_transition|automated_recovery|drill|source_change|manual_intervention|heartbeat|observation_gap|segment_start|segment_stop|archive|hold`. Sequence starts 0, strictly contiguous; first previous_sha256=null, subsequent values hash the exact preceding Event bytes. An observer may never retrospectively invent an event time; late collected authentic source evidence keeps its own timestamps in its Artifact and is marked with the collection event. The chain detects accidental missing/replaced files, not an untrusted host's forgery; ordinary trusted-host/controller operation is assumed, with separate native/journal evidence for important facts.

`Release={product_commit:SHA,product_tree:SHA,queue_commit:SHA,governing_adr:SHA,source_inventory:Artifact,loaded_inventory:Artifact,configuration_digest:Digest,policy_digest:Digest,managed_installs:[Install],capabilities:Artifact,tests:[Artifact]}`. `Install={adapter:"codex"|"claude-code",version:ID,install_digest:Digest,verification:Artifact}`. Exactly one selected install per reference adapter; running session install pins are recorded independently in Workstream. Inventories identify package/unit/executable/module/configuration versions actually loaded, plus binary/content hashes where available; a checkout HEAD or active service alone is insufficient. Failure to identify a required loaded component holds entry. Configuration capture is a sanitized allowlist plus digests of protected originals, not environment dumps or secret bytes.

`Gate={name:ID,source_revision:SHA,completion:Artifact}` rows cover each predecessor/required capability separately. `Workstream={id:ID,native_queue_identity_ref:ID,sessions:Artifact,claims:Artifact,journal_backup:Artifact,beads_backup:Artifact}`. Private session/claim artifacts enumerate real task IDs, worker identities, launch key/generation/native thread or session ID, role/profile, install/account-key opaque refs, relevant journal rows and supported claim readback. Runtime launch receipts, Marmot send receipts, native decisions and controller evidence retain separate namespaces. A stale worker's claim cannot be borrowed: supported authorized stopped-holder recovery precedes any real new claim; native history and original stopped session stay recorded.

`Corpus={bead_id:ID,origin_evidence:Artifact,migration:"retained"|"culled",rationale:Artifact,required_coverage:[ID]}`. `Drill={id:ID,scope:"isolated"|"release",authority_ref:ID,runbook:Artifact,receipt:Artifact}`. `Observation={period_seconds:300,max_gap_seconds:600,collector:Artifact,source_inventory:Artifact,retention:Artifact}`. Entry has nonempty corpus, gates, drills and evidence; every referenced Artifact resolves and hashes correctly. Existing completed drill receipts are admissible only for exact matching release/config/capability identities; changed inputs require renewed affected drills before entry. No placeholder or pending receipt satisfies a gate.

## 7. Contiguous259200-second stability clock

A qualifying segment is one **real contiguous 259200 seconds (72 hours)**, observed on the declared release/configuration/policy and fresh workstream, after entry. Release/source/configuration changes below mean the admitted running harness and its effective control policy, not normal code commits, task changes or WIP in the corpus projects. Ordinary reviewed corpus development is expected and does not restart the clock unless it changes that running acceptance release. Start/end are recorded actual events. duration_ns must be >=259200000000000 and derived from trusted elapsed-time evidence; UTC must agree within the captured clock-health bound. On one boot use its monotonic clock; crossing a reboot needs independently recorded trusted elapsed/boot correlation from the admitted observer. If that proof is unavailable, end the old segment as clock_uncertain and start a new one after recovery. No extrapolation, pause/resume accounting, adding separate segments or rounding partial days.

A **proposed acceptance collector**, not the existing local-health observer/babysitter, must emit a heartbeat at most 300s apart, referencing source-stream checkpoints and collector health. Plan8 d1's local-health observation does not prove this full acceptance stream. A later scoped acceptance-integration implementation owns the read-only collector and evidence evaluator; this design installs nothing. Its bounded input contract is the finite Entry/Event/Artifact inventory in §3: supported native task/decision readbacks, journal/recovery checkpoints, actual outbox/delivery receipts, admitted loaded-source/configuration inventory, clock/boot health and authenticated operator-intervention audit. It reads only declared authorized sources, uses the existing 300s scheduling seam or an explicitly admitted equivalent, and neither changes native/product state nor calls models. Final source-specific APIs, bounds, capture privacy and observed gap behavior must be reviewed and tested before entry; no provisional sibling design or unavailable audit API is assumed implemented. If any required transition/intervention source cannot be captured with verifiable continuity, record that proof gap and hold entry, or interrupt a running segment as below. No assertion that a heartbeat alone sees all human actions is sufficient. Each required stream must have durable continuity: native task/decision state transitions, journal/recovery events, delivery states and operator interventions. These are event-driven or existing bounded read-only checks, not model polling. A heartbeat does not substitute for missing source data. A delayed collection <=600s can remain continuous only if original durable records prove the entire missing interval without sampling, timestamp invention or an unobserved intervention. Any >600s observation gap, missing/unverifiable required records, missing sequence, unreadable observer or unexplained clock discrepancy interrupts the segment. No filling a silent period from later service uptime. These numbers are explicit design choices presented in §11, not historical ADR measurements.

During a running segment:

- **Allowed:** authentic approvals/denials to complete pinned cards; automatic policy-governed pickup/park/resume, retries with documented dedup, scheduled jobs, service-manager restarts and audited automated recovery already covered by the admitted release. All preserve task/session/review history, resolve uncertainty through real readback, and do not require substantive manual repair. Observing evidence without changing product state is not intervention. Normal model work/reviews under existing task authority are expected.
- **Interrupt and start a new segment only after recovery/new entry relation:** human steering/correction to get work unstuck, tmux attach/terminal dialog handling, manual rearm/reclaim/status/dependency/configuration repair, manual service/account action, deployment/install/source/configuration/policy changes, intentional fault injection, security invariant failure, or observation/clock uncertainty. An operational question/hold requiring human repair interrupts even if the actual repair has not occurred. Do not reinterpret an instruction or repair as an approval. Planned drill approval is not permission to count drill time as stability.
- **Fail-closed state is not automatically failure:** a genuine normal pending approval or native unmet dependency can wait while unrelated work progresses. Uncertain send/review/action state may automatically reconcile conservatively under the admitted design; otherwise unresolved uncertainty prevents qualification and human intervention interrupts the segment. No bypass to make a green dashboard.

Record the old segment_stop/interruption cause, prior evidence and actual elapsed time. Recovery never resets underlying review budgets, native task status/history, original session identities or grooming/nudge counters. A new qualifying segment has a new segment_id and complete revalidated Entry relation, preserving all interrupted segments. A source change needs affected regressions/reviews and deployment authority as applicable, not a freshly fabricated approval for unchanged design.

## 9. Recovery, rollback and approval-channel failure

Use the completed supported pause/stop/admission and native management paths, with actual authority and before/after readback. Stop affected new effects when identity/policy/action evidence is uncertain, retain worktrees/journals/spools/decision cards and notify through authenticated admind. No direct DB writes, borrowed worker identity, fake approved digest, queue latch removal, erased review round or assumed send success. CLI selection rollback applies on next launch; running sessions keep their recorded approved install. A deployment rollback has separate exact scope and preserves state and audit history.

If admind itself is unavailable, the existing authenticated audited operator recovery runbook is the break-glass path: diagnose read-only, preserve state, perform only already-authorized bounded restoration or direct operator action with real authority, then record readback and restored Marmot evidence. Do not require a new reply through the dead transport before diagnosis, and do not invent an automatic authority fallback or impersonated sender. Such recovery is disclosed substantive intervention and interrupts the clock. This design does not execute or expand break-glass authority.

## 10. Evidence retention, privacy and implementation acceptance

Keep exact original private logs/receipts, UTC+monotonic metadata, hashes, native evidence and interrupted segment history. The capture inventory maps Artifact IDs to actual private files and source origin. Public artifacts contain only redacted reports, digests and immutable code/design links; no credential values, login paths, host identities, full environment, native transcripts or raw secret-bearing messages. Sanitization must never alter the original privately retained evidence or turn an unreadable original into a PASS. Raw collection uses existing authorized access/retention policy, not permission to collect new secrets. Acceptance artifacts stay retained until explicitly retired under separately authorized retention policy; this design schedules no deletion.

Later implementation acceptance requires offline fixture tests of exact receipt types, hash-chain continuity, genuine-source bindings, clock boundaries at 259199/259200 seconds, gaps at 600/601 seconds, reboot/clock uncertainty, corpus missing rows, stale pins, archive dependency holds and retained interrupted history. Simulated time tests verify the evaluator only; a fake clock cannot prove live stability. Reuse existing recovery/deployment/managed-install tests and add narrowly scoped evidence validation; do not replace native gate algorithms. Exact final source-specific CLI/runbooks/observer integration must be reviewed before an implementation/deployment claims this protocol is executable. No test is run by this design task.
