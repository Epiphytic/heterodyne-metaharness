## 3. Closed evidence grammar and bindings

These proposed **acceptance evidence** formats are not native APIs. Objects reject unknown/duplicate keys, floats, bool-as-int and trailing data. `ID` is 1..128 ASCII letters/digits or `_:.+-`; `SHA` is 40 lowercase hex; `Digest` is 64 lowercase hex; `Count` is an exact JSON integer 0..2147483647. All nanosecond fields use `NS`, a canonical decimal **string** (0 or nonzero digit followed by digits), parsed to an integer 0..18446744073709551615 without float conversion; overflow refuses. `UTC` is `YYYY-MM-DDTHH:MM:SS.ffffffZ`, validated Gregorian UTC, no leap-second representation. `Artifact={id:ID,sha256:Digest}` resolves through the immutable private inventory; its named field supplies its role. No arbitrary role string selects authoritative evidence from generic evidence lists. For derived JSON identity digests only, canonical serialization is UTF-8 with lexicographically sorted object keys, no insignificant whitespace, ensure_ascii=true and no trailing newline; closed types admit no floats. Artifact and event-chain digests always hash the exact stored original bytes, not reserialization. Every referenced artifact is hash-verified; lists named evidence are supplementary only and never replace a mandatory field.
