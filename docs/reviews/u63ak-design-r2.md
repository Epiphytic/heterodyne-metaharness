[BLOCKING] **The census misses spawned children that have not acquired their lock — Design, lines 49–53, 74–78; “How it is proven,” line 97.** A child can be spawned, then descheduled before opening or locking `census`. Teardown acquires `LOCK_EX`, removes the directory, and returns successfully while that child remains alive. If the child is stopped before registration, it can survive indefinitely without being reported. I reproduced the admission gap with a gated child on Linux. The late-start rule provides eventual exit for a runnable child; it does not establish bounded disappearance. Specify registration that covers the interval from spawn through sleeper startup, with descriptor ownership and failure handling, and add deterministic tests paused both before census open and between open and lock.

[BLOCKING] **The proposed missing-PID regression cannot reach the sleeper on `ESCAPED` — Design, lines 90 and 105–109; `tests/test_admind_r13_summary.py:385`.** `ESCAPED` writes its PID before execing the sleeper. Giving it a nonexistent publication directory makes `os.open` fail before exec, so `started()` cannot name a sleeper. This test cannot provide its stated positive control. Specify a publication-failure path that actually leaves an admitted sleeper alive, and distinguish it from failure before sleeper startup.

[BLOCKING] **The audit-hook proof is not executable as specified for every path — Tests, lines 115–118.** The fork-based paths produce both `os.fork` and `os.exec`, rather than exactly one recorded event; an experiment confirmed both events. Moreover, `ESCAPED` is shell code: a Python audit hook does not propagate into independently executed interpreters or observe shell spawns. Specify a harness boundary and expected event sequence for each path. For fork paths, validate the directory before `fork`, rather than only when the child builds its exec argv. Otherwise an unset directory can still create a child despite the refusal claim.

[NON-BLOCKING] **The four r1 blockers are addressed in the revised approach, subject to the new proof defects above — Survey and “The fakes and scripts.”** The omitted survey sites are included, and the short-lived orphan writer has an explicit exclusion. Removing signals resolves the PID-reuse hazard; replacing marking with lifelines removes both argv-marking and matching contradictions. Removing discovery subprocesses addresses the earlier discovery-bound concern. The spawn-observation proposal addresses r1’s unmarked-child concern in intent, but needs the corrections above.

[NON-BLOCKING] **The lock semantics are compatible with Linux and macOS, but descriptor ownership remains a required invariant — Design, lines 49, 71 and 80.** Both platforms associate these locks with inherited open-file references. `O_CLOEXEC` prevents retention through successful exec; it does not prevent retention by a forked child before exec. `setsid` does not resolve descriptor inheritance. With the present path-based design, code under test closing its own descriptors cannot release locks independently opened by the sleeper. Preserve that separation when fixing admission, and test descriptor inheritance explicitly. See the [Linux manual](https://man7.org/linux/man-pages/man2/flock.2.html) and [Apple manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html). macOS execution remains unverified here.

[NON-BLOCKING] **Stopped survivors are detected failures, not completed cleanup — Design, lines 76–79 and 98; Tests, line 111.** A registered SIGSTOPed sleeper keeps its census lock indefinitely. Sessionfinish retries teardown but neither resumes nor reaps it; the 60-second cap cannot execute while it is stopped. Reporting and failing is consistent with the specified timeout policy, but the unconditional pytest-death claim is false for this case. State the exception and who handles survivors. Census release also proves lock release, not that an orphan has been reaped.

[NON-BLOCKING] **CI timing and preservation claims need narrower wording — Design, lines 74 and 93; Tests, lines 111–120.** Nonblocking flock avoids waiting for conflicting locks, but scheduling and filesystem operations still prevent a hard wall-clock guarantee. A two-second interpreter-start allowance can flake under load; synchronize readiness and use the normal cleanup budget. The existing assertions can remain unchanged with teardown after the test body, but this design-only diff does not demonstrate that. The no-signal test supports the wrapped APIs; it does not repair the census admission gap.
