3. **[BLOCKING] `file:1080–1096` — The install-root walk can follow a replaced directory symlink.** After `entry.stat(follow_symlinks=False)` identifies a directory, its pathname is queued. If that directory becomes a symlink before `os.scandir(folder)`, the scan follows it. A link to an outside directory containing innocently named files can therefore pass without ever triggering `ROOT_LINK_OUT`, contrary to r16’s requirement that the walk follow no symbolic link. **Fix:** traverse using directory descriptors opened with `O_DIRECTORY | O_NOFOLLOW`, verify identities, and refuse replacement races. Add a deterministic race test.

4. **[BLOCKING] `file:1063`, `file:1091` — Non-strict `realpath` does not establish successful resolution.** A self-referential symlink inside the root can resolve non-strictly to an unresolved pathname still inside the root and pass. Likewise, some resolution errors are suppressed rather than becoming `ROOT_WALK_FAILED`. This violates the stated fail-closed walk semantics. **Fix:** explicitly handle resolution errors and loops, mapping them to fixed refusal constants. If dangling internal links are permitted, distinguish missing targets from failed resolution.

5. **[BLOCKING] `file:1130` — Login names come from resolved filenames rather than the adapter contract.** Main canonicalizes login-file paths. If configured `auth.json` points to a file named `credentials-store`, this code checks for `credentials-store`, losing the required `auth.json` name check. An unrelated `auth.json` planted in the install tree then passes unless it aliases a known login inode. **Fix:** retain the adapter’s `login_names` in the spec and use those for name checks; use canonical account files separately for inode checks. Test a renamed symlink target.

6. **[BLOCKING] `file:1980–1993` — Deduplication suppresses necessary fresh observations.** Once a rate-limit value is saved, identical redraws are suppressed indefinitely. After the cache’s `stale_minutes` expires, a still-current exhausted window becomes unknown and eligible despite continuing status-line reports. The persistent synthetic home also carries this suppression across generations and account switches. **Fix:** scope deduplication to the launch generation and periodically resend unchanged observations before they become stale. Test both cache expiry and relaunch with identical values.

7. **[BLOCKING] `file:1873–1903` — Subprocess cleanup misses paths and can report success after a timeout.** Pipe validation and `timer.start()` occur before the cleanup `try`; failures there leave the spawned app-server unreaped. The timer also records no timeout verdict: if it fires after a valid response, the function can still return that response successfully. `proc.wait(5)` ignores the actual status, and the timer is never joined. **Fix:** enter cleanup protection immediately after spawning, track deadline expiration explicitly, check the process status under a documented termination policy, close pipes, and join the timer. Test timer-start failure and response/deadline races.

8. **[BLOCKING] `file:1862–1866`, `file:1556–1589` — Scratch cleanup and process disappearance are not proven.** The script calls `rmtree` without the required `lexists` confirmation. Inject cleanup failure and require an unsuccessful read.
