Note: cycle 1 of 3 of the btq-9yiku (hostread setuid holder) design review.

- **[BLOCKING] The UID invariant excludes more than delegated spawns.** Design lines **28–32, 101–109, 144**. A descendant can create a user namespace, then ask an existing helper outside the tree to invoke `newuidmap` with authorized subordinate UIDs. The descendant retains `NoNewPrivs=1`, but acquires namespace `CAP_SETUID` and can switch all its UIDs to a mapped foreign host UID. Rule 5 can then clear this actual descendant. The existing residual describes only holders spawned outside the tree; it misses outside assistance changing a descendant’s credentials. Explicitly scope and accept this residual, or close it. [`newuidmap`](https://man7.org/linux/man-pages/man1/newuidmap.1.html), [namespace mapping rules](https://man7.org/linux/man-pages/man7/user_namespaces.7.html).

- **[BLOCKING] The proof assumes an initially unprivileged launcher without establishing that premise.** Lines **27–30, 42, 144**. `no_new_privs` prevents privilege gains through exec; it does not remove existing capabilities. For example, an app-server inheriting ambient `CAP_SETUID` can call `setresuid(B,B,B)` despite the trampoline. Require or explicitly document the supported launch conditions: ordinary UID A, no retained host credential-changing capabilities, and no broader namespace mappings that permit foreign host UIDs. The unconditional “every task … keeps … uid A” claim is otherwise false. [Kernel guarantee and limitations](https://docs.kernel.org/userspace-api/no_new_privs.html).

- **[NON-BLOCKING] The trampoline closes the reported direct-exec scenario under those launch conditions.** Lines **36–52**. Setuid/setgid exec and file capabilities cannot supply the missing privilege. Ordinary saved-UID/fsuid operations cannot manufacture UID B when initial credentials are A. The supplied trampoline ran successfully in a bounded offline check: the executed process reported `NoNewPrivs: 1` and `PID == PGID == SID`. No app-server code runs before the barrier; normal trampoline startup introduces no descendant-spawn window. Explicitly distinguish direct `sudo` execution, whose setuid elevation is suppressed even with NOPASSWD, from already privileged services reached over IPC. SCM_RIGHTS transfers descriptors, not UID-changing capabilities by itself; ptrace remains subject to its separate permission checks. [Kernel documentation](https://docs.kernel.org/userspace-api/no_new_privs.html).

- **[NON-BLOCKING] The measurement supports recovery cost, but not the claimed arrival rate.** Lines **61–72**. Counts of currently surviving processes by age are a snapshot, not evidence of “3 … in any 10 s” or approximately 100 arrivals/hour. Retain the concrete recovery obstruction; qualify the read-failure frequency. Also weigh the requested hybrids: start-time filtering is already candidate (b), while session filtering misses `setsid()` descendants. Cgroup filtering needs an enforced membership guarantee; `systemd-run --scope` alone does not constrain externally delegated services.

- **[NON-BLOCKING] Two proposed tests need correction.** Lines **128–130, 141**. The default-path test cannot require `NoNewPrivs=0`: a test runner may already inherit `1`. Assert inheritance and direct argv instead. Patch `NO_NEW_PRIVS` in the dynamically loaded usage module, where the design places it. Also allow for `_end()` racing the failing trampoline’s exit: SIGKILL can produce an accepted `-9` status, leaving `ClosedOutput` rather than the asserted `ExitStatus`. Pin failure, absence of a reading, and safe cleanup deterministically.

The unchanged rule ordering preserves the btq-19fh0 pins and flakes2 behavior. No repository files were changed, and no live tests or privileged experiments were run.
