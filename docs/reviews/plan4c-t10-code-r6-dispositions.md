2. **fixed-bounded-native-seam** — Approval composition runs inline on the already-accounted HARNESS lane; no secondary worker.join exists. Queue.bd/show already have 20 s subprocess deadlines. wsd.btq.load sets 20 s GIT_TIMEOUT on its isolated imported queue module so commit-ref digest Git reads cannot wait forever. Finite subprocess limits are not an overall latency guarantee for unlimited recipe content or failing kernel/storage.

3. **fixed** — recover isolates every ordinary Exception from settling each approved row, logging type only and preserving the OPEN row. Unrelated rows and daemon startup continue; affected adapter protection remains. BaseException and unreadable global journal state are not swallowed.

4. **design-required-hold** — Approved 4ac749 Task 10 gives finite positive store readback/publish/failure recovery but no quarantine abandonment/clear command. A wrong-name or ambiguous store publication must remain OPEN and adapter-protected; neither elapsed time nor a caller-provided claim proves safe clearing. Root must obtain a scoped operator-resolution design/approval before adding a supported resolution command. No manual database/journal edit is proposed. This is an unresolved operational limitation, not claimed fixed or waived.

5. **fixed** — taint_current uses only the no-follow marker read, not HarnessOps.lock. tainted takes only alerts_lock plus the existing journal primitives; it does not wait behind approval network reads while the scheduler owns its parker lock.

6. **fixed** — Both synchronous and asynchronous startup run harness recovery before workstream recovery/pickup and do not advance posted approvals there. The existing independent harness timer advances approvals after startup.

Terminal row state does not authorize an effect if a late human approves; no publication occurs outside E13. Orphan-card withdrawal/lifecycle requires its own supported design and authority, retained as an operational limitation.

9. **deferred-performance** — Repeated in_use scans still have bounded per-store/journal/runtime work but multiply under prune/list. Snapshotting runtime selections across guard locks is a separate optimization with concurrency implications; retained unchanged and UNWAIVED, no claim of constant latency.

10. **fixed** — Clean provenance status includes ignored source files. Only ignored __pycache__/*.pyc entries are excluded; an ignored .py even inside __pycache__ refuses provenance. ## Required escalation for ambiguous publication

Root must publish this report and author response, and request genuine Marmot operator disposition under the current review policy or author a narrowly approved recovery interface. Existing install state, native authority, worktree/history, store receipt and adapter hold must survive. A future resolution must distinguish positive failed/published evidence from unknown effects and define who may abandon/quarantine physical store artifacts. No current command or automatic timeout authorizes clearing this hold.

The approval lifecycle limitation in finding 7 similarly needs a separately approved withdrawal protocol; wsd cannot add native mutations merely to make a list look clean. These are explicit release/activation limits for the controller, not hidden exceptions or fabricated consent.
