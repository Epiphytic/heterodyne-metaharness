**Verdict: changes needed.** I ran the built-in `code-review` skill with args `153` against the frozen worktree at head `ac6fad9fda5ab8fde4733bcde4ca9877b57620ba` (base `35650c0`), read-only. I also re-read the code behind the two most serious findings myself. Nothing was edited, published or run live.

### Blocking
1. **Regression for workers that never use control** (`src/heterodyne/session/server.py:218`). `_handle` used to parse hook traffic with `json.loads` and now uses `strict_json` for all of it. `strict_json` (`shim.py:327-330`) re-encodes the whole parsed value, so an escaped lone surrogate anywhere in a `hook_event` payload raises `UnicodeEncodeError`, and the server maps that to `FORBIDDEN`. For example, a truncated UTF-16 string inside `tool_input` now gets the worker's tool call denied. Duplicate keys and NaN, which were accepted before, now return `MALFORMED`. The strict codec should apply only to control operations and the token, not to existing hook intake.
2. **Concurrent intake returns a false refusal** (`control.py:115-122`). `locked()` opens a new fd and calls `flock(LOCK_EX | LOCK_NB)` with no retry. Two concurrent manager requests (`MAX_HANDLERS=32` allows this), or an observer calling `pending()` during intake, raise `BlockingIOError`. The second request then gets back `state:'refused'`, which looks final, even though nothing was journaled. It needs a blocking or bounded-wait lock, or a separate "retryable" result.
3. **`request_sha256` doesn't cover the manager's bytes** (`shim.py:537`). `run_control` sends `json.dumps(parsed)` rather than the raw stdin bytes. So the "exact bytes" pin and the returned `request_sha256` cover bytes the manager never produced. A retry with the same `request_id` but different bytes can also be accepted without hitting the "different bytes" conflict check.
4. **Intake after `close()`** (`server.py:379`). The control path doesn't check `self._closed`, unlike `_spool` and `_record`. A handler that is still running after `close()`'s bounded join can journal a request and ack `accepted` into a generation that has already been torn down.

### Should fix
5. **Exception types leak.** `_server` (`runtime.py:1083`) now calls `manager_owner.check()` and `ControlJournal(...)`. Their `RuntimeError` and `ValueError` escape `_rebind`, which only catches `OSError` and `KeyError`, instead of becoming `RuntimeUnavailable`. A failed owner check also stops worker sockets from coming up.
6. **`close_manager_control` closes every session server, workers included, but leaves them in `self.servers`** (`runtime.py:342`). `_rebind` skips any key already in `self.servers`, so if the owner is taken again those sockets are never served.
7. **Untranslated tmux errors** (`runtime.py:541`). `observe_session`'s ENDED branch calls `tmux.has_session` without the `TMUX_ERRORS` translation, so `TmuxError` or `TimeoutExpired` escape instead of `RuntimeUnavailable`.
8. **Read-only operations use up the capacity limit** (`control.py:249`). Status, Boundary, ReadOutcome and List are journaled as pending intents. Polling can therefore fill the 100-request limit and block a real Ask. Each intake also re-reads every file and recomputes every hash while holding the lock, which makes finding 2 more likely.
9. **Identical replay can be rejected** (`control.py:316`). The replay check compares a stored outcome that was read back from JSON with the live result dict. Tuples or non-string keys make an identical retry raise "immutable". Comparing the canonical encoded bytes would fix this.

### Expected given the stated scope, not a defect
- `own_manager_control` and `close_manager_control` have no production callers, so the transport can't be reached end to end. `source-scope.md` says this openly ("Hermes must own the runtime… before this lane is usable end to end"), so I'm not counting it against the PR. It does mean findings 1 and 5 can hit live paths before control can.

### Tests and evidence
- None of findings 1–4 is covered by the causal tests in `tests/test_manager_control.py`: surrogates in non-token hook payloads, two concurrent intakes, compact or non-ASCII raw bytes, and intake racing `close()`.
- The qualification evidence is described accurately. The 427-test pass belongs to the earlier a3da combination, and only the 62-test pass ran on the final merge. Neither counts as clearance for the regression in finding 1, because no test sends a surrogate in a hook payload.
