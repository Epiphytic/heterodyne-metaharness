1. **[BLOCKING] EOF does not establish that launches have finished.** [design-tmux-leak.md:24](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:24), [design-tmux-leak.md:45](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:45). Pytest can die after spawning a tmux client or launcher but before the server binds its socket. The watchdog skips the absent `pending` socket; the surviving launch can create it afterward. An empty-root removal does not reliably prevent this, especially while another socket keeps the root nonempty. Likewise, an inode check followed by a separate `tmux -S … kill-server` invocation leaves a replacement window before connection. R1 findings 1 and 5 remain partially unresolved.

   **Fix:** Make cleanup wait for a launch barrier that proves no creator can still bind or replace registered paths—for example, watchdog-owned launch transactions or supervised foreground servers. Establish exclusive namespace ownership during cleanup, or check identity and kill through the same server connection. Add deterministic SIGKILL tests before bind and between identity check and kill.

2. **[BLOCKING] The async SIGTERM handler violates the handler-preservation contract.** [design-tmux-leak.md:35](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:35). `loop.add_signal_handler` replaces an existing handler regardless of the configure hook’s guard. Removing it, including through `Runner` closure, resets SIGTERM to `SIG_DFL`; it does not restore the synchronous interrupt handler. I reproduced both behaviors with the repo’s Python 3.12.3. [CPython’s implementation](https://github.com/python/cpython/blob/3.12/Lib/asyncio/unix_events.py) confirms this. R1 finding 2 is addressed conceptually, but finding 8 remains incomplete; the helper naming and `before(h)` fixes are resolved.

   **Fix:** Install async cancellation only when this plugin owns SIGTERM, and restore the appropriate handler on every exit while preserving later replacements. Test custom handlers through an actual `run_with`, plus SIGTERM during a synchronous phase after one completed scenario. If clean interruption and exit code 2 are optional, removing the SIGTERM customization is simpler and equally safe for tmux cleanup once the watchdog is sound.

3. **[BLOCKING] Watchdog startup and shutdown lack an explicit lifecycle contract.** [design-tmux-leak.md:16](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:16), [design-tmux-leak.md:31](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:31). The displayed script path depends on the caller’s working directory. Successful `Popen` and a flushed write do not establish that the watchdog initialized successfully. Normal `pytest.main()` completion also does not end the interpreter, so relying on process exit for EOF can leave the watchdog waiting indefinitely. Pending-state discovery has no specified timeout.

   **Fix:** Use an absolute script path and a bounded readiness acknowledgement before permitting launches. At final session teardown, explicitly close the writer and boundedly wait/reap the watchdog. Bound every discovery command and isolate per-entry failures so one broken socket cannot block other cleanup. Test startup failure, execution from another directory, and `pytest.main()` returning to a live interpreter.

4. **[BLOCKING] Process registration is incomplete for pending starts and multiple panes.** [design-tmux-leak.md:21](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:21), [design-tmux-leak.md:24](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:24). Pending recovery obtains only the server PID, yet subsequent steps require both server and pane PIDs. The `up` message contains one pane PID, and `list-panes` without `-a` covers only the selected window. Existing fixture tests create multiple sessions on one server. [Tmux documents that distinction](https://man.openbsd.org/tmux.1#list-panes). Registration also needs to follow server restarts on the same path.

   **Fix:** Define the test-side interception point around every `new_session`, including failed starts and restarts. Recover all current pane PIDs in pending cleanup, use `list-panes -a`, and define how registrations update across server incarnations. Add pending-start, multiple-live-session, and restart tests.

5. **[NON-BLOCKING] ESRCH alone makes termination checks unnecessarily brittle.** [design-tmux-leak.md:26](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:26), [design-tmux-leak.md:49](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:49). `kill(pid, 0)` succeeds for an exited but unreaped zombie; I confirmed this locally. PID reuse can also make a dead recorded process appear alive. These conservatively produce `survived`, but can retain sockets and fail CI despite successful termination. The ten-second assertion budget also has no margin beyond the specified five-second command timeout plus five-second wait.

   **Fix:** Distinguish terminated processes from running processes, reap owned children, and treat uncertain identities conservatively. Use a monotonic deadline with scheduling margin and useful timeout diagnostics on both platforms.

6. **[BLOCKING] The proposed stand-in does not test the PID-verification mutation.** [design-tmux-leak.md:65](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:65), [design-tmux-leak.md:72](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:72). A plain bound socket makes `kill-server` fail or time out. Removing the PID-gone check would still preserve it because kill failure independently selects `survived`. Thus R1 finding 6 is improved by independent PID assertions, but remains unresolved for this safety check.

   **Fix:** Add a fake command runner that returns successful `kill-server` while registered processes remain alive; removing PID verification must then fail the test. Add the launch and handler cases above. The existing non-inheritable writer and default `close_fds=True` are sound for the tmux → fake_claude → hook exec chain, but exercise cancellation while a hook child is outstanding. Ensure the inheritance mutation actually passes the writer across exec; non-inheritability does not prevent bare-fork inheritance. [Python documents these rules](https://docs.python.org/3/library/os.html#inheritance-of-file-descriptors).

7. **[NON-BLOCKING] Repeating cleanup is not currently harmless for socket removal.** [design-tmux-leak.md:28](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:28), [design-tmux-leak.md:45](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:45). If pytest dies after killing the server but before unlinking or sending `gone`, the watchdog’s repeated `kill-server` can fail because the server is already dead. The unconditional “kill failed ⇒ preserve” rule then retains the stale socket and root.

   **Fix:** Check for already-established process termination before retrying the command. Permit inode-checked removal when termination is proven, even if a redundant kill fails. Gate a test immediately after kill and assert socket/root removal.

8. **[NON-BLOCKING] The production blast radius is small, but needs explicit compatibility checks.** [design-tmux-leak.md:10](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:10), [tmux.py:41](src/heterodyne/tmux.py:41), [tmux.py:64](src/heterodyne/tmux.py:64). Removing cmdline classification and pinning an exact socket root resolve R1 findings 3 and 4. However, production has two command builders, including the systemd launcher path; switching real fixtures to `-S` reduces exercised coverage of default `-L` behavior.

   **Fix:** Add `socket_path` as a keyword-only argument, share socket-selector construction, and test both selectors with and without a launcher. Preserve constructor compatibility, launcher failure behavior, and the rule that only starts use the launcher. Keep watchdog registration entirely in test code.

9. **[NON-BLOCKING] CI enforcement should cover every tmux skip mechanism.** [design-tmux-leak.md:42](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:42), [test_tmux.py:14](tests/test_tmux.py:14). R1 finding 7’s installation, explicit plugin loading, short paths, and bounded-handshake requirements are addressed. However, changing `needs_tmux` alone leaves the independent module-level skip in `test_tmux.py`. The process-group test also needs an explicitly isolated child group.

   **Fix:** Use one session-level failure when `HZ_REQUIRE_TMUX=1` and tmux is unavailable; retain ordinary local skip markers. Start subprocess pytest children in their own sessions before calling `killpg`, and give the watchdog controlled output descriptors so inherited capture pipes cannot obscure child completion.
