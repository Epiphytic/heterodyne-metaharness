1. **[BLOCKING] The serve factory breaks shared-server identity.** A2, [lines 154–156](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:154), specifies a fresh socket for the `cli.Tmux` monkeypatch. The existing test deliberately shares `h.tmux.socket_path`, then asserts `h.tmux.has_session(SESSION)` and tears down through Harness ([test lines 901–919](tests/test_admind_daemon.py:901)). The amendment would start a different server, fail that assertion, and target the wrong server during Harness cleanup. The independent cross-model review confirmed this defect. **Fix:** Return the existing guarded `h.tmux` in this test, whose launcher is already stubbed to `None`.

2. **[NON-BLOCKING] “Any prefix” is an unsupported descriptor-inheritance guarantee.** A2, [line 142](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:142). `pass_fds` preserves the descriptor through the immediate subprocess exec; a prefix can subsequently close it or launch tmux through another process with `close_fds=True`. The server would then lack SH. The current shell gate can preserve it, but arbitrary launchers cannot be assumed to. [Python subprocess documentation](https://docs.python.org/3/library/subprocess.html). **Fix:** Require test launchers to preserve the descriptor through tmux exec, constrain supported prefixes, and test a prefix that drops it.

3. **[NON-BLOCKING] The source scan provides narrower enforcement than the safety argument suggests.** A2, [lines 151–163](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:151). Rejecting direct `Tmux(socket_path=...)` misses raw `subprocess.run(["tmux", "-S", str(t.socket_path), ...])`, constructor aliases, and keyword unpacking. It also needs an explicit allowance for fully mocked production selector tests. The `_exec` extraction itself appears behavior-preserving if exception handling remains in its existing callers. **Fix:** Describe the scan’s limits, add negative cases for common bypasses and generated child scripts, narrowly exempt mocked selector tests, and pin existing exception mapping alongside argv/input/timeouts.

4. **[NON-BLOCKING] Final unlink omits the lock-identity check.** A3, [lines 182–184](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:182). A replacement immediately before this step lets the watchdog lock the original inode while unlinking its replacement, contradicting A6’s “nothing more is removed” regression. Ordinary guarded launchers never replace the file, so this is a promised-defense gap rather than an ordinary launch race. **Fix:** Under final EX, repeat the recorded identity check and honor any previous replacement failure. Test replacement in a lock-only directory.

5. **[NON-BLOCKING] The final-step explanation overstates closure.** A3, [line 186](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:186). Rename alone does not exclude operations that already resolved the parent; the base design explicitly recognizes that. Also, A4 permits a pre-opened launcher to acquire SH after final unlink and run a failing tmux command, so closure cannot mean “no guarded process remains.” **Fix:** State that EX excludes current SH holders, guarded pending binds remain serialized, late post-closure starts cannot resolve the original socket parent, and successful `rmdir` establishes filesystem closure.

6. **[NON-BLOCKING] The `O_CREAT` mutant is not established as equivalent.** A6, [line 249](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:249). On Linux, parent lookup and final-component creation are separate. An open can resolve the parent before rename, then create a replacement `launch.lock` after final unlink but before `rmdir`, producing `ENOTEMPTY`. Without `O_CREAT`, that final lookup fails. This is a source-based counterexample, not an executed reproduction. [Linux pathname-lookup documentation](https://www.kernel.org/doc/html/v6.8/filesystems/path-lookup.html). **Fix:** Remove the equivalence classification; add deterministic coverage of delayed final-component creation or record the surviving mutant as unresolved evidence.

7. **[NON-BLOCKING] Extend coverage for release and cleanup progress.** A2/A3/A6, [lines 141–145](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:141), 178, and 234–250. The core protocol checks out: tmux 3.4’s [fork/daemon path](https://raw.githubusercontent.com/tmux/tmux/3.4/proc.c) retains the descriptor; neither [glibc daemon](https://raw.githubusercontent.com/bminor/glibc/master/misc/daemon.c) nor tmux’s [macOS daemon implementation](https://raw.githubusercontent.com/tmux/tmux/3.4/compat/daemon.c) closes arbitrary inherited descriptors. [Pane](https://raw.githubusercontent.com/tmux/tmux/3.4/spawn.c), [job](https://raw.githubusercontent.com/tmux/tmux/3.4/job.c), and [pipe-pane](https://raw.githubusercontent.com/tmux/tmux/3.4/cmd-pipe-pane.c) children drop them before exec. Linux and macOS inherited flock semantics preserve SH after client exit, although explicit `LOCK_UN` releases the shared lock. [Linux](https://man7.org/linux/man-pages/man2/flock.2.html), [Apple](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html). No inherent deadlock follows because kills/death proofs remain outside EX. A survivor conservatively blocks all removals without weakening ownership, death-proof, or truthful-closure guarantees. **Fix:** Add an early-`LOCK_UN` mutant, real child-descriptor-release tests, and a mixed survivor/healthy-server case proving held removals do not prevent subsequent kills. Run the lifetime tests on both platforms; this review verified source, not runtime behavior.
