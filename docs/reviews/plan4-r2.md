R1 findings 2, 5–7 and 9–12 are resolved at the plan level. Findings 1, 3, 4 and 8 remain partially resolved, as detailed below. Gap 2 now matches approved r15. Gap 3 needs an ADR amendment only if relocation is rejected; gap 4 needs none. Gap 15 is correctly an operator host decision.

All locations below refer to `docs/superpowers/plans/2026-10-09-plan4-agents-and-sandbox.md`.

1. **[BLOCKING] :3905 — Landing still permits host writes through agent-controlled symlinks.** `_plain_tree` checks descendants but never checks its root. An agent can replace `private/objects` with a symlink; `os.walk(..., followlinks=False)` does not reject a symlink supplied as the root. `_write(objects / "info", ...)` subsequently follows that intermediate component and creates or replaces host-side `info/alternates` outside the private directory. **Fix:** anchor landing operations at a trusted directory descriptor, reject symlinks in every component—including `objects` itself—and fail on traversal errors. Add a test replacing the entire object directory with a symlink and assert no external file changes.

2. **[BLOCKING] :5971 — Probe namespace verification trusts an ancestor the agent can create.** `_cli_ancestor` accepts any process executing the CLI binary. Comparing the probe’s namespaces with that ancestor therefore permits both to inhabit an agent-created namespace. An attacker can overlay probe files, drop namespace capabilities, then start the real CLI and its probe there; the capability snapshots do not detect the earlier mount. Task 15’s control at :8794 merely verifies that `unshare` creates a different namespace, which does not establish protection. **Fix:** pin the trusted workload/launch namespaces from the host and require the CLI ancestor and probe to match them, or demonstrate that namespace creation and overlays are denied. Exercise an actual overlay plus nested CLI/probe attempt through the result channel. This leaves r1 findings 1 and 8 open.

3. **[BLOCKING] :143 — The btq Git exposure cannot be classified as a non-blocking follow-up without containment.** The plan explicitly leaves host btq calls following the agent-writable `.git` pointer while a session runs. An agent can point it at its private Git directory containing malicious configuration or hooks. Rewriting the pointer during landing protects only subsequent calls. **Fix:** gate backend enablement on hardening those consumers, or enforce that no unpinned host Git consumer touches an active worktree and that pointer restoration precedes every later consumer, including failure recovery. Add a malicious-pointer/configuration test. This implements existing §7 isolation; accepting the exposure would require an ADR/operator decision.

4. **[BLOCKING] :7727 — The lifetime backstop eventually abandons a running sandbox.** After 60 unsuccessful deletion attempts, the reaper exits. With wsd down and the backend unavailable long enough, nothing remains to stop the workload when the backend recovers. Moreover, deletion through an unavailable control service cannot establish the promised deadline bound. **Fix:** retain retries until confirmed deletion and provide an independent local/container deadline kill that does not require OpenShell’s control service. Test an outage exceeding the retry budget with wsd absent, followed by recovery. R1 finding 4 is not fully resolved.

5. **[BLOCKING] :6913, :2938 — The newly “durable” session transitions are only atomic replacements.** `write_record` uses `write_private` → `write_at`, which closes and renames without syncing the file or containing directory. A machine crash can lose the lifetime-stop reason, pending WIP mark or `unlanded` failure after the corresponding side effect occurred. The checkpoint tests establish process-crash replay, not durable ordering. **Fix:** sync the temporary record before replacement and sync its directory before continuing with stopping, landing or relaunch. Add verification of that ordering and recovery tests around landing and failure-record persistence.

REVISE
