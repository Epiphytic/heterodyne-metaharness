**Findings, most severe first. The production ones are carried over from round 1 unless marked new.**
1. **No-effect guard tests are weak** (`tests/test_deployment_profile_check.py:25`, `:88`). They patch `producer._prepare`/`_derive` and `os.open`, but `_profile_check` never refers to those names, and in the child `os.open` is patched only after imports have run. The review says they "can't fail", which overstates it: they would catch a call routed through the producer module's globals. But a direct import or a `builtins.open`/`pathlib` open would get past them. This fits the disposition: they are regression sentinels, not import-isolation evidence.
2. **No strict decoder or size bound on the owner side** for the checker's stdout (`deployment_profile_check.py:38`). The producer has `_check_output` for this; the checker has nothing equivalent.
3. **The result doesn't identify which profile was checked** (`:38`). It carries only the operation-original SHA and the packet SHA. `group_hex`, `publication_url` and `targets` aren't bound, so two profiles that share those digests but differ in those fields give identical results. This is plausible and low severity, since the owner already holds FD3.
4. **New: the refusal boundary catches only `Exception`** (`:52`). If the child gets SIGINT while blocked reading stdin, `KeyboardInterrupt` skips the fixed stderr line and `os._exit(2)`, so a traceback is printed and the exit code isn't 2. The producer `_entry` has the same gap.
5. **Heavy imports for a "pure" checker** (`:17`). Pulling `_bound_operation`, `_identity` and `_profile` from `deployment_producer_process` loads the card and publication modules into the checker process. Moving those three helpers into a shared module would fix this.
6. **Hardcoded descriptor slot** (`:48`). The checker uses a literal `3` instead of the existing `_PROFILE_FD` constant.
7. **Duplicated entry boilerplate** (`:43`). `_entry` copies the producer's argv check, read, write and refusal pattern almost line for line; `quality.log` flags this too.
8. **Test fixture differences** (`test:80`, `test:75`). The child fixture uses `os.dup` instead of `F_DUPFD_CLOEXEC` with a floor of 64, so if fd 3 is free the remap does nothing. It also doesn't stub the network calls (`_https`/`_rendering`) the way the producer child fixture does.
9. **Redundant work** (`:33`). There's an extra `_identity` snapshot on top of the one `_profile` already takes, and `_bound_operation` re-encodes the packet, then throws the result away.
