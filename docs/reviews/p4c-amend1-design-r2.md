- **[BLOCKING] §4.2, lines 128–131 — Cleanup can cross mounts and delete outside the home.** FD-relative, symlink-resistant `shutil.rmtree` does not prevent mount traversal. A directory mounted at `.codex/packages`, or beneath it, can have its contents deleted before removing the mount point fails with `EBUSY`. Require mount-ID checks on the executable-directory roots and every directory opened during deletion, including same-filesystem binds; refuse crossings before deleting their contents. Specify fail-closed handling of cleanup errors and a final emptiness check. Add mount-crossing and concurrent symlink-substitution controls. Ordinary symlink unlinking and hardlink unlinking do not delete the outside target’s contents; mounts are the missing boundary. Clearing disposable home state is compatible with E25 and need not taint the managed install.

- **[BLOCKING] §4.2, lines 187–190 — The migration gate must run the candidate validator.** Running the currently deployed `heterodyne config check` before merge can succeed because its `check_profiles` does not validate `args`. Moving the live checkout afterward can then prevent both daemons from starting. Require the T6 candidate checkout’s command, pointed at the deployed configuration with the service’s configuration-location environment, and record its successful result after any profile migration. That makes the proposed gate sufficient.

- **[NON-BLOCKING] §4.6, lines 236–246 — Pin S9-10 to the adapter-generated argv and environment.** The production new-session TUI includes `--dangerously-bypass-approvals-and-sandbox`; the listed command omits it and leaves `<socket>` unspecified. Generate commands through `server_argv`/`tui_argv`, retain the production bridge-to-rendezvous socket arrangement, and use a clean environment with explicit `HOME`/`CODEX_HOME`. Otherwise the spike can validate a nearby launch shape while T6 changes production. Also specify how the operator completes thread creation if it requires model traffic: the fresh network namespace has no external route merely because credentials are supplied.

- **[NON-BLOCKING] §4.4, lines 222 and 230 — Sentinel controls need a writable destination and a positive control.** Place each sentinel in a directory reachable and writable by the launched user, and demonstrate that executing the marker creates it. Without that check, an executed marker whose write is denied can leave no sentinel and falsely pass. The EROFS and `apply_patch` controls otherwise resolve r1’s evidence gap.

- **[NON-BLOCKING] §4.2, lines 128–131 — Record destructive cleanup.** Journal which executable directory was cleared and a bounded removal summary, without file contents. Silent deletion otherwise removes useful evidence when unexpected executable state is discovered. Preserve the launcher’s existing requirement to confirm the prior generation has ended before preparing the home.
