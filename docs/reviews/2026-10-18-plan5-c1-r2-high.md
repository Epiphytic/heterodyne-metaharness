**Verdict: REVISE.** This was a read-only static review of the full range `77e3c4a..bed3bb6`, including all R1 repairs. I ran no tests or probes and made no edits.

- **Most serious defect:** `add_dispatch` (finding 1) only overwrites the clock and deadline fields and trusts every other field the caller supplies. A reconciliation child can be inserted already settled, with a forged "succeeded" result, and then settle its parent. That undercuts the mandatory P1 #1–3 child-evidence fixes.
- **Absence attestation (P1 #2):** the parent dispatch's own retained "succeeded" report is still not compared before an absence settlement.
- **Unicode metadata:** the "closed grammar" is still a denylist. Hidden content can still get in through variation selectors, private-use or unassigned code points, or an unbounded flag tag run. Separately, ZWNJ/ZWJ in Persian and Indic text are refused even though that text is visible.
- **Oracles and fixtures:** I found no original test function deleted or skipped. The five oracle changes match the author's supersession table. The retained tests' clock fixture still echoes the caller's clock (finding 10).
- **Residuals and scope:** P1 #4–6 and P2 #10 remain unwaived residuals. Quality is 93 regressions with 49 gating, plus an incremental 49 with 26 gating; none are waived. My own findings on journal complexity are 5, 7 and 8. All adapters remain unavailable, and this review is not proof that a reserved review profile ran.

10 findings, most severe first:

1. `src/heterodyne/actions/journal.py:412`: add_dispatch overwrites only the clock and deadline fields and accepts every other caller-supplied Dispatch field. A reconciliation child can be inserted already settled with reconciliation_effect='succeeded', and an initial dispatch can be inserted with forged reconciliation_lookups or launch_attempts.

   Failure scenario: Parent dispatch is consumed and uncertain. The caller calls add_dispatch with msgspec.structs.replace(prepare_reconciliation(...), settled=True, cleanup_proven=True, reconciliation_effect='succeeded', reconciliation_cleanup_proven=True, evidence=DIGEST). The only checks are version==0 and state=='preparing', and _add_reconciliation never inspects the new child's settled or effect fields. The next parent lookup with reconciliation_key set to this child passes dispatch_transition's settled/cleanup/effect checks, and reconcile_lookup settles the parent 'succeeded' and releases resources without any ReconciliationReadback(read_only, invocation_finished). Likewise an initial dispatch with reconciliation_lookups=3 can be settled through DispatchRecovery with no real 1/5/30 lookups. Fix: rebuild the record with prepare()/prepare_reconciliation() from the sampled clock and require equality, as add_decision does with begin_decision.

2. `src/heterodyne/actions/journal.py:708`: The new absence-versus-success check only looks at retained reconciliation children. The parent's own retained worker report of effect='succeeded' (report() leaves it 'uncertain' when cleanup is unproven, and the effect is stored only in the dispatch-observation event) is never compared before an absence settlement.

   Failure scenario: Consumed claim, then a report with DispatchReadback(effect='succeeded', evidence=D, cleanup_proven=False) leaves the parent uncertain. Three 'unknown' lookups follow. The operator then submits DispatchRecovery(effect_definitively_absent=True). There are no succeeded children, so both the journal check and settle_dispatch accept it. The parent settles 'failed' and the request can complete as absent, even though the journal holds machine evidence that the effect succeeded. This is the same contradiction P1 R11 #2 requires to HOLD.

3. `src/heterodyne/actions/decisions.py:52`: The denial-metadata 'closed grammar' is really a denylist. Variation selectors (U+FE00-FE0F, U+E0100-E01EF, category Mn), private-use (Co) and unassigned (Cn) code points are accepted anywhere, and the black-flag tag run has no length bound. Invisible payloads that secret_value cannot see therefore still pass.

   Failure scenario: denial_reason = 'no' + ''.join(chr(0xE0100 + b) for b in b'sk-live-...') passes _metadata_controls_safe (Mn is not refused), passes the visible-character check because of 'no', and passes secret_value. It renders as 'no' and is persisted byte for byte as authenticated metadata. Likewise '🏴' + 64 tag characters encoding a lowercase-hex key + U+E007F passes, and the hex-key regex cannot match it. This reopens the hidden-text class from R1 #2.

4. `src/heterodyne/actions/decisions.py:53`: Refusing every Cf character (ZWJ allowed only between emoji) also refuses ZWNJ U+200C and ZWJ in ordinary Persian, Hindi and Malayalam text. Design §4 Q0 R3 #5 only requires refusing reasons made up entirely of whitespace or format controls.

   Failure scenario: An authenticated operator denies with the Persian reason 'نمی\u{200C}خواهم' (contains U+200C) or a Devanagari conjunct that uses ZWJ. begin_decision raises decision-reason-unsafe, add_decision cannot admit the genuine denial, and the request stays pending instead of being denied.

5. `src/heterodyne/actions/journal.py:637`: With unconditional sampling, observation.now is always set, so the observation is never EMPTY_OBSERVATION. Every transition (including decision and stage steps with no caller observation) now writes a '-observation' event that repeats the clock already written in the '-clock' event.

   Failure scenario: Each transition now costs 3 events (record, clock, observation) instead of 1–2, plus a capacity-recovery event during recovery. That spends the bounded MAX_EVENTS and the per-request TERMINAL_RESERVE=96 noticeably faster for the same lifecycle. The guard `if observation != EMPTY_OBSERVATION` is now dead. Write the observation event only when the caller supplied non-clock fields, or drop the duplicate clock.

6. `src/heterodyne/actions/judgement.py:445`: The permission branch of current_projection calls _bind_checked only to get the policy floor. It computes and throws away the full canonical binding digest (state, judgement DTO, privacy, model). _identity also calls validate_request_inputs directly and then again through request_denial_key, before assemble_envelope decodes the same tuple again.

   Failure scenario: Every permission projection does an extra full canonical encode and SHA-256 of the whole request state and privacy context, plus a redundant intent/origin/resolved/config validation pass. This adds to the unwaived P2 #10 repeated-decode cost. Split the floor evaluation from the digest, and drop the explicit validate_request_inputs call because request_denial_key already performs it.

7. `src/heterodyne/actions/journal.py:731`: Now that _sample_clock always returns a Clock or raises, several pieces of code are dead: `if sampled is None: raise` in _recovery_clock, `sampled: Clock | None` and its None guard in _clock_event, the `proven` parameter of _dispatch_lookup_clock (both callers pass True), the first `data = encode_record(value)` in add_dispatch, and `if floor is None` in current_projection.

   Failure scenario: Readers and the type checker still see optional-clock paths that cannot happen. A future caller of _dispatch_lookup_clock that relies on the default proven=False would silently skip clock provenance. This also adds to the unwaived journal complexity growth (28→31). Make the parameters non-optional and remove the dead branches.

8. `src/heterodyne/actions/journal.py:273`: The legacy denial-domain hold is copied into six places (get, add_request, _requests_for_approvals, request_transition, _identity, _denial_provenance). The new denial_domain field is also derivable: every legacy v1 denial_identity already fails comparison with request_denial_key, which embeds DENIAL_DOMAIN.

   Failure scenario: _requests_for_approvals repeats get()'s decode and domain check, and any new decode path (for example _reconciliation_children-style raw msgspec.json.decode of Request rows) must remember to add the check or it silently lets legacy rows into effect paths. A single strict Request decode helper used by every read would remove these special cases.

9. `src/heterodyne/actions/judgement.py:313`: This bug predates C1 but sits in a touched function. _bind_checked (and _bind around it) catch ValueError, and Refused is a ValueError subclass, so the fixed codes judgement-denied-intent, judgement-policy-refused, enrichment-repin-required and judgement-model-refused are always rewritten to judgement-binding-refused.

   Failure scenario: assess or bind with an action whose denial_identity is in prior_denials, or with a stale enrichment repin, raises Refused('judgement-binding-refused'), never the documented denied-intent or repin diagnostic. Callers cannot tell a denied intent from a malformed binding. P2 R4 #8 required stable fixed diagnostics. No test asserts any of these codes, so they are unreachable. Re-raise Refused before the generic except.

10. `tests/actions_journal_fixture.py:32`: Retained clock-provenance tests now run through a fixture that copies the caller's observation.now into the journal sampler. Tests named for clock independence, such as test_journal_checks_independent_actual_clock_not_reducer_clock (test_actions_p1_r3.py:162), therefore exercise the same caller-clock path P1 #1 removed.

    Failure scenario: If production regressed to trusting observation.now for consume-claim, ready or allocation timing, these retained tests would still pass, because sampled time and caller time are identical under the fixture. Only the new C1 tests in test_actions_c1_r1.py use an independent sampler. The retained test names overstate what they protect.
