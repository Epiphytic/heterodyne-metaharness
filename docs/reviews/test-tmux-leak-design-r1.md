1. **[BLOCKING] Cleanup requires a future test run.** [docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:66](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:66). After SIGKILL—or an interrupted SIGTERM teardown—the server survives until another pytest starts. If there is no next run, it leaks indefinitely. This does not meet the stated goal.

   **Fix:** Add cleanup outside the killed pytest process: a supervisor or watchdog that observes owner death and cleans registered servers within a bounded time. Define whether cancellation targets pytest alone or its process group; the cleaner must survive that cancellation scope. Keep startup sweeping as recovery.

2. **[BLOCKING] Raising `KeyboardInterrupt` does not guarantee asyncio cleanup.** [docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:10](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:10). Ordinary interruption during `await asyncio.sleep` and `subprocess.run` propagated and ran both finalizers in Python 3.12.3. However, deterministically delivering SIGTERM after asyncio dequeued a task wakeup caused shutdown to hang, with neither finalizer reached. Asyncio’s special SIGINT handling cancels the main task; your SIGTERM handler bypasses it. [Python’s explanation](https://docs.python.org/3/library/asyncio-runner.html#handling-keyboard-interruption) explicitly covers this problem.

   **Fix:** Use loop-aware task cancellation during async scenarios, translating cancellation to pytest interruption at the synchronous boundary. Treat the global raising handler as best effort. Retain independent cleanup for interrupted event-loop internals, teardown, and SIGKILL.

3. **[BLOCKING] The cmdline heuristic can kill a live concurrent run.** [docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:29](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:29). A live process executing `pytest.main()` need not have `pytest` in its arguments. Xdist’s execnet workers can likewise start as `python -u -c 'import sys;exec(eval(sys.stdin.readline()))'`; process-title rewriting is optional. These owners become “live non-pytest” candidates and their servers are killed. Conversely, unrelated arguments containing `pytest` preserve stale servers. [Execnet’s launcher](https://github.com/pytest-dev/execnet/blob/master/src/execnet/gateway_io.py) confirms the worker command.

   **Fix:** Remove cmdline-based permission to kill. Preserve every live or uncertain PID unless stronger ownership evidence proves otherwise. Prefer a registered run identity and an owner-held advisory lock, with descriptor inheritance controlled; this also avoids relying on PID reuse heuristics.

4. **[BLOCKING] The socket-directory rule is wrong on macOS and configured Linux hosts.** [docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:22](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:22); [tests/test_admind_daemon.py:104](tests/test_admind_daemon.py:104). Tmux normally uses `TMUX_TMPDIR` or `/tmp`; Python’s `tempfile.gettempdir()` can instead follow `TMPDIR`, including macOS’s `/var/folders/...`. Copying the existing cleanup rule copies its bug. Also, inspecting `dir/name` and killing with `-L name` does not ensure both operations target the same socket. [Tmux’s documented rules](https://man.openbsd.org/tmux.1#L) distinguish `-L` from an explicit `-S` path.

   **Fix:** Pin the test socket root at launch and reuse it for cleanup. Kill the exact inspected socket with `-S`. Test unset `TMUX_TMPDIR` with a different `TMPDIR`, explicit `TMUX_TMPDIR`, and macOS path resolution.

5. **[BLOCKING] Unconditional unlink can hide a surviving server and invalidate the safety checks.** [docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:33](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:33). A timed-out or failed `kill-server` does not establish server death. Unlinking afterward can leave a running server unreachable. Additionally, name, UID, and socket type do not prove test provenance; a matching non-test socket qualifies. The initial `lstat` also does not protect against entry replacement before unlink.

   **Fix:** Require registration in a dedicated test-owned namespace, validate the resolved directory, and serialize cleanup against creation and other cleaners. Preserve the socket after uncertain termination. Verify server death, then remove only the still-matching socket inode. Report failures separately from successfully killed servers.

6. **[BLOCKING] The proposed assertions can pass while the server leaks.** [docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:58](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:58). Once the socket is unlinked, `has-session` fails even if the server remains alive. Removing `kill-server` while retaining unlink could therefore pass the SIGKILL test. The two-owner test’s injected “pytest” answers also bypass the dangerous real classifier.

   **Fix:** Capture server and pane process identities before termination and verify their termination independently of socket reachability. Reap the owner before checking dead-owner behavior. Add a mutation that removes the kill operation, real programmatic pytest owners, PID-reuse cases, uncertain process inspection, and socket replacement. Exercise both the actual `run_with` path and the yielding tmux fixture.

7. **[NON-BLOCKING] CI and subprocess isolation need explicit contracts.** [docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:60](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:60); [.github/workflows/ci.yml:15](.github/workflows/ci.yml:15). CI does not explicitly install tmux, so required integration coverage can silently skip. A generated test outside the repository also will not automatically load `tests/conftest.py`. [Pytest discovers conftests from test paths](https://docs.pytest.org/en/stable/how-to/writing_plugins.html#plugin-discovery-order-at-tool-startup).

   **Fix:** Require tmux on both CI platforms; explicitly load the real cleanup plugin in child runs. Use short isolated socket paths, bounded readiness handshakes, bounded child waits, and parent-side cleanup on assertion failure. Include SIGTERM during launch and teardown, rather than only after readiness.

8. **[NON-BLOCKING] Lifecycle integration has avoidable traps.** [docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:15](docs/superpowers/specs/2026-10-08-test-tmux-leak-design.md:15); [tests/conftest.py:23](tests/conftest.py:23); [tests/test_admind_daemon.py:113](tests/test_admind_daemon.py:113). An imported `test_socket_name` helper can be collected as a test. The current configure hook returns early on Linux, so new setup must precede that return. `before(h)` also runs outside the cleanup `try`, allowing a callback that starts tmux to escape cleanup.

   **Fix:** Name the helper `new_test_socket_name`, install session setup independently of macOS temp configuration, and protect `before(h)` with cleanup. Restore SIGTERM only if this plugin installed—and still owns—the handler.
