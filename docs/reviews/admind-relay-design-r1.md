Verdict: REVISE

1. **[BLOCKING] [design:49](docs/superpowers/specs/2026-10-05-admind-marmot-relay-design.md:49), [plan:183](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:183): The writer does not guarantee “first recorded decision wins.”** The actual `approve-bead` pre-write check compares only the digest; status, labels, decision fields and policy are excluded. Two terminal/relay writers can read the same open bead and subsequently overwrite decisions. A content edit can also occur after the final check. **Fix:** define a shared per-bead serialization or transactional conditional-write contract, revalidate all decision prerequisites immediately before writing, and test concurrent approve/deny and edits after the final read. Narrow the guarantee explicitly for direct same-user `bd` edits outside that protocol.

2. **[BLOCKING] [design:78](docs/superpowers/specs/2026-10-05-admind-marmot-relay-design.md:78), [plan:431](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:431): Restart reconciliation lacks the intended decision.** `settle` requires approve/deny, approver, digest and `via_ref`, but the schema does not persist a decision attempt containing those values. Existing inbound storage retains neither command text nor enough information to reconstruct its reference. **Fix:** transactionally persist the action, operator, originating message ID/reference and expected digest before launching the child. Reconcile against that exact attempt. Specify child cleanup on cancellation, output overflow and unexpected exceptions, so recovery cannot reopen an ask while its writer remains alive.

3. **[BLOCKING] [design:162](docs/superpowers/specs/2026-10-05-admind-marmot-relay-design.md:162), [plan:65](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:65): Redaction breaks the “hashed content was shown” guarantee.** Arbitrary title, description and ask content can contain values that redact identically while authorizing different effects. `!details` also redacts them. An unterminated private-key marker can consume subsequent card text, including instructions; the claim that redaction never removes lines is false. **Fix:** refuse phone approval when redaction hides semantic approval content, with a host-review fallback. Format known machine digests deliberately, protect fixed framing, redact the complete text before splitting, and test hidden effect text and unterminated markers. Typing a prefix confirms intent toward a card; it does not recover invisible context.

4. **[MAJOR] [design:55](docs/superpowers/specs/2026-10-05-admind-marmot-relay-design.md:55), [plan:405](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:405): Settlement misreports partial writes and cannot establish gate acceptance.** An open bead can already contain approval metadata because update, comment and close are separate operations. Returning it to `open` with “nothing recorded” permits a conflicting retry. Conversely, matching closed decision fields do not prove `approval_valid`: that function also checks timestamps, review evidence, ADR pins, denial fields and every `*_digest`. **Fix:** introduce a partial/uncertain outcome that blocks new decisions pending reconciliation. Have `--json` expose the actual gate verdict and reasons, and distinguish “decision recorded” from “gate accepts,” including after timeout or restart. Replace the test that requires partial writes to be reported as nothing recorded.

5. **[MAJOR] [design:54](docs/superpowers/specs/2026-10-05-admind-marmot-relay-design.md:54): `work_lock` does not freeze all authorization state.** Administrative removal waits for it, but `on_event(GroupStateChanged)` can latch immediately, and subscription/group checks can invalidate authorization while the decision subprocess runs. The parent’s check before launch cannot prevent subsequent writes. **Fix:** define the authorization commit point explicitly. Either an already delegated decision may finish after latching, with that residual risk documented, or authorization loss must cancel the child and produce an uncertain read-back outcome. Test latching and observation loss during the decision.

6. **[MAJOR] [design:51](docs/superpowers/specs/2026-10-05-admind-marmot-relay-design.md:51), [design:228](docs/superpowers/specs/2026-10-05-admind-marmot-relay-design.md:228): Complete delivery is required only for shortened cards.** An unshortened card may span several transport chunks, yet replying to its first sent chunk suffices while remaining context is pending or failed. **Fix:** require all expected card chunks to be sent before approval, or a complete details delivery for that operator. Persist the expected chunk count so an empty or incomplete set cannot satisfy the check. Test delayed and failed final chunks.

7. **[MAJOR] [design:218](docs/superpowers/specs/2026-10-05-admind-marmot-relay-design.md:218): Admission checks race across asynchronous reads.** Concurrent socket handlers can all pass the open-count/hourly checks before awaiting `--json`, then exceed both limits. Latching during that await is not rechecked before insertion. Posting also changes ask state despite being described as “only reads,” and can create another actionable ask while one for the bead is deciding. **Fix:** bound concurrent subprocess admission, reserve/recheck limits transactionally, recheck latch state before enqueueing, and define the same-bead behavior during `deciding`. Add concurrent-post tests.

8. **[MAJOR] [plan:253](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:253): The generalized socket interface is incomplete.** Existing `CtlServer` validation and audit paths access `req.op`/`req.name`, absent from `AskRequest`. The proposed refusal callable is absent from the signature and construction call; peer PID acquisition and delivery to `on_ask` are also unspecified. **Fix:** provide exact validation, refusal/failure, audit and peer-context interfaces, wire them into the construction example, and test malformed requests and handler failures while preserving existing ctl responses.

9. **[MAJOR] [plan:257](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:257): Larger requests do not solve larger responses.** Existing `ctl.request` uses `open_unix_connection` with its default 64 KiB reader limit. A legal ask with several 16,000-character answers already exceeds it; `list` can be much larger. **Fix:** define response byte limits and matching client framing limits. Use summary-only list entries and bound or paginate answer retrieval. Test large `get`, `wait` and `list` responses, not just a large request.

10. **[MAJOR] [plan:101](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:101): The JSON digest contract excludes real malformed beads.** `btq.ask_digest` returns `None` when `metadata.ask` is missing or malformed, whereas the contract requires a full digest and `Readout.digest` is a string. Such beads become decoding failures instead of returning the promised grooming gaps. **Fix:** make the digest nullable for invalid readouts, reject them through `postable`, and test missing/non-object asks and malformed root data.

11. **[MAJOR] [plan:55](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:55): The prescribed btq gate is not offline.** `tests/test_queue.py` does not automatically skip without a server: its setup constructs a real Queue, and tests create, update and close shared-server beads. Running discovery can therefore mutate the real queue. **Fix:** prescribe an explicitly selected offline suite, or add an opt-in integration-test gate before discovery. Assert that the new tests use only temporary configuration, credentials, repositories and fake executables.

12. **[MAJOR] [plan:448](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:448): The approval integration fixture starts latched.** Supplying two policy operators to a fresh Harness leaves confirmed operators unset; startup deliberately latches that configuration, and the fake defaults to two members rather than three. The happy-path assertion also expects the final logged invocation to be the decision, although mandatory read-back makes it `--json`. **Fix:** seed confirmed membership and expected count, configure the fake count and removal policy fixture, and select the decision invocation by its arguments. Provide an executable shared fixture for the listed scenarios.

13. **[MAJOR] [design:266](docs/superpowers/specs/2026-10-05-admind-marmot-relay-design.md:266): The ADR delta omits the §5.9 exception.** The design explicitly removes gatekeeper judgement, but the proposed ADR amendment does not waive that mandatory sufficiency step. Terminal readout capture also does not supply clickable forge permalinks required wherever a forge exists. **Fix:** provide a specific interim §5.9 amendment identifying the waived judgement/enrichment workflow and its replacement, and either supply pinned phone-accessible links or document an approved exception. Correct the member-swap wording too: an unfamiliar swapped-in key does not become a configured approver merely by preserving the member count.

14. **[MINOR] [plan:160](docs/superpowers/plans/2026-10-05-admind-marmot-relay.md:160): Task 1’s fixture hides repository-selection inconsistency.** `approve-bead` invokes `bd -C btq.REPO`, while Queue resolves `BTQ_REPO` into `queue.repo`; the fake strips `-C` without checking it. The suggested eager-Dolt workaround is unnecessary because Queue construction performs no connectivity probe. **Fix:** use the resolved repository consistently, assert its path in the fake, and remove the speculative lazy-Queue branch.

Summary: Revise the write, recovery and display contracts before approval; the deployment/restart gate is sound, but the implementation plan is not yet safely executable offline.
