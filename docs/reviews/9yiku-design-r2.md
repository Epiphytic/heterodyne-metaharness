- **[BLOCKING] B1 is not fully closed: current allocations do not bound existing namespace mappings.** Design **lines 74–77, 132, 170**. A namespace legitimately created using range R retains that mapping after R is removed from `/etc/subuid`. A new app-server descendant can join it, switch all UIDs into R, and have environ refused; the scan reads the updated file, considers it foreign, and clears the live holder. A missing file has the same problem. Conversely, adding R after the scan’s range snapshot permits an outside helper to map R before the holder is judged. Neither scenario requires the arbitrary privileged mapping described in residual 2. Kernel mappings are established independently of subsequent allocation-file reads. Close this gap, or explicitly accept historical mappings and allocation-change races as PoC residuals and qualify the invariant. [Namespace mapping rules](https://man7.org/linux/man-pages/man7/user_namespaces.7.html), [newuidmap authorization](https://man7.org/linux/man-pages/man1/newuidmap.1.html).

[Capability rules](https://man7.org/linux/man-pages/man7/capabilities.7.html), [no_new_privs guarantee](https://docs.kernel.org/userspace-api/no_new_privs.html).

[UID/GID mapping rules](https://man7.org/linux/man-pages/man7/user_namespaces.7.html), [subuid format](https://man7.org/linux/man-pages/man5/subuid.5.html).
