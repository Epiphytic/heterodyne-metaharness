## Trusted configuration

Add optional `worktree_inspection_roots` to the operator's existing canonical queue policy JSON at the effective OS user's passwd-home plus `.config/beads-task-queue/policy.json`. Resolve home with `pwd.getpwuid(os.getuid()).pw_dir`, not HOME, BTQ_CONFIG_DIR, BTQ_POLICY, a task field or caller argv. An internal `_trusted_identity()` seam returns `(uid, canonical_passwd_home)`; production derives it only from the OS. In-process offline tests patch this seam to disposable identity/home, never environment, argv or task data. Existing Handoff/management fixture HOME and this mocked identity must agree, with a guard asserting no open/read targets the real passwd home. Subprocess tests cannot use the mock and must not exercise operator policy reads. Only this new setting uses the fixed trusted policy source; existing unrelated policy/location behavior remains unchanged. The existing `load_policy` environment override therefore cannot grant inspection roots. No new CLI/env roots option or caller-supplied policy dictionary is introduced.

The setting is a list of at most 8 unique absolute canonical directory strings. Absent file or absent key means no additions: the default remains the OS user's `repos` directory. Empty list has the same meaning. Default membership is always retained; configuration cannot remove it. Root `/`, passwd-home itself, and ancestors of passwd-home are forbidden additions. Reject empty/relative/dot-dot/NUL/non-string/duplicate paths, symlink components, nonexistent paths and paths whose realpath differs from their supplied spelling. Every configured root must be an existing directory owned by the effective UID, not group/world writable. Do not create roots on inspection. The setting authorizes this trusted same-UID controller host, not arbitrary callers or hostile same-UID code.

Read the canonical policy as a bounded regular file (64 KiB maximum), with O_NOFOLLOW and strict JSON duplicate-key rejection. Its final file must be effective-UID-owned and not group/world writable. Walk its existing ancestor components without following symlinks; each must be root-owned or effective-UID-owned and not group/world writable. Missing canonical file permits only default. Normalize every other reader failure, including `_read_nofollow` filters/too-large and ancestor/type/ownership/JSON failures, to `Uninspected("inspection-policy")`; do not expose those underlying categories for policy files. Never fall back to environment policy after failure. Do not print policy contents, credential paths or raw parser exceptions. The default is the realpath of passwd-home/repos, required to be a directory owned by the effective UID. Preserve its existing lack of group/world-mode rejection: this host has repos mode 0775, so the default has a weaker shared-group-write residual than configured additions. No chmod is required or authorized. Missing default contributes no admitting root and yields outside-roots if no configured root admits the target; wrong type/owner refuses inspection-policy. Default symlink spelling is resolved as today; configured additions still forbid symlink components. HOME changes cannot expand either root class.

Example additive deployment delta on this host:

```json
{"worktree_inspection_roots":["/home/openclaw/.hermes/workstreams"]}
```

This is a merge into existing policy, not replacement of approvers/admind settings. Retain all unrelated keys and exact authority configuration. Human deployment approval must disclose that this root covers all controller run directories underneath it, not just Y. It permits reading owned, associated worktrees there; it does not permit native writes or executing their hooks. A narrower future root may be chosen by genuine deployment scope, with its exact config bytes disclosed.

## Inspection and freshness

Preserve early no-recorded-worktree and other-host outcomes without reading the root policy; their facts carry no admitting-root marker. For a recorded local worktree, load and validate the trusted root setting, then resolve both recorded worktree and repository with the current strict realpath behavior. Strict parsing is an intentional availability dependency for all local inspections, including default-only checkouts: a malformed canonical policy blocks them even if unrelated approval consumers still accept it. OPS must document a read-only policy preflight using the same reader, reporting only valid/absent or inspection-policy without contents, native writes or cards; deployment cannot proceed without this preflight. Require each resolved directory to be inside at least one admitted root using commonpath boundary equality, never string prefix. Preserve effective-UID ownership, actual directory and all current Git common-dir and registered-worktree association checks. An ordinary worktree alias may resolve to an admitted actual directory as today; an alias into an unadmitted actual location still refuses. No move, symlink or receipt rewrite is a recovery mechanism.

Keep existing sanitized Git subprocess environment, private temporary Git HOME, no hooks/filters/textconv/external diff, bounded status/diff/untracked/history and partial-clone refusals byte-equivalent. Do not introduce Git config from the new policy. The recorded native worker/repository/base/path, holder cessation, locks, valid design pins/blockers, pause/quiescence, authenticated per-operation decision and uncertain-write rules remain required.

Successful local inspection adds `inspection_admission` with `{version:1,uid,home,worktree_root,repository_root}` and `inspection_policy_sha256`. Each root is the canonical admitting root string; choose the longest containing root, lexical order as a deterministic tie-break. Hash the admission object as SHA256 of compact UTF8 sorted-key JSON with ensure_ascii=false and no final newline. Bind only these admitting roots, never the entire configured root list or unrelated settings. Reordering or adding a disjoint root leaves existing facts identical; removal or a change of an admitting root invalidates them. Handoff and management cards add one budgeted literal line naming the worktree/repository admitting roots (label default where appropriate) and the policy digest prefix; oversized cards retain the existing whole-card refusal. The complete values remain in facts. No paths from untrusted task prose become new clickable links.

Reload before ordinary plan/post/pre-write fact comparisons; changed admission requires a newly authorized request only after safe termination/reconciliation of the old one. Never automatically repost or repeat a native write. Keep HANDOFF_FORMAT 1. A non-terminal saved record with successful local worktree evidence but no admission/digest is legacy: refuse before post/apply/resume with a dedicated legacy-inspection-policy hold, retaining all receipts. Do not mistake absent/other-host facts for legacy local inspections. Terminal done/aborted format-1 records remain readable and allow later fresh requests; no format bump or rewriting old evidence.

Management `_observed_bead` must obtain the exact existing canonical bead projection without invoking worktree inspection (extract/reuse the bead-only projection underlying evidence_snapshot, not a weakened comparison). On resume, reconcile an already-issued step against this projection before any policy-dependent pre-write validation, with no native mutation: matching readback marks the step verified durably; mismatch remains unknown and never reissues it. Every next unissued step still requires fresh full inspection/admission, existing endpoint/approval/pause checks and expected facts before issue. Policy drift can therefore hold further work but cannot prevent observing an issued result. This is not authority to finish the remaining replacement after policy drift; retain partial edges and receipts for supported reconciliation under actual scoped operator authority. Handoff issued-state observation likewise must remain possible without authorizing a new write under changed admission; its existing native expected-state checks are preserved. Test actual crash/resume seams, not only new plans.

Root-policy edits, upgrade and rollback are supported only with pickup paused, no effectful operations and no non-terminal Handoff or management records in the shared state, including issued/unknown/replacing records; never abandon them to satisfy this precondition. Stage the compatible reader alongside the original artifact if reconciliation is required. A violation still holds rather than providing an automatic replay bypass. Stale policy under concurrent filesystem mutation remains ordinary trusted-host TOCTOU risk; preserve final checks, no kernel confinement or atomic filesystem snapshot claim.
