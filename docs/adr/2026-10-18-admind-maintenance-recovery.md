# Authenticated retirement of a proven pre-effect admind attempt

Design task btq-vx7l6; author Codex. Draft for ONE actual Claude Opus HIGH design review, then one incorporation and separate human Marmot approval. No implementation, deployment or changed approval pin is authorized by this document.

## Problem and retained contracts

The approved queue-maintenance design b13fd101011102dde43299d5f530d28f9f049118 §4 preserves the original Attempt and inbound message after an exact proven-pre-effect maintenance HOLD. Fresh authority/card/native checks prevent stale approval replay. Actual exjsy R1/R2 reviews found that changed-card, revoked-authority and native-conflict cases can occupy all 20 open ask slots permanently. The current repair suspends their retry rather than polling forever, but offers no supported retirement command. CLI cancellation only accepts open/answered asks. Existing command grammar has !asks [bump|repeat], not a recovery verb. Existing request/decision recovery elsewhere does not authorize retirement of this overlay.

This addition permits only authenticated terminal retirement of an exact provably not-issued attempt. It never approves, denies, replays, changes policy, clears a queue fence, reallocates ownership, repairs an uncertain write, creates a replacement ask or treats an old decision as current consent. Native first-valid-decision rules, genuine design/deployment approvals, immutable histories and the existing group/transport authority boundary remain intact. Same-UID DB tampering is outside the existing trusted-host boundary.

## Operator interface

Add deterministic `!asks retire <ask-id> <attempt-message-id> <full-context-digest>` as a reply to the original approval card or its threaded maintenance notice. IDs use the existing exact bounded grammar; digest is exactly 64 lowercase hex. No optional/latest, prefix match, bulk mode, free-text authority, reaction alias or LLM inference. Commands are bounded to 1024 UTF-8 bytes; malformed commands cause a bounded diagnostic and no mutation beyond their ordinary durable inbound/audit receipt. HELP and !asks display the exact syntax and held attempt identity with full digest in details; ordinary summary remains bounded.

The command is a new authenticated operator decision to retire a pending local delivery, not a denial of the native design. The operator need not be the original sender, who may have been removed. The current authenticated sender must be a configured authorized operator, present in the correct group with current verified membership/authority, with current policy permitting control. Replayed or unverified transport input, stale membership, wrong thread/card/notice, suspended observation, changed policy, malformed metadata and missing sender mapping refuse. Recheck the same current authority immediately before the local commit. Message bodies cannot supply sender privilege. This command never enters the manager/agent input path.

## Exact eligibility and proof

Under the existing daemon serialized admission and Store transaction/CAS, require the ask to remain deciding with exactly the named current Attempt, immutable original message/ref/operator/action/digest, and exact full stored card digest. It must retain a maintenance overlay and a complete exact receipt for the most recent child invocation that returned the fence's closed exit-75 not-issued JSON. No invocation may have begun since that receipt. Both retryable pending-maintenance and suspended maintenance-held overlays are eligible; maintenance-issuing, uncertain, settled, superseded, unknown/corrupt and missing-proof states are not.

Implement an additive bounded proof record, atomically with defer_maintenance: version1, ask/attempt/card digest, monotonically incremented per-attempt invocation generation, exact closed HOLD envelope, exit75, bounded raw stdout SHA256, captured coordinator capability/adapter identity, receipt generation and no-later-issuance assertion derived from the durable issuing marker. The child adapter validates the existing precise envelope; a plain string, process error, timeout, arbitrary75, truncated output, unknown version, extra keys or post-effect failure is not proof. Record issuing intent before each child; delete/invalidate prior retry entitlement and proof in that same transaction. No successful publication of the next issuing intent can leave the old proof eligible. Receipt publication and issuing intent failures preserve the existing uncertain/held path and never authorize retirement.

Pre-proof historical overlays are explicitly ineligible until independently retained exact original receipt plus invocation correlation establishes the same facts through a separately reviewed migration. A fresh native undecided read alone cannot prove absence of an earlier unknown issuance. There is no auto-backfill, synthetic receipt, timeout proof or operator assertion bypass. This feature therefore cannot claim to clear every historical possibly-issued hold; it provides the supported exit for the new fully recorded proven-pre-effect class. Existing matching native decision reconciliation remains available for genuinely issued attempts and does not become this command.

Before commit, take the existing read-only approve-bead snapshot using the retained source/adapter admission; native read must succeed and be parseable/current. An undecided native approval may be retired locally. A known conflicting terminal native decision may also retire this local pre-effect attempt: retain its exact different provenance as a conflict and explicitly say that the native decision remains unchanged. A native decision exactly matching the original Attempt follows existing native reconciliation instead; it is never mislabeled not-issued or retired by this path. Unknown/unreadable/read timeout or malformed native authority remains held and can be retried by a new authenticated command after inspection. No native mutation is made by any of these branches.

## Atomic retirement and races

The local commit compare-and-sets the ask status, current Attempt identity, full digest, overlay/proof/invocation generation and current authority epoch against the values actually checked. On success, in ONE existing Store transaction: mark the original attempt settled as pre-effect-retired (preserve exit75 and original data), set ask status cancelled with outcome maintenance-retired, retain decided_by as the retiring authenticated operator with a distinct retirement record rather than native approval provenance; clear asks.attempt and remove only its exact maintenance overlay/proof; mark original inbound consumed with an explicit retirement mapping; record the recovery command ID/sender/thread/ref/full digest, original attempt identity, proof hash, before/after state, native readback hash/conflict and retirement reason; queue exactly one deduplicated threaded acknowledgement. No other ask, historical message, native decision, ownership/dependency or policy changes.

Store uses an additive bounded recovery-receipt table keyed by recovery inbound message ID and an exact unique ask/attempt identity. Keep original ask_attempts and immutable proof/retirement evidence, subject only to the existing retention policy. Never delete history to free active capacity. Repeated delivery of the SAME authenticated command returns its existing receipt, without new notice/native calls/effects; a DIFFERENT command for an already-retired attempt reports the existing retirement and changes nothing. Ordinary command inbound acknowledgement follows existing idempotent delivery behavior.

Receipt/notice and retirement state either commit together or all roll back. Restart after commit resends only the existing outbox item. SQLite or outbox failure before commit leaves the original attempt/proof/inbound untouched. Crash after native read but before commit does not authorize a retry of the decision child. The daemon actor's serialization excludes retry launch during the read/commit interval; the Store CAS independently rejects another process or changed generation. A stale process cannot overwrite newer issuance, receipt, ask or authority. Invalid generation or unknown DB schema fails closed with bounded diagnostic.

## Capacity, escalation and rollout

This operation needs no new open ask and is available at MAX_OPEN=20 or maintenance capacity128, even when every slot is suspended. It needs only existing bounded Store/outbox/audit resources; if those are unavailable, return a precise storage HOLD and preserve history. Local receipt storage is finite under existing retention; it cannot be claimed infinitely available. The native approval JSON read stays read-only under queue HOLD and must not instantiate a writer. No dependency on approving a NEW native recovery bead while the fence is held is introduced.

Held notices distinguish retryable maintenance, permanently suspended native/card/authority conflict, issuance-unverified and storage failure. They show exact recovery syntax only when the proof makes retirement eligible. For ineligible ambiguous or historical records, link the retained exact diagnostic to the existing human escalation channel and state which independent native/issuance evidence is missing. Never instruct operators to edit SQLite or manufacture authority. Broader recovery of unknown native effects remains outside this narrow addition and may require a separate reviewed design/explicit administrative action.

Sequence: approved exjsy proof/issuing repair and this additive recovery implementation -> actual cross-model code review and offline acceptance -> compatible queue/Hermes/admind closure composition -> exact deployment card with this immutable design link and explicit deviations -> approved coordinated deployment. Do not deploy exjsy under a claim that the recovery command exists until this implementation and migration posture have been included. No timer, re-invite behavior, approval-policy change or live admin test is included.

## Offline acceptance

Use disposable fixtures only, never production DB/group or unmarked admin sends. Cover: eligible retryable and suspended overlays; all20 open slots full; correct current second operator after original removal; verified command metadata and correct thread; original command versus duplicate command idempotency across restart; unreadable or drifted authority/native snapshots; conflicting native terminal readback versus exact matching reconciliation; missing proof and each unknown/extra envelope field; issuance marker and generation races; process crash before/after issuing/proof/retirement transaction and outbox; notice failure rollback; foreign attempt/digest/thread/operator; every state not deciding/maintenance and every already-issued/uncertain state; no native mutation, new ask, privilege construction, history deletion or cross-ask consumption. Negative tests must assert original Attempt/inbound/proof bytes survive, and positive tests verify one terminal retirement receipt and one deduplicated threaded notice. Schema upgrades retain old rows and explicitly mark missing proof ineligible.
