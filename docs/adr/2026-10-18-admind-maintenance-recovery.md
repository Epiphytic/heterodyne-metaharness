# Authenticated retirement of a proven pre-effect admind attempt

Design task btq-vx7l6; author Codex. ONE actual Claude Opus HIGH review at d94370eb8f6296a14300b5334068a754c4eaa459 returned REVISE10, incorporated once below. No second review/validation and no reviewer APPROVE is claimed; separate human Marmot approval remains required. No implementation, deployment or changed approval pin is authorized by this document.

## Problem and retained contracts

The approved queue-maintenance design b13fd101011102dde43299d5f530d28f9f049118 §4 preserves the original Attempt and inbound message after an exact proven-pre-effect maintenance HOLD. Fresh authority/card/native checks prevent stale approval replay. Actual exjsy R1/R2 reviews found that changed-card, revoked-authority and native-conflict cases can occupy all 20 open ask slots permanently. The current repair suspends their retry rather than polling forever, but offers no supported retirement command. CLI cancellation only accepts open/answered asks. Existing command grammar has !asks [bump|repeat], not a recovery verb. Existing request/decision recovery elsewhere does not authorize retirement of this overlay.

This addition permits only authenticated terminal retirement of an exact provably not-issued attempt. It never approves, denies, replays, changes policy, clears a queue fence, reallocates ownership, repairs an uncertain write, creates a replacement ask or treats an old decision as current consent. Native first-valid-decision rules, genuine design/deployment approvals, immutable histories and the existing group/transport authority boundary remain intact. Same-UID DB tampering is outside the existing trusted-host boundary.

## Operator interface

Add deterministic `!asks retire <proof-token>` as a direct reply to the generated held notice. The notice binds the original ask, attempt, full stored native card/context digest and invocation generation; the token is the first24 lowercase hex characters of SHA256 of the canonical closed version1 proof record including those values. Resolve exactly one current matching notice/proof/thread; zero or collision refuses. The full64-hex card digest is the original Attempt digest, distinct from the full proof hash. The command uses the token only as an exact selector, never authority. Display the token in the held notice so it can be copied on a phone. No optional/latest, prefix match, bulk mode, free-text authority, reaction alias or LLM inference. Commands are bounded to 1024 UTF-8 bytes; malformed commands cause a bounded diagnostic and no mutation beyond their ordinary durable inbound/audit receipt. HELP and !asks display exact syntax and held attempt identity; the full digest/proof/generation are retained in the bounded receipt, not required to be typed. Ordinary summary remains bounded.

The command is a new authenticated operator decision to retire a pending local delivery, not a denial of the native design. The operator need not be the original sender, who may have been removed. The current authenticated sender must be a configured authorized operator, present in the correct group with current verified membership/authority, with current policy permitting control. This new control permission explicitly permits any currently authorized operator to retire another operator’s local pending approval OR denial, including after original removal. It cannot change an existing native decision. The original operator identity/action and retiring identity appear separately in the acknowledgement threaded to the original decision and held notice; no claim of private delivery to a removed operator is made. Replayed or unverified transport input, stale membership, wrong thread/card/notice, suspended observation, changed policy, malformed metadata and missing sender mapping refuse. Recheck the same current authority immediately before the local commit. Message bodies cannot supply sender privilege. This command never enters the manager/agent input path.

## Exact eligibility and proof

Under the existing daemon serialized admission and Store transaction/CAS, require the ask to remain deciding with exactly the named current Attempt, immutable original message/ref/operator/action/digest, and exact full stored card digest. It must retain a maintenance overlay and a complete exact receipt for the most recent child invocation that returned the fence's closed exit-75 not-issued JSON. No invocation may have begun since that receipt. Both retryable pending-maintenance and suspended maintenance-held overlays are eligible; maintenance-issuing, uncertain, settled, superseded, unknown/corrupt and missing-proof states are not.

Add monotonic `invocations` and `proof_capable_since_begin` columns to ask_attempts by additive schema migration, preserving every old row and its existing settled CHECK. New begin_attempt sets proof_capable_since_begin=true and invocations=0; historical rows remain false permanently, including after future exact HOLD retries. No automatic migration can promote them. Every invocation intent increments this durable counter in the same transaction BEFORE possible child creation; it is never deleted/reset when a proof is cleared. Same-process/no-await authority checks and the existing work_lock serialize membership and retry admission.

One additive proof row per exact ask/attempt stores version1, full original card digest, counter, validated closed HOLD envelope/exit75, bounded raw stdout SHA256, captured coordinator/adapter identity and the number of consecutive proven invocations since begin. Create/replace this row ONLY in the validated exact proven_hold child-result branch, atomically with defer. Other backoff, preflight, conflict or authority defer calls preserve the row; they cannot fabricate or refresh proof. Retirement requires proof_capable_since_begin and complete consecutive proof coverage for EVERY invocation1..invocations; no-later-issuance means the durable counter and current issuing marker both match. Issuing intent invalidates entitlement before child creation, but need not delete history/counter. A child adapter failure proven in-process launched=False may atomically mark that generation not-spawned and restore the previous eligible chain; after a crash missing such proof remains unknown. Arbitrary75, timeout, partial JSON, extra fields, process failure or post-effect error never counts as proof. Record only bounded per-attempt aggregate proof plus latest exact envelope/hash, not unbounded per-retry rows; the immutable original attempt and final recovery receipt retain provenance. If exact coverage cannot be represented or verified, HOLD.

Historical pre-proof attempts remain ineligible PERMANENTLY in this version even after upgrade retries. Native undecided alone, elapsed time and operator assertion are never absence proof. A separately reviewed original-receipt migration is outside this design. Unknown or maintenance-issuing attempts are not made eligible by this feature.

Before commit, take the existing read-only approve-bead snapshot using the retained source/adapter admission; native read must succeed and be parseable/current. An undecided native approval may be retired locally as cancelled/maintenance-retired. A known conflicting terminal native decision uses existing close_attempt settled=blocked/new_status=blocked and existing BLOCKED wording, plus separate recovery provenance; the native decision remains unchanged. An authenticated successful read with explicit not-open or not-approval is also eligible for local blocked retirement only when the complete prior proof chain establishes no issuance; do not infer these states from malformed output. A native decision exactly matching the original Attempt follows existing native reconciliation instead; it is never mislabeled not-issued or retired by this path. Unknown/unreadable/read timeout or malformed native authority remains held and can be retried by a new authenticated command after inspection. No native mutation is made by any of these branches.

## Atomic retirement and races

The local commit compare-and-sets the ask status, current Attempt identity, full digest, overlay/proof/invocation generation and monotonic invocations against the values actually checked. There is no invented persisted membership/policy epoch: refresh policy and verify current authenticated membership under existing work_lock, with no await between final check and local commit. The existing daemon single-writer/host exclusion is the authority boundary; Store CAS alone does not authenticate a separate process. On success, in ONE existing Store transaction: close the original attempt through existing close_attempt with allowed settled=untouched/new_status=cancelled/outcome=maintenance-retired, or settled=blocked/new_status=blocked/existing BLOCKED text for the conflict/not-open/not-approval branch (preserve exit75 and original data), retain decided_by as the retiring authenticated operator with a distinct retirement record rather than native approval provenance; clear asks.attempt and remove only its exact maintenance overlay/proof; mark original inbound consumed with an explicit retirement mapping; record the recovery command ID/sender/thread/ref/full digest, original attempt identity, proof hash, before/after state, native readback hash/conflict and retirement reason; queue exactly one deduplicated threaded acknowledgement. No other ask, historical message, native decision, ownership/dependency or policy changes.

Store uses an additive recovery-receipt table keyed uniquely by ask/attempt, with original recovery inbound message ID as retained provenance; existing inbound primary-key dedup handles command redelivery. Keep original ask_attempts and one final immutable proof/retirement receipt. There is no existing ask/history retention policy; this design does not invent one. Keep at most one replaceable active proof per attempt and one final receipt per retired attempt; no per30-second-retry history rows. Total lifetime storage still grows with real attempts and remains an explicitly finite operational limit, with storage failures holding without deleting history. Never delete history to free active capacity. Repeated delivery of the SAME authenticated command returns its existing receipt, without new notice/native calls/effects; a DIFFERENT command for an already-retired attempt reports the existing retirement and changes nothing. Ordinary command inbound acknowledgement follows existing idempotent delivery behavior.

Receipt/notice and retirement state either commit together or all roll back. Restart after commit resends only the existing outbox item. SQLite or outbox failure before commit leaves the original attempt/proof/inbound untouched. Crash after native read but before commit does not authorize a retry of the decision child. The daemon actor's serialization excludes retry launch during the read/commit interval; the Store CAS independently rejects changed ask/proof/counter, including ABA where identical HOLD JSON returns after another invocation. Authority changes are excluded only by existing single-daemon work_lock/admission and trusted-host process exclusion; no cross-process authority epoch claim is made. Invalid generation or unknown DB schema fails closed with bounded diagnostic.

## Capacity, escalation and rollout

This operation needs no new open ask and is available at MAX_OPEN=20 or maintenance capacity128, even when every slot is suspended. It needs only existing bounded Store/outbox/audit resources; if those are unavailable, return a precise storage HOLD and preserve history. Local receipt storage is finite and has no new pruning; it cannot be claimed infinitely available. The native approval JSON read stays read-only under queue HOLD and must not instantiate a writer. No dependency on approving a NEW native recovery bead while the fence is held is introduced.

Held notices distinguish retryable maintenance, permanently suspended native/card/authority conflict, issuance-unverified and storage failure. They show exact recovery syntax only when the proof makes retirement eligible. For ineligible ambiguous or historical records, publish one deduplicated ordinary threaded maintenance notice through admind’s existing durable notice/outbox transport, which does NOT allocate an ask slot, containing ask/attempt, exact diagnostic and missing evidence. This notice is the concrete in-group escalation channel; the operator may reply directly and the authenticated ingress preserves it. It is NOT a new approval ask or authority for uncertain repair. Explicit residual: twenty historical or ambiguous records can still starve NEW ask allocation; this narrow design cannot clear them. Broader ambiguous-outcome recovery must receive a separately reviewed design and authenticated decision through this same notice/reply path before deployment if that state exists. No claim that the narrow command solves every lockout is made. Never instruct operators to edit SQLite or manufacture authority. Broader recovery of unknown native effects remains outside this narrow addition and may require a separate reviewed design/explicit administrative action.

Sequence: approved exjsy proof/issuing repair and this additive recovery implementation -> actual cross-model code review and offline acceptance -> compatible queue/Hermes/admind closure composition -> exact deployment card with this immutable design link and explicit deviations -> approved coordinated deployment. Do not deploy exjsy under a claim that the recovery command exists until this implementation and migration posture have been included. No timer, re-invite behavior, approval-policy change or live admin test is included.

Cover: eligible retryable and suspended overlays; all20 open slots full; correct current second operator after original removal; verified command metadata and correct thread; original command versus duplicate command idempotency across restart; unreadable or drifted authority/native snapshots; conflicting native terminal readback versus exact matching reconciliation; missing proof and each unknown/extra envelope field; issuance marker and generation races; process crash before/after issuing/proof/retirement transaction and outbox; notice failure rollback; foreign attempt/digest/thread/operator; every state not deciding/maintenance and every already-issued/uncertain state; no native mutation, new ask, privilege construction, history deletion or cross-ask consumption. Negative tests must assert original Attempt/inbound/proof bytes survive, and positive tests verify one terminal retirement receipt and one deduplicated threaded notice. Schema upgrades retain old rows and explicitly mark missing proof ineligible.

## Explicit state mapping and review incorporation

For a fully proof-covered attempt, stop reason is metadata, not proof: maintenance/native-busy/read-unavailable/approvals-unconfigured/policy-unavailable/group-unverified require a fresh successful native read and current retiring authority before retirement; authority/latched/not-approver/gate/changed-card similarly need no original operator to return, because a different current operator may explicitly retire. Undecided => cancelled/untouched; conflicting native decision => blocked/blocked; explicit not-open or not-approval => blocked/blocked; exact matching original native decision => existing reconciliation; unreadable/busy/malformed/unknown => HOLD. No original decision is automatically resumed by the retirement command. Current exjsy issuing/restart repairs must preserve ordinary R26 reconciliation separately; this design does not turn every ordinary in-flight decision into permanent maintenance uncertainty.
